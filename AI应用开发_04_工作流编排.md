# AI工作流编排：从DAG到多模态管线的系统工程

## 一、工作流引擎设计：执行模型与核心算法

### 1.1 DAG vs Pipeline vs Tree：三种执行模型的本质差异

工作流编排的第一个设计决策是选择底层执行模型。这三种模型在表达能力、可分析性和执行效率上存在根本性权衡。

**Pipeline（线性管道）** 是最简单的模型：节点按固定顺序执行，每个节点消费上一个节点的输出。它等价于一个函数复合链 `f_n ∘ ... ∘ f_1(x)`。优点是延迟可预测、调试直观；缺点是缺乏分支和并行能力。在AI场景中，一个典型的推理Pipeline形如"预处理→推理→后处理"，但当需要同时运行多个模型或条件分流时，Pipeline就不够了。

**DAG（有向无环图）** 是当前工作流引擎的事实标准。节点代表计算单元，边代表依赖关系。DAG的表达能力远超Pipeline：支持扇出（fan-out，一个节点触发多个下游）、扇入（fan-in，多个节点汇聚到一个节点）、条件分支和并行子图。DAG的可分析性也强——通过拓扑排序可以确定执行顺序，通过最长路径计算可以估计总延迟。

**Tree（树形结构）** 本质上是DAG的一个受限子集（每个节点至多一个父节点），但在AI场景中有特殊用途：决策树模型集成、分层任务分解（hierarchical task decomposition）和条件路由树。Tree的优势在于天然支持递归分解和可解释的路由决策。

```python
# === Core abstraction: three execution models ===
from abc import ABC, abstractmethod
from typing import Any, Callable
import asyncio
import networkx as nx

class ExecNode:
    """A single unit of work in the workflow."""
    def __init__(self, node_id: str, fn: Callable, depends_on: list[str] | None = None):
        self.node_id = node_id
        self.fn = fn
        self.depends_on = depends_on or []

class PipelineExecutor:
    """Sequential pipeline: nodes execute in declared order."""
    def __init__(self, nodes: list[ExecNode]):
        self.nodes = nodes

    async def run(self, init_data: Any = None) -> Any:
        result = init_data
        for node in self.nodes:
            result = await node.fn(result)
        return result

class DAGExecutor:
    """DAG-based executor: resolves dependencies via topological sort, runs parallel-ready."""
    def __init__(self, nodes: list[ExecNode]):
        self.graph = nx.DiGraph()
        for n in nodes:
            self.graph.add_node(n.node_id, fn=n.fn)
            for dep in n.depends_on:
                self.graph.add_edge(dep, n.node_id)

    def resolve_execution_order(self) -> list[str]:
        """Topological sort — Kahn's algorithm for cycle detection."""
        try:
            return list(nx.topological_sort(self.graph))
        except nx.NetworkXUnfeasible:
            raise RuntimeError("Cycle detected in workflow DAG")

    async def run(self, init_data: dict[str, Any] | None = None) -> dict[str, Any]:
        order = self.resolve_execution_order()
        results: dict[str, Any] = init_data or {}
        for nid in order:
            deps = {dep: results[dep] for dep in self.graph.predecessors(nid)}
            node_fn = self.graph.nodes[nid]["fn"]
            results[nid] = await node_fn(deps)
        return results
```

Pipeline的O(n)延迟可预测但无并行，DAG通过拓扑排序实现并行调度但需要处理依赖解析。选择模型的判断标准是：如果工作流中存在任何不依赖前置节点的分支（如同时调用两个独立的LLM），就必须使用DAG。

### 1.2 状态机驱动的工作流实现

将工作流建模为有限状态机（FSM）是一种更健壮的方法。每个节点对应一个状态，边对应状态转移。FSM方案的优点在于：状态空间显式可控，非法转移可被编译器/运行时捕获，并且天然支持暂停和恢复。

```python
# === State-machine driven workflow ===
from enum import Enum, auto
from dataclasses import dataclass, field

class WorkflowState(Enum):
    PENDING = auto()
    RUNNING = auto()
    SUCCEEDED = auto()
    FAILED = auto()
    SKIPPED = auto()
    ROLLED_BACK = auto()

@dataclass
class NodeInstance:
    node_id: str
    state: WorkflowState = WorkflowState.PENDING
    result: Any = None
    error: str | None = None
    retry_count: int = 0
    started_at: float | None = None
    completed_at: float | None = None

@dataclass
class WorkflowInstance:
    workflow_id: str
    nodes: dict[str, NodeInstance] = field(default_factory=dict)
    global_state: dict[str, Any] = field(default_factory=dict)
    current_state: WorkflowState = WorkflowState.PENDING

class StateMachineWorkflow:
    """FSM-driven workflow engine with explicit state transitions."""
    VALID_TRANSITIONS = {
        WorkflowState.PENDING: {WorkflowState.RUNNING, WorkflowState.SKIPPED},
        WorkflowState.RUNNING: {WorkflowState.SUCCEEDED, WorkflowState.FAILED},
        WorkflowState.FAILED: {WorkflowState.RUNNING},        # retry
        WorkflowState.SUCCEEDED: {WorkflowState.ROLLED_BACK}, # compensate
    }

    def __init__(self, adjacency: dict[str, list[str]]):
        self.adjacency = adjacency  # node_id -> downstream ids

    def transition(self, node: NodeInstance, target: WorkflowState) -> None:
        if target not in self.VALID_TRANSITIONS.get(node.state, set()):
            raise ValueError(
                f"Invalid transition: {node.state.name} -> {target.name}"
            )
        node.state = target

    def evaluate_condition(self, deps: dict, condition_expr: str) -> bool:
        """Evaluate a Python expression against current dependency results."""
        # SAFETY: in production, use a sandboxed eval (e.g., restricted scope)
        allowed = {"len": len, "all": all, "any": any, "sum": sum}
        return bool(eval(condition_expr, {"__builtins__": {}}, {**allowed, **deps}))
```

FSM的核心价值在于**合法性保障**：它禁止了悬挂边、重复执行和非法恢复路径。这在AI Pipeline中尤为重要——LLM调用是有副作用的（消耗token、写入数据库），必须确保每个节点至多执行一次（exactly-once）或最多执行一次（at-most-once）。

### 1.3 拓扑排序与依赖解析

拓扑排序是DAG引擎的骨架。Kahn算法（基于入度）和DFS（基于完成时间标记）是两种经典实现。在工业级引擎中，还需要处理：条件依赖（节点B仅在节点A的输出满足某个谓词时才执行）、超时依赖（节点C在节点A超时后自动触发降级路径）和数据依赖（节点B需要节点A的特定字段而非全部输出）。

```python
# === Kahn's topological sort with conditional edges ===
from collections import deque

@dataclass
class Edge:
    source: str
    target: str
    condition: Callable[[dict], bool] | None = None  # None = unconditional

class ConditionalDAG:
    """DAG that supports conditionally-active edges."""

    def __init__(self):
        self.nodes: dict[str, Callable] = {}
        self.edges: list[Edge] = []

    def add_node(self, nid: str, fn: Callable) -> None:
        self.nodes[nid] = fn

    def add_edge(self, source: str, target: str, condition: Callable | None = None) -> None:
        self.edges.append(Edge(source, target, condition))

    def get_active_graph(self, context: dict) -> nx.DiGraph:
        """Return a DAG with only the edges whose conditions are satisfied."""
        g = nx.DiGraph()
        for nid in self.nodes:
            g.add_node(nid)
        for e in self.edges:
            if e.condition is None or e.condition(context):
                g.add_edge(e.source, e.target)
        return g

    def kahn_topological_sort(self, context: dict) -> list[str]:
        """Kahn's algorithm: indegree-driven O(V+E) sort."""
        graph = self.get_active_graph(context)
        in_degree = {n: 0 for n in graph.nodes()}
        for u, v in graph.edges():
            in_degree[v] += 1

        queue = deque([n for n, d in in_degree.items() if d == 0])
        order = []

        while queue:
            node = queue.popleft()
            order.append(node)
            for succ in graph.successors(node):
                in_degree[succ] -= 1
                if in_degree[succ] == 0:
                    queue.append(succ)

        if len(order) != len(graph.nodes()):
            raise RuntimeError("Graph contains a cycle — active edges produce circular dependency")
        return order
```

**条件分支与循环：动态DAG构建**

```python
# === Dynamic DAG: branches and loops ===
class DynamicDAGBuilder:
    """
    Build execution DAG dynamically based on runtime conditions.
    Supports IF/ELSE branches and WHILE-style loops via node rewiring.
    """

    def __init__(self):
        self._graph = nx.DiGraph()
        self._node_fn: dict[str, Callable] = {}
        self._condition_fn: dict[str, Callable] = {}

    def add_condition_node(self, nid: str, condition_fn: Callable[[dict], str]) -> None:
        """Condition node: evaluates a predicate and returns the next node id to route to."""
        self._graph.add_node(nid, node_type="condition")
        self._condition_fn[nid] = condition_fn

    def add_task_node(self, nid: str, fn: Callable) -> None:
        self._graph.add_node(nid, node_type="task")
        self._node_fn[nid] = fn

    def add_loop(self, loop_body: list[str], condition: Callable[[dict], bool],
                 max_iterations: int = 10) -> None:
        """
        Build a WHILE-like loop by routing the tail back to the head.
        Guarded by max_iterations to prevent infinite loops.
        """
        head, *rest, tail = loop_body
        for i in range(len(rest)):
            self._graph.add_edge(rest[i], rest[i + 1] if i + 1 < len(rest) else tail)

        # Loop condition: after tail, re-evaluate before going back to head
        loop_guard_id = f"_loop_guard_{head}"
        self.add_condition_node(loop_guard_id, lambda ctx, _cond=condition, _h=head, _m=max_iterations: (
            _h if _cond(ctx) and ctx.get("_loop_count", 0) < _m else "__exit__"
        ))
        self._graph.add_edge(tail, loop_guard_id)

    def resolve_dynamic_order(self, context: dict) -> list[str]:
        """Runtime topological resolution: follow condition branches."""
        order = []
        visited = set()
        start_nodes = [n for n in self._graph.nodes()
                       if self._graph.in_degree(n) == 0]

        def walk(node_id: str):
            if node_id in visited or node_id == "__exit__":
                return
            visited.add(node_id)
            order.append(node_id)

            node_type = self._graph.nodes[node_id].get("node_type", "task")
            if node_type == "condition":
                next_id = self._condition_fn[node_id](context)
                walk(next_id)
            else:
                for succ in self._graph.successors(node_id):
                    walk(succ)

        for s in start_nodes:
            walk(s)
        return order
```

动态DAG构建的关键挑战是**可终止性保证**。循环必须绑定最大迭代次数，条件分支必须有默认路径（else或fallback），否则一个LLM响应格式异常就可能导致无限循环。生产实践中，循环次数通常限制在3-5次，超过则触发人工介入。

## 二、编排框架选型：从LangGraph到Temporal

### 2.1 LangGraph：StateGraph的编程模型

LangGraph是LangChain生态中专门为LLM工作流设计的状态图框架。它的核心设计理念是"节点+边+状态"三元组：

- **Node**：一个可调用对象（函数或可运行对象），接收State并返回State的增量更新
- **Edge**：节点间的连接，可以是普通边（无条件）或条件边（基于State的某个字段路由）
- **State**：一个TypedDict或Pydantic模型，贯穿整个图的全局状态
- **Checkpoint**：执行过程中State的快照，支持暂停/恢复和人肉审核

```python
# === LangGraph: StateGraph construction ===
from typing import TypedDict, Literal, Annotated, Sequence
from langgraph.graph import StateGraph, END
from langgraph.checkpoint.memory import MemorySaver
import operator

# --- State definition (Pydantic or TypedDict) ---
class AgentState(TypedDict):
    messages: Annotated[list, operator.add]  # reducer: append on each update
    context: dict
    next_step: str
    error_count: int

# --- Node functions ---
async def retrieve_documents(state: AgentState) -> dict:
    """Node: fetch relevant documents based on user query."""
    query = state["messages"][-1]["content"]
    docs = await vector_store.similarity_search(query, k=5)
    return {"context": {"documents": docs, "query": query}}

async def build_prompt(state: AgentState) -> dict:
    """Node: construct the LLM prompt from retrieved context."""
    docs_text = "\n\n".join([d.page_content for d in state["context"]["documents"]])
    prompt = f"Context:\n{docs_text}\n\nQuestion: {state['context']['query']}\n\nAnswer:"
    return {"messages": [{"role": "user", "content": prompt}]}

async def call_llm(state: AgentState) -> dict:
    """Node: invoke the LLM and capture response."""
    response = await llm_model.ainvoke(state["messages"])
    return {"messages": [response], "next_step": "quality_check"}

async def quality_check(state: AgentState) -> dict:
    """Node: evaluate output quality, decide to accept or retry."""
    last_msg = state["messages"][-1]["content"]
    score = await evaluate_quality(last_msg)
    if score < 0.7 and state.get("error_count", 0) < 2:
        return {"error_count": state["error_count"] + 1, "next_step": "retry"}
    return {"next_step": "finalize"}

# --- Routing function (conditional edge) ---
def decide_next(state: AgentState) -> Literal["build_prompt", "quality_check", "__end__"]:
    """Conditional routing based on next_step field."""
    step = state.get("next_step", "")
    routing = {
        "retry": "build_prompt",
        "quality_check": "quality_check",
        "finalize": "__end__",
    }
    return routing.get(step, "__end__")

# --- Graph assembly ---
def build_rag_graph() -> StateGraph:
    workflow = StateGraph(AgentState)

    workflow.add_node("retrieve", retrieve_documents)
    workflow.add_node("build_prompt", build_prompt)
    workflow.add_node("call_llm", call_llm)
    workflow.add_node("quality_check", quality_check)

    workflow.set_entry_point("retrieve")
    workflow.add_edge("retrieve", "build_prompt")
    workflow.add_edge("build_prompt", "call_llm")
    workflow.add_edge("call_llm", "quality_check")

    # Conditional edge: quality gate determines next step
    workflow.add_conditional_edges("quality_check", decide_next)

    # Compile with checkpoint saver for persistence
    return workflow.compile(checkpointer=MemorySaver())

# Execute with per-thread state
async def run():
    graph = build_rag_graph()
    config = {"configurable": {"thread_id": "session-001"}}
    result = await graph.ainvoke(
        {"messages": [{"role": "user", "content": "What is the Transformer architecture?"}]},
        config
    )
    print(result["messages"][-1]["content"])
```

LangGraph的优势在于**LLM-native的节点设计**：state的reducer机制（`operator.add`）天然支持流式token追加，Checkpoint可以序列化到任何存储后端，并且Human-in-the-loop的interrupt机制（`NodeInterrupt`）让AI工作流可以被人工审核打断再恢复。它的主要限制是单进程执行——对于需要跨机器的工作流，需要配合LangGraph Cloud或自行封装。

### 2.2 Temporal Workflow：确定性重放与AI Pipeline

Temporal是源自Uber的分布式工作流引擎，它的核心承诺是**确定性重放**：只要Workflow函数的代码不变、所有外部通信通过Activity封装，Temporal就可以从头重放Workflow的全部执行过程来恢复状态。这对AI Pipeline的意义在于：即使LLM调用失败、worker崩溃或网络分区，Temporal都能精确恢复执行到最后一个成功点。

```python
# === Temporal Workflow for AI Pipeline ===
from temporalio import workflow, activity
from temporalio.workflow import workflow_method
from datetime import timedelta
import asyncio
from dataclasses import dataclass

# --- Data types ---
@dataclass
class InferenceRequest:
    prompt: str
    model_name: str
    max_tokens: int = 1024
    temperature: float = 0.7

@dataclass
class InferenceResult:
    text: str
    token_count: int
    model_name: str
    latency_ms: float

# --- Activities (non-deterministic: I/O, LLM calls, DB) ---
@activity.defn
async def preprocess_input(request: InferenceRequest) -> dict:
    """Activity: sanitize prompt, build context, load RAG docs."""
    docs = await vector_store.similarity_search(request.prompt, k=3)
    enriched = f"Context:\n{chr(10).join([d.page_content for d in docs])}\n\nPrompt:\n{request.prompt}"
    return {"enriched_prompt": enriched, "document_ids": [d.id for d in docs]}

@activity.defn
async def call_llm(model_name: str, prompt: str, max_tokens: int, temperature: float) -> str:
    """Activity: the actual LLM invocation — the only non-deterministic external call."""
    response = await llm_provider.complete(model_name, prompt, max_tokens=max_tokens, temperature=temperature)
    return response

@activity.defn
async def postprocess_output(raw_text: str) -> dict:
    """Activity: parse, validate, format, and store the result."""
    validation = await content_safety_check(raw_text)
    if not validation.passed:
        raise ValueError(f"Content safety check failed: {validation.reason}")
    await result_store.save(validation.sanitized_text)
    return {"safe_text": validation.sanitized_text, "score": validation.score}

# --- Workflow (deterministic — NO I/O, NO randomness, NO time) ---
@workflow.defn
class AIInferenceWorkflow:
    """Deterministic workflow: orchestrates Activities; Temporal replays this for recovery."""

    @workflow_method
    async def run(self, request: InferenceRequest) -> InferenceResult:
        # Step 1: Preprocessing (delegated to Activity)
        preprocessed = await workflow.execute_activity(
            preprocess_input,
            request,
            start_to_close_timeout=timedelta(seconds=30),
            retry_policy={"maximum_attempts": 3},
        )

        # Step 2: LLM call (Activity with exponential backoff built-in)
        start = workflow.time()
        raw_output = await workflow.execute_activity(
            call_llm,
            request.model_name,
            preprocessed["enriched_prompt"],
            request.max_tokens,
            request.temperature,
            start_to_close_timeout=timedelta(minutes=5),
        )
        elapsed_ms = (workflow.time() - start).total_seconds() * 1000

        # Step 3: Postprocessing (Activity with validation)
        result = await workflow.execute_activity(
            postprocess_output,
            raw_output,
            start_to_close_timeout=timedelta(seconds=30),
        )

        return InferenceResult(
            text=result["safe_text"],
            token_count=count_tokens(raw_output),
            model_name=request.model_name,
            latency_ms=elapsed_ms,
        )
```

Temporal的设计哲学是**Workflow代码必须纯函数化**：不能直接调用LLM、不能读写文件、不能使用`time.now()`或`random()`。所有有副作用的操作都封装在Activity中，Worker可以自由重启而Workflow状态通过Event History持久化在Temporal Server中。这使得Temporal成为**金融级AI Pipeline**的首选——当一次LLM调用需要花费$10+时，执行可靠性的价值远超框架的复杂性问题。

### 2.3 Prefect / Luigi / Airflow 在AI工作流中的角色

这三者都是较早的工作流框架，但在AI Pipeline的实时性需求面前暴露出设计鸿沟：

| 框架 | 核心抽象 | 调度模型 | AI场景定位 | 关键限制 |
|------|----------|----------|-----------|---------|
| **Airflow** | DAG + Scheduler + Worker | 基于时间/事件的批调度 | 离线特征计算、数据集ETL、模型训练Pipeline | 秒级延迟不可控；DAG静态定义难适应动态条件 |
| **Prefect** | Flow + Task + Block | 混合(推+拉) | 数据预处理、模型评估Pipeline、MLOps编排 | Serverless延迟1-3秒，不适合实时推理 |
| **Luigi** | Task + Target | 基于文件依赖的批处理 | 数据仓库构建、特征工程、报告生成 | 被Prefect/Airflow全面超越，生态萎缩 |

**核心差异在于：实时推理Pipeline需要毫秒级响应和动态路由，而Airflow/Prefect设计之初是为小时级或天级的批处理服务。** 它们可以在AI管线中扮演"数据制备层"的角色（如每日更新embedding向量数据库、重算特征、触发模型重训练），但不能替代LangGraph或Temporal在推理路径中的位置。

```python
# === Prefect for AI data preparation pipeline ===
from prefect import flow, task
from prefect.task_runners import ConcurrentTaskRunner
import asyncio

@task(retries=2, retry_delay_seconds=60)
def fetch_new_documents(data_source: str) -> list[dict]:
    """Task: pull recently added/updated documents."""
    return list(data_api.get_changes(since="last_run"))

@task
def chunk_documents(docs: list[dict], chunk_size: int = 512) -> list[dict]:
    """Task: split long documents into overlapping chunks."""
    chunks = []
    for doc in docs:
        text = doc["content"]
        for i in range(0, len(text), chunk_size - 64):
            chunk = text[i:i + chunk_size]
            chunks.append({"source_id": doc["id"], "text": chunk, "offset": i})
    return chunks

@task(task_run_name="embed_{chunk_id}")
def embed_chunk(chunk: dict) -> dict:
    """Task: generate embedding vector for a single chunk."""
    vector = embedding_model.encode(chunk["text"], convert_to_numpy=True)
    chunk["vector"] = vector.tolist()
    return chunk

@task
def store_embeddings(chunks: list[dict]) -> int:
    """Task: batch-upsert to vector database."""
    vectors = [(c["source_id"], c["vector"], {"text": c["text"], "offset": c["offset"]})
               for c in chunks]
    vector_db.upsert(vectors=vectors)
    return len(vectors)

@flow(name="embedding_refresh", task_runner=ConcurrentTaskRunner())
async def embedding_pipeline(data_sources: list[str]):
    """Flow: orchestrates multi-step embedding update. Runs daily."""
    total_vectors = 0
    for source in data_sources:
        docs = fetch_new_documents(source)
        chunks = chunk_documents(docs)
        embedded = await embed_chunk.map(chunks)  # parallel embedding
        count = store_embeddings(embedded)
        total_vectors += count
        print(f"Source {source}: {count} vectors stored")
    return {"vectors_written": total_vectors, "sources": data_sources}
```

Prefect在这里的角色清晰：它是**离线数据管线**而非**在线推理管线**。两者应该通过中间存储（如向量数据库、消息队列或特征存储）解耦——Prefect负责"从原始文档到向量数据库"，LangGraph/Temporal负责"从用户查询到推理结果"。

## 三、AI Pipeline组件化

### 3.1 数据处理节点

AI工作流的数据处理节点通常遵循"解析→分块→嵌入→存储"的四阶段模式。每个阶段的输出是下一个阶段的输入，但需要考虑容错性和增量处理。

```python
# === Document processing pipeline ===
from typing import AsyncIterator
import hashlib

class DocumentProcessor:
    """Modular document processing pipeline with streaming support."""

    async def parse(self, source: str | bytes, mime_type: str) -> dict:
        """Parse raw input into structured text with metadata."""
        parsers = {
            "application/pdf": self._parse_pdf,
            "text/plain": self._parse_text,
            "text/markdown": self._parse_markdown,
            "text/html": self._parse_html,
        }
        parser = parsers.get(mime_type)
        if not parser:
            raise ValueError(f"Unsupported mime type: {mime_type}")
        return await parser(source)

    async def chunk(self, document: dict, strategy: str = "recursive",
                    chunk_size: int = 512, overlap: int = 64) -> list[dict]:
        """Split parsed document into overlapping chunks."""
        text = document["content"]
        if strategy == "recursive":
            return self._recursive_split(text, chunk_size, overlap)
        elif strategy == "semantic":
            return await self._semantic_split(text, chunk_size)
        raise ValueError(f"Unknown chunk strategy: {strategy}")

    def _recursive_split(self, text: str, chunk_size: int, overlap: int) -> list[dict]:
        """Split by paragraph, then sentence, then token boundary."""
        chunks, start = [], 0
        while start < len(text):
            end = min(start + chunk_size, len(text))
            # Try to break at paragraph boundary
            if end < len(text):
                paragraph_break = text.rfind("\n\n", start, end)
                if paragraph_break > start + chunk_size // 2:
                    end = paragraph_break
            chunks.append({
                "text": text[start:end],
                "start_offset": start,
                "end_offset": end,
                "chunk_id": hashlib.md5(text[start:end].encode()).hexdigest()[:12],
            })
            start = end - overlap
        return chunks

    async def embed(self, chunks: list[dict], model_name: str = "text-embedding-3-small") -> list[dict]:
        """Generate embeddings for each chunk — batch for efficiency."""
        texts = [c["text"] for c in chunks]
        # Batching: split into groups of 32 for API efficiency
        all_embeddings = []
        for batch_start in range(0, len(texts), 32):
            batch = texts[batch_start:batch_start + 32]
            embeddings = await embedding_client.embed(batch, model=model_name)
            all_embeddings.extend(embeddings)
        for chunk, vector in zip(chunks, all_embeddings):
            chunk["embedding"] = vector
        return chunks

    async def store(self, chunks: list[dict], collection: str = "documents") -> int:
        """Persist chunks and embeddings to vector store."""
        records = [
            {
                "id": c["chunk_id"],
                "vector": c["embedding"],
                "payload": {"text": c["text"], "source": c.get("source", "unknown")},
            }
            for c in chunks
        ]
        await vector_store.upsert(collection=collection, points=records)
        return len(records)

    async def run_pipeline(self, source: str | bytes, mime_type: str) -> dict:
        """End-to-end pipeline: parse -> chunk -> embed -> store."""
        doc = await self.parse(source, mime_type)
        chunks = await self.chunk(doc)
        embedded = await self.embed(chunks)
        count = await self.store(embedded)
        return {"chunks_count": count, "source": doc.get("source_id", "unknown")}
```

### 3.2 LLM调用节点

LLM调用节点是AI Pipeline中最关键也最脆弱的组件。封装时需要考虑：上下文构建（context window管理）、模型调用（含重试和降级）、输出解析（structured output extraction）、和token追踪。

```python
# === LLM invocation node with context management and structured parsing ===
import json
from pydantic import BaseModel, Field

class LLMInvocationNode:
    """LLM call node with context window management, retry, and structured parsing."""

    def __init__(self, model: str = "gpt-4o", max_context_tokens: int = 128_000):
        self.model = model
        self.max_context_tokens = max_context_tokens

    def build_context(self, messages: list[dict], retrieved_docs: list[dict],
                      system_prompt: str | None = None) -> list[dict]:
        """Build context respecting token budget — truncate oldest if needed."""
        context = []
        if system_prompt:
            context.append({"role": "system", "content": system_prompt})

        # Estimate tokens: ~4 chars per token for English, ~2 for CJK
        doc_text = "\n\n".join([d["text"] for d in retrieved_docs])
        # Truncate documents if overshoot (LRU: drop middle, keep head + tail)
        doc_tokens = len(doc_text) // 4 + 1
        context_window_docs = 4  # reserve for messages
        if doc_tokens > self.max_context_tokens - context_window_docs:
            mid = len(retrieved_docs) // 2
            retrieved_docs = retrieved_docs[:mid] + retrieved_docs[mid+1:]

        if retrieved_docs:
            context.append({"role": "user", "content": f"Relevant context:\n{doc_text}"})
        context.extend(messages)
        return context

    async def invoke(self, messages: list[dict], response_model: type[BaseModel] | None = None,
                     temperature: float = 0.7) -> dict:
        """Call LLM with retry, fallback, and structured output parsing."""
        last_error = None
        models_to_try = [self.model, "gpt-4o-mini", "gpt-3.5-turbo"]  # fallback chain

        for attempt, model in enumerate(self._retry_chain(models_to_try)):
            try:
                if response_model:
                    # Structured output: request JSON-schema constrained generation
                    response = await llm_client.beta.chat.completions.parse(
                        model=model,
                        messages=messages,
                        response_format=response_model,
                        temperature=temperature,
                    )
                    parsed = response.choices[0].message.parsed
                else:
                    response = await llm_client.chat.completions.create(
                        model=model,
                        messages=messages,
                        temperature=temperature,
                    )
                    parsed = response.choices[0].message.content

                return {
                    "parsed": parsed,
                    "raw": response,
                    "model_used": model,
                    "token_count": {
                        "prompt": response.usage.prompt_tokens,
                        "completion": response.usage.completion_tokens,
                        "total": response.usage.total_tokens,
                    },
                }
            except Exception as e:
                last_error = e
                # Exponential backoff: 1s, 2s, 4s
                await asyncio.sleep(2 ** attempt)

        raise RuntimeError(f"LLM invocation failed after all retries: {last_error}")

    def _retry_chain(self, models: list[str]):
        """Yield (attempt_index, model) — downgrades model on each retry."""
        for i, model in enumerate(models):
            yield (i, model)
            if i > 0 and i < len(models) - 1:
                # Downgrade after first failure, keep last as final fallback
                pass
```

**降级策略（Degradation Strategy）** 是LLM节点的关键设计点。当主力模型（如gpt-4o）超时或返回错误时，自动降级到更便宜/更快的模型（如gpt-4o-mini），并标记本次请求使用了降级。这需要在Workflow层面记录"模型版本"元数据，以便后续审计和成本归因。

### 3.3 多模态处理节点

多模态AI工作流涉及图像、音频和视频的编解码、推理和重新编码。这些操作是计算密集型的，必须异步执行并考虑内存管理。

```python
# === Multimodal processing pipeline ===
import io

            results["transcript"] = await self._transcribe(audio_data)
        if "diarize" in operations:
            results["speakers"] = await self._diarize(audio_data)
        if "embedding" in operations:
            results["embedding"] = await self._embed_audio(audio_data)

        return results

                            keyframe_interval: float = 1.0) -> AsyncIterator[dict]:
        """
        Process video frame-by-frame or scene-by-scene.
        Yields results as each keyframe is processed (streaming).
        """
        import cv2
        cap = cv2.VideoCapture(video_path)
        fps = cap.get(cv2.CAP_PROP_FPS)
        frame_interval = int(fps * keyframe_interval)
        frame_idx = 0

        try:
            while cap.isOpened():
                ret, frame = cap.read()
                if not ret:
                    break

                if frame_idx % frame_interval == 0:
                    # Convert BGR (OpenCV) to RGB (PIL)
                    rgb = cv2.cvtColor(frame, cv2.COLOR_BGR2RGB)
                    pil_img = Image.fromarray(rgb)

                    frame_result = {"timestamp": frame_idx / fps, "frame": frame_idx}
                    if "caption" in tasks:
                        frame_result["caption"] = await self._caption(pil_img)
                    if "detection" in tasks:
                        frame_result["detection"] = await self._detect_objects(pil_img)

                    yield frame_result

                frame_idx += 1
        finally:
            cap.release()

    async def _caption(self, image: Image.Image) -> str:
        """Generate image caption via VLM."""
        response = await vlm_client.chat.completions.create(
            model="gpt-4o",
            messages=[{
                "role": "user",
                "content": [
                    {"type": "text", "text": "Describe this image in detail."},
                    {"type": "image_url", "image_url": {"url": self._pil_to_b64(image)}},
                ]
            }]
        )
        return response.choices[0].message.content

    def _pil_to_b64(self, image: Image.Image) -> str:
        """Convert PIL image to base64 data URI for API consumption."""
        import base64
        buf = io.BytesIO()
        image.save(buf, format="PNG")
        return f"data:image/png;base64,{base64.b64encode(buf.getvalue()).decode()}"
```

多模态处理的关键设计约束是**内存与延迟的权衡**：视频解码可能产生数百MB的帧数据，必须使用流式处理（如Python的`AsyncIterator`）逐帧处理，而非一次性加载全部帧到内存。

### 3.4 评估与质量控制节点

评估节点在AI Pipeline中扮演"守门人"角色。它可以是一个自动化的质量检查器，也可以是一个路由到人工审核的条件分支。

```python
# === Quality evaluation node with auto-pass / human-review routing ===
class QualityGateNode:
    """Quality gate that auto-passes good results and routes suspicious ones to human review."""

    def __init__(self, auto_pass_threshold: float = 0.8, max_auto_retries: int = 2):
        self.threshold = auto_pass_threshold
        self.max_auto_retries = max_auto_retries

    async def evaluate(self, output: dict, context: dict) -> dict:
        """Multi-dimensional quality evaluation."""
        scores = {}

        # Dimension 1: Relevance (embedding cosine similarity to query)
        query = context.get("query", "")
        if query and output.get("embedding"):
            scores["relevance"] = self._cosine_similarity(output["embedding"],
                                                          context.get("query_embedding", []))

        # Dimension 2: Completeness (did the model answer all sub-questions?)
        if context.get("required_points"):
            scores["completeness"] = await self._check_completeness(
                output["text"], context["required_points"]
            )

        # Dimension 3: Safety (toxicity, PII, hallucination check)
        scores["safety"] = await self._safety_check(output["text"])

        # Dimension 4: Format compliance (JSON validity if applicable)
        if context.get("expected_format") == "json":
            scores["format"] = self._check_json(output["text"])

        # Aggregate
        scores["overall"] = sum(scores.values()) / len(scores) if scores else 0.0

        # Decision
        decision = self._decide(scores, context)
        return {"scores": scores, "decision": decision, "output": output}

    def _decide(self, scores: dict, context: dict) -> str:
        """Route: auto_pass, retry, or human_review."""
        overall = scores.get("overall", 0.0)
        if overall >= self.threshold:
            return "auto_pass"
        if context.get("retry_count", 0) < self.max_auto_retries:
            return "retry"  # trigger re-generation
        return "human_review"  # escalate

    async def _safety_check(self, text: str) -> float:
        """Content moderation: returns 1.0 if clean, <1.0 if flagged."""
        response = await moderation_client.create(input=text)
        flags = [c for c in response.results[0].categories if c.flagged]
        # 1.0 minus 0.25 per flag category
        return 1.0 - len(flags) * 0.25

    def _check_json(self, text: str) -> float:
        """Validate JSON parsability."""
        try:
            json.loads(text)
            return 1.0
        except json.JSONDecodeError:
            return 0.0

    @staticmethod
    def _cosine_similarity(a: list[float], b: list[float]) -> float:
        a, b = np.array(a), np.array(b)
        return float(np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b) + 1e-10))
```

质量门禁的工程关键点是**分级响应**：auto_pass直接放行，retry触发LLM节点的重新生成（带更好的few-shot示例或更严格的system prompt），human_review将工作流挂起到一个审核队列，等待人工审批后恢复。

## 四、异步执行架构

### 4.1 Async/await vs Task Queue vs Actor Model

AI Pipeline的执行架构选择需要在延迟、吞吐量和开发复杂度之间做三角权衡。

**Async/await（协程）** 适合单进程内的I/O密集型并行。Python的`asyncio`在单个事件循环中可以轻松管理数百个并发LLM调用——每个调用主要是网络等待时间，不阻塞事件循环。但协程无法跨机器扩展，且受限于GIL（对于纯I/O操作影响不大）。

**Task Queue（Celery / RQ）** 将任务序列化为消息，由Worker从队列中消费。这解决了跨机器问题，但引入了至少一次的消息投递语义（at-least-once delivery），需要幂等处理。Celery在AI场景的典型用途是编排异构计算资源——GPU Worker处理推理，CPU Worker处理预处理，两者通过消息解耦。

**Actor Model（Ray / Akka）** 将每个计算单元封装为一个Actor，Actor之间通过消息通信。Ray的Actor模型特别适合AI Pipeline：因为模型加载是昂贵的，Actor可以持有一个模型在内存中，持续处理推理请求，避免重复加载。Ray还天然支持分布式对象存储（Ray Object Store），用于在Actor之间高效传递大张量。

```python
# === Three async execution models compared ===

# --- Model 1: Asyncio (single-process, cooperative concurrency) ---
async def asyncio_pipeline(prompts: list[str]) -> list[str]:
    """Run multiple LLM calls concurrently within one process. ~50 concurrent calls."""
    async def call(prompt: str) -> str:
        resp = await llm_client.completions.create(model="gpt-4o", prompt=prompt)
        return resp.choices[0].text

    tasks = [call(p) for p in prompts]
    return await asyncio.gather(*tasks)

# --- Model 2: Celery (distributed task queue, persistent messaging) ---
from celery import Celery

celery_app = Celery("ai_pipeline", broker="redis://redis:6379/0",
                    backend="redis://redis:6379/1")

@celery_app.task(bind=True, max_retries=3, soft_time_limit=120)
def llm_task(self, prompt: str, model: str = "gpt-4o") -> str:
    """Celery task: LLM invocation with retry. Each task runs on a separate worker."""
    try:
        response = llm_client.completions.create(model=model, prompt=prompt)
        return response.choices[0].text
    except Exception as exc:
        raise self.retry(exc=exc, countdown=2 ** self.request.retries)

# --- Model 3: Ray Actor (stateful, GPU-persistent workers) ---
import ray

@ray.remote(num_gpus=1)
class ModelActor:
    """Actor that holds a loaded model in GPU memory. Handles requests without reloading."""

    def __init__(self, model_name: str):
        self.model_name = model_name
        self.model = self._load_model()     # expensive: runs once per actor

    def _load_model(self):
        from transformers import AutoModelForCausalLM, AutoTokenizer
        model = AutoModelForCausalLM.from_pretrained(self.model_name, device_map="auto")
        tokenizer = AutoTokenizer.from_pretrained(self.model_name)
        return {"model": model, "tokenizer": tokenizer}

    def predict(self, prompt: str, max_tokens: int = 256) -> str:
        """Inference call — no reload, no cold start."""
        inputs = self.model["tokenizer"](prompt, return_tensors="pt").to("cuda")
        outputs = self.model["model"].generate(**inputs, max_new_tokens=max_tokens)
        return self.model["tokenizer"].decode(outputs[0], skip_special_tokens=True)

# Parallel inference across N GPU actors
async def ray_pipeline(prompts: list[str], num_gpus: int = 4):
    actors = [ModelActor.remote("mistralai/Mistral-7B-Instruct-v0.3")
              for _ in range(num_gpus)]
    refs = [actors[i % num_gpus].predict.remote(p) for i, p in enumerate(prompts)]
    return ray.get(refs)
```

**选择指南：** 单机场景且并发<200→asyncio；需要跨机器扩展且任务粒度为分钟级→Celery；需要GPU持久化模型且追求高吞吐→Ray Actor。

### 4.2 流式处理：Streaming Output + Chunked Response

LLM的token-by-token生成天然是流式的。在Pipeline中，下游节点可能在上游刚生成第一个token时就启动处理——这就是**流式管线（Streaming Pipeline）**的核心。

```python
# === Streaming pipeline: tokens flow through nodes in real-time ===
from typing import AsyncGenerator

class StreamingLLMNode:
    """LLM node that yields tokens as they arrive — downstream can start before completion."""

    async def stream(self, prompt: str, system: str = "") -> AsyncGenerator[str, None]:
        """Yield tokens incrementally."""
        stream = await llm_client.chat.completions.create(
            model="gpt-4o",
            messages=[
                {"role": "system", "content": system},
                {"role": "user", "content": prompt},
            ],
            stream=True,  # SSE-based token streaming
        )

        async for chunk in stream:
            delta = chunk.choices[0].delta.content
            if delta:
                yield delta

class StreamingPostprocessor:
    """Post-process tokens on-the-fly: filter, format, store as they arrive."""

    def __init__(self):
        self.buffer = ""

    async def process_stream(self, token_stream: AsyncGenerator[str, None]) -> AsyncGenerator[str, None]:
        """Filter and augment tokens before forwarding."""
        async for token in token_stream:
            self.buffer += token
            # Apply real-time transformations
            yield token

    async def flush(self) -> None:
        """Persist the complete accumulated text."""
        if self.buffer:
            await result_store.save(self.buffer)
            self.buffer = ""

# Chunked response in FastAPI
from fastapi import FastAPI
from fastapi.responses import StreamingResponse

app = FastAPI()

@app.post("/pipeline/stream")
async def streaming_pipeline(request: dict):
    """API endpoint: returns chunked SSE response from the pipeline."""
    prompt = request["prompt"]

    async def generate():
        llm_node = StreamingLLMNode()
        postproc = StreamingPostprocessor()
        async for token in postproc.process_stream(llm_node.stream(prompt)):
            yield f"data: {token}\n\n"
        await postproc.flush()
        yield "data: [DONE]\n\n"

    return StreamingResponse(generate(), media_type="text/event-stream")
```

流式处理的工程挑战在于**背压（backpressure）**：如果LLM生成速度（100 tokens/sec）超过了后处理节点的处理能力（50 tokens/sec），需要缓冲或丢弃。实践中使用有界队列（`asyncio.Queue(maxsize=256)`）来协调生产者和消费者的速度差异。

### 4.3 事件驱动架构：Event Bridge→Lambda→Step Functions

在云原生环境中，AI工作流可以完全由事件驱动。AWS的架构三元组（EventBridge + Lambda + Step Functions）是一个典型的参考模式：

- **EventBridge** 接收各种事件源（S3上传、SQS消息、API调用），根据事件规则路由到目标
- **Lambda** 执行无状态的计算节点（预处理、后处理、轻量推理）
- **Step Functions** 编排有状态的工作流（条件分支、并行扇出、人工审批）

```python
# === AWS Step Functions: event-driven AI workflow (CDK definition) ===
from aws_cdk import (
    aws_stepfunctions as sfn,
    aws_stepfunctions_tasks as tasks,
    aws_lambda as lambda_,
    aws_events as events,
    aws_events_targets as targets,
    Stack, Duration,
)

class AIEventDrivenPipeline(Stack):
    """Event-driven AI pipeline: S3 upload -> EventBridge -> Step Functions -> Lambda."""

    def __init__(self, scope, id: str, **kwargs):
        super().__init__(scope, id, **kwargs)

        # Lambda functions for each pipeline stage
        preprocess_fn = lambda_.Function(self, "Preprocess", ...)
        inference_fn = lambda_.Function(self, "Inference", ...)
        postprocess_fn = lambda_.Function(self, "Postprocess", ...)
        quality_fn = lambda_.Function(self, "QualityGate", ...)

        # Step Functions state machine
        definition = (
            sfn.Chain
            .start(tasks.LambdaInvoke(self, "Preprocess", lambda_function=preprocess_fn))
            .next(sfn.Choice(self, "ContentCheck")
                  .when(sfn.Condition.boolean_equals("$.content_safe", True),
                        tasks.LambdaInvoke(self, "Inference", lambda_function=inference_fn))
                  .otherwise(tasks.LambdaInvoke(self, "FlagForReview",
                                                lambda_function=postprocess_fn)))
            .next(tasks.LambdaInvoke(self, "Postprocess", lambda_function=postprocess_fn))
            .next(tasks.LambdaInvoke(self, "QualityGate", lambda_function=quality_fn))
            .next(sfn.Choice(self, "HumanReview")
                  .when(sfn.Condition.boolean_equals("$.needs_review", True),
                        sfn.Succeed(self, "AwaitingHumanReview"))
                  .otherwise(sfn.Succeed(self, "Completed")))
        )

        state_machine = sfn.StateMachine(
            self, "AIPipeline",
            definition=definition,
            timeout=Duration.minutes(15),
        )

        # EventBridge rule: trigger on S3 upload
        rule = events.Rule(self, "NewDocumentRule",
            event_pattern=events.EventPattern(
                source=["aws.s3"],
                detail_type=["Object Created"],
                detail={"bucket": {"name": ["ai-documents"]}},
            ),
            targets=[targets.SfnStateMachine(state_machine)],
        )
```

事件驱动架构的优势是**松耦合和自动缩放**：每个事件触发一个独立的执行上下文，没有资源被浪费在空闲等待上。缺点是调试难度大（事件流难以追踪）和冷启动延迟（Lambda首次调用可能有1-5秒的初始化时间）。

## 五、状态管理

### 5.1 Checkpoint机制：节点执行中间结果持久化

Checkpoint是工作流引擎实现容错和恢复的基础。每个节点执行完成后，将其输出持久化到可靠存储（数据库、对象存储或文件系统），这样即使整个系统崩溃，新启动的实例也能从最后一个Checkpoint恢复。

```python
# === Checkpoint mechanism for workflow persistence ===
import pickle
import sqlite3
from datetime import datetime, timezone

class CheckpointStore:
    """Persist workflow node outputs for recovery and audit."""

    def __init__(self, db_path: str = "workflow_checkpoints.db"):
        self.conn = sqlite3.connect(db_path, check_same_thread=False)
        self.conn.execute("""
            CREATE TABLE IF NOT EXISTS checkpoints (
                workflow_id TEXT NOT NULL,
                node_id TEXT NOT NULL,
                state TEXT NOT NULL,
                result BLOB,
                error TEXT,
                created_at TEXT NOT NULL,
                PRIMARY KEY (workflow_id, node_id)
            )
        """)
        self.conn.commit()

    async def save(self, workflow_id: str, node_id: str, state: str,
                   result: Any = None, error: str | None = None) -> None:
        """Persist a node's execution result."""
        result_blob = pickle.dumps(result) if result else None
        self.conn.execute(
            "INSERT OR REPLACE INTO checkpoints VALUES (?, ?, ?, ?, ?, ?)",
            (workflow_id, node_id, state, result_blob, error,
             datetime.now(timezone.utc).isoformat()),
        )
        self.conn.commit()

    async def load(self, workflow_id: str) -> dict[str, dict]:
        """Restore all checkpoints for a workflow — used for recovery."""
        cursor = self.conn.execute(
            "SELECT node_id, state, result, error FROM checkpoints WHERE workflow_id = ?",
            (workflow_id,),
        )
        rows = cursor.fetchall()
        return {
            row[0]: {
                "state": row[1],
                "result": pickle.loads(row[2]) if row[2] else None,
                "error": row[3],
            }
            for row in rows
        }

    async def list_incomplete(self, workflow_id: str) -> list[str]:
        """List nodes that have not successfully completed."""
        cursor = self.conn.execute(
            "SELECT node_id FROM checkpoints WHERE workflow_id = ? AND state != 'SUCCEEDED'",
            (workflow_id,),
        )
        return [row[0] for row in cursor.fetchall()]

class RecoverableWorkflow:
    """Workflow that can resume from the last checkpoint."""

    def __init__(self, checkpoint_store: CheckpointStore):
        self.store = checkpoint_store

    async def execute_with_recovery(self, workflow_id: str, nodes: dict[str, Callable],
                                    adjacency: dict[str, list[str]],
                                    depends_on: dict[str, list[str]]) -> dict[str, Any]:
        """Execute workflow — skip completed nodes, redo pending/failed ones."""
        completed = await self.store.load(workflow_id)
        results = {nid: n["result"] for nid, n in completed.items()
                   if n["state"] == "SUCCEEDED"}
        in_degree = {nid: 0 for nid in nodes}
        for nid, deps in depends_on.items():
            in_degree[nid] = len(deps)

        order = self._resolve_order(depends_on)
        for node_id in order:
            if node_id in results:
                continue  # already completed in a previous run

            # Collect dependency results
            dep_results = {dep: results.get(dep) for dep in depends_on.get(node_id, [])}
            try:
                await self.store.save(workflow_id, node_id, "RUNNING")
                node_result = await nodes[node_id](dep_results)
                results[node_id] = node_result
                await self.store.save(workflow_id, node_id, "SUCCEEDED", result=node_result)
            except Exception as e:
                await self.store.save(workflow_id, node_id, "FAILED", error=str(e))
                raise

        return results

    def _resolve_order(self, depends_on: dict[str, list[str]]) -> list[str]:
        """Simple Kahn's algorithm for execution ordering."""
        in_degree = {nid: len(deps) for nid, deps in depends_on.items()}
        from collections import deque
        queue = deque([n for n, d in in_degree.items() if d == 0])
        order = []
        while queue:
            node = queue.popleft()
            order.append(node)
            for nid, deps in depends_on.items():
                if node in deps:
                    in_degree[nid] -= 1
                    if in_degree[nid] == 0:
                        queue.append(nid)
        return order
```

Checkpoint的设计决策包括：
- **粒度**：节点级（每个节点完成后保存）还是步骤级（节点内多个步骤完成后保存）？节点级更简单，但长节点（如处理1000个文档的循环节点）可能需要在内部设置子Checkpoint
- **存储后端**：SQLite适合单机，PostgreSQL适合多Worker共享，S3适合归档和审计
- **序列化格式**：pickle（Python原生，不安全）、JSON（安全，但不支持复杂类型）、MessagePack（紧凑，适合大体积结果如中间张量）

### 5.2 分布式锁与并发控制

在分布式工作流中，多个Worker可能同时尝试执行同一个节点——这就是并发冲突。Redis Redlock是一种广泛使用的分布式锁实现。

```python
# === Distributed lock with Redis Redlock for workflow concurrency ===
import aioredis
import uuid
import time

class DistributedWorkflowLock:
    """Redis-based distributed lock for workflow node execution."""

    def __init__(self, redis_client: aioredis.Redis, lock_ttl_ms: int = 30_000):
        self.redis = redis_client
        self.lock_ttl_ms = lock_ttl_ms

    async def acquire(self, workflow_id: str, node_id: str,
                      owner_id: str | None = None) -> str | None:
        """Try to acquire a lock on a workflow node. Returns lock token if successful."""
        lock_key = f"wf:lock:{workflow_id}:{node_id}"
        token = owner_id or str(uuid.uuid4())
        acquired = await self.redis.set(
            lock_key, token,
            nx=True,                  # only set if key does not exist
            px=self.lock_ttl_ms,      # auto-expire to prevent deadlock
        )
        return token if acquired else None

    async def release(self, workflow_id: str, node_id: str, token: str) -> bool:
        """Release lock only if we still own it (Lua script for atomicity)."""
        lock_key = f"wf:lock:{workflow_id}:{node_id}"
        lua_script = """
        if redis.call("get", KEYS[1]) == ARGV[1] then
            return redis.call("del", KEYS[1])
        else
            return 0
        end
        """
        result = await self.redis.eval(lua_script, keys=[lock_key], args=[token])
        return result == 1

    async def with_lock(self, workflow_id: str, node_id: str,
                        fn: Callable, timeout_ms: int = 30_000):
        """Context-manager style: acquire lock, execute fn, release."""
        token = None
        deadline = time.monotonic() + timeout_ms / 1000
        while time.monotonic() < deadline:
            token = await self.acquire(workflow_id, node_id)
            if token:
                break
            await asyncio.sleep(0.1)  # retry interval
        if not token:
            raise TimeoutError(f"Could not acquire lock for {workflow_id}:{node_id}")
        try:
            return await fn()
        finally:
            await self.release(workflow_id, node_id, token)
```

Redlock的核心安全属性包括：锁自动过期（防止Worker崩溃后锁永久持有）、只有锁的持有者才能释放（通过Lua脚本检查token）、可重入（通过计数器扩展）。在AI Pipeline中，分布式锁主要用于**资源竞争场景**——如两个并行分支同时写入同一个状态键，或两个推理节点同时调用同一个API但受限于并发配额。

### 5.3 工作流回溯与恢复：断点续传

当工作流因错误中断后恢复时，需要精确区分"已完成"、"进行中"和"待执行"三种节点状态。这被称为**断点续传（resume from breakpoint）**。

```python
# === Resume workflow from last successful checkpoint ===
class WorkflowRecoveryManager:
    """Handles workflow resume, rollback, and compensation for failed branches."""

    def __init__(self, checkpoint_store: CheckpointStore, lock_service: DistributedWorkflowLock):
        self.store = checkpoint_store
        self.lock = lock_service

    async def resume(self, workflow_id: str, dag: nx.DiGraph,
                     node_fns: dict[str, Callable]) -> dict[str, Any]:
        """Resume a workflow from the last checkpoint."""
        checkpoints = await self.store.load(workflow_id)

        # Phase 1: Classify nodes
        completed = set()
        failed = set()
        running = set()
        for nid, state_data in checkpoints.items():
            if state_data["state"] == "SUCCEEDED":
                completed.add(nid)
            elif state_data["state"] == "FAILED":
                failed.add(nid)
            else:
                running.add(nid)

        results = {nid: state_data["result"] for nid, state_data in checkpoints.items()
                   if state_data["state"] == "SUCCEEDED" and state_data["result"] is not None}

        # Phase 2: Roll back failed branch — identify downstream of failed nodes
        to_rollback = set()
        for nid in failed:
            to_rollback.update(nx.descendants(dag, nid))

        for nid in to_rollback:
            results.pop(nid, None)
            completed.discard(nid)

        # Phase 3: Execute pending nodes (completed are skipped, failed are retried)
        order = list(nx.topological_sort(dag))
        for node_id in order:
            if node_id in completed and node_id not in failed:
                continue

            async def execute_node(nid: str, deps: dict) -> Any:
                return await self.lock.with_lock(workflow_id, nid, lambda: node_fns[nid](deps))

            predecessors = list(dag.predecessors(node_id))
            dep_results = {p: results.get(p) for p in predecessors}
            try:
                await self.store.save(workflow_id, node_id, "RUNNING")
                result = await execute_node(node_id, dep_results)
                results[node_id] = result
                await self.store.save(workflow_id, node_id, "SUCCEEDED", result=result)
            except Exception as e:
                await self.store.save(workflow_id, node_id, "FAILED", error=str(e))
                raise

        return results

    async def compensate_failed(self, workflow_id: str, dag: nx.DiGraph,
                                compensations: dict[str, Callable]) -> None:
        """Run compensation actions for every succeeded node in reverse order."""
        order = list(reversed(list(nx.topological_sort(dag))))
        for node_id in order:
            if node_id in compensations:
                try:
                    await compensations[node_id]()
                except Exception as e:
                    print(f"Compensation failed for {node_id}: {e}")
```

断点续传的核心机制是**幂等重入**：每个节点必须实现为幂等的（相同输入产生相同输出），这样重放不会产生副作用。对于LLM调用节点，幂等性需要额外处理——通过缓存（相同的提示词+参数直接返回缓存结果）或通过去重（每个请求携带唯一的idempotency key）。

### 6.1 OpenTelemetry：节点级Span与Trace传播

### 6.2 节点延迟统计与瓶颈识别

```python
# === Latency tracking and bottleneck identification ===
import time
from collections import defaultdict

class WorkflowProfiler:
    """Profile each node's latency and identify bottlenecks."""

    def __init__(self):
        self.timings: dict[str, list[float]] = defaultdict(list)  # node_id -> [latency_ms]
        self.attempts: dict[str, int] = defaultdict(int)

    async def profile(self, node_id: str, fn: Callable, *args) -> Any:
        """Wrap a node execution with timing."""
        start = time.perf_counter()
        try:
            result = await fn(*args)
            return result
        finally:
            elapsed_ms = (time.perf_counter() - start) * 1000
            self.timings[node_id].append(elapsed_ms)
            self.attempts[node_id] += 1

    def identify_bottlenecks(self, threshold_p95_ms: float = 5000.0) -> list[dict]:
        """Identify nodes with p95 latency exceeding threshold."""
        bottlenecks = []
        for node_id, latencies in self.timings.items():
            if not latencies:
                continue
            sorted_lat = sorted(latencies)
            p50 = sorted_lat[len(sorted_lat) // 2]
            p95 = sorted_lat[int(len(sorted_lat) * 0.95)]
            bottlenecks.append({
                "node_id": node_id,
                "p50_ms": round(p50, 1),
                "p95_ms": round(p95, 1),
                "attempts": len(latencies),
                "is_bottleneck": p95 > threshold_p95_ms,
            })

        return sorted(bottlenecks, key=lambda x: x["p95_ms"], reverse=True)

    def report(self) -> dict:
        """Generate a full profiling report."""
        bn = self.identify_bottlenecks()
        total_time = sum(sum(t) for t in self.timings.values())
        return {
            "total_pipeline_ms": round(total_time, 1),
            "node_count": len(self.timings),
            "bottlenecks": [b for b in bn if b["is_bottleneck"]],
            "all_nodes": bn,
        }
```

### 6.3 质量门禁：条件流转触发人审或回退

Quality Gate结合了监控和控制两个功能：它监控每个节点的输出质量，并在质量不达标时触发工作流的条件转移（回退到上一个节点、路由到人工审核通道、或直接终止）。

```python
# === Quality Gate with automatic routing ===
from enum import Enum

class GateDecision(Enum):
    PASS = "pass"                  # continue to next node
    RETRY = "retry"                # re-execute current node
    ROLLBACK = "rollback"          # undo and go back N nodes
    HUMAN_REVIEW = "human_review"  # pause and wait
    ABORT = "abort"                # terminate workflow

@dataclass
class GateResult:
    decision: GateDecision
    score: float
    reason: str
    metadata: dict = field(default_factory=dict)

class QualityGateSystem:
    """Pluggable quality gates that analyze node outputs and route the workflow."""

    def __init__(self):
        self.gates: dict[str, list[Callable[[dict], Awaitable[GateResult]]]] = defaultdict(list)

    def register_gate(self, node_id: str, gate_fn: Callable) -> None:
        """Register a quality check function for a specific node."""
        self.gates[node_id].append(gate_fn)

    async def evaluate_node(self, node_id: str, output: dict,
                            pipeline_context: dict) -> GateDecision:
        """Evaluate all gates for a node. Returns the strictest decision."""
        gate_fns = self.gates.get(node_id, [])
        if not gate_fns:
            return GateDecision.PASS

        worst = GateDecision.PASS
        for check in gate_fns:
            result = await check(output, pipeline_context)
            if self._severity(result.decision) > self._severity(worst):
                worst = result.decision
            if worst == GateDecision.ABORT:
                break

        return worst

    def _severity(self, d: GateDecision) -> int:
        return {"pass": 0, "retry": 1, "rollback": 2, "human_review": 3, "abort": 4}[d.value]

# Example: gate that checks LLM output for hallucination risk
async def hallucination_check(output: dict, ctx: dict) -> GateResult:
    """Detect potential hallucination by checking factual consistency."""
    text = output.get("text", "")
    source_docs = output.get("source_documents", [])
    if not source_docs:
        return GateResult(GateDecision.PASS, 1.0, "No source documents to verify against")

    # Check: does the output contain claims not present in any source document?
    claims = await extract_claims(text)
    unsupported = []
    for claim in claims:
        support_scores = [compute_support(claim, doc) for doc in source_docs]
        if max(support_scores) < 0.5:
            unsupported.append(claim)

    unsupported_ratio = len(unsupported) / max(len(claims), 1)
    if unsupported_ratio > 0.3:
        return GateResult(
            GateDecision.HUMAN_REVIEW, 1.0 - unsupported_ratio,
            f"{len(unsupported)}/{len(claims)} claims lack source support"
        )
    if unsupported_ratio > 0.1:
        return GateResult(
            GateDecision.RETRY, 1.0 - unsupported_ratio,
            "Retry: too many unsupported claims"
        )
    return GateResult(GateDecision.PASS, 1.0 - unsupported_ratio, "OK")
```

## 七、生产化部署

### 7.1 工作流模板化：YAML/JSON配置驱动

生产环境的AI工作流需要支持**动态加载**——工作流定义存储在配置文件中，运行时解析构建DAG，而非硬编码在代码中。这样运维人员无需修改代码就能调整管线拓扑。

```python
# === YAML-defined workflow: load and execute dynamically ===
import yaml
from pathlib import Path

# Example workflow YAML:
# nodes:
#   - id: validate_input
#     type: python_function
#     module: pipeline.nodes.input
#     function: validate
#     retry: 3
#   - id: retrieve_context
#     type: python_function
#     module: pipeline.nodes.retrieval
#     function: retrieve
#     depends_on: [validate_input]
#   - id: generate
#     type: llm_call
#     model: gpt-4o
#     prompt_template: "templates/rag_prompt.jinja"
#     depends_on: [retrieve_context]
#     max_tokens: 1024
#   - id: quality_gate
#     type: conditional
#     function: pipeline.gates.quality
#     branches:
#       pass: output
#       retry: generate
#       human_review: approval_queue
#     depends_on: [generate]

class WorkflowTemplateLoader:
    """Load workflow definitions from YAML/JSON and construct the execution graph."""

    def __init__(self, template_dir: str = "workflow_templates"):
        self.template_dir = Path(template_dir)
        self._func_cache: dict[str, Callable] = {}

    async def load(self, template_name: str) -> "WorkflowInstance":
        """Load a template and build a runnable workflow instance."""
        template_path = self.template_dir / f"{template_name}.yaml"
        if not template_path.exists():
            raise FileNotFoundError(f"Workflow template not found: {template_path}")

        with open(template_path) as f:
            spec = yaml.safe_load(f)

        return await self._build_from_spec(spec)

    async def _build_from_spec(self, spec: dict) -> "WorkflowInstance":
        """Parse spec into executable nodes with resolved dependencies."""
        nodes = {}
        adjacency = {}

        for node_spec in spec["nodes"]:
            nid = node_spec["id"]
            node_fn = self._resolve_function(node_spec)
            nodes[nid] = node_fn
            adjacency[nid] = node_spec.get("depends_on", [])

        return WorkflowInstance(nodes=nodes, adjacency=adjacency,
                                config=spec.get("config", {}))

    def _resolve_function(self, spec: dict) -> Callable:
        """Dynamically import and return the function for a node spec."""
        node_type = spec.get("type", "python_function")
        if node_type == "llm_call":
            return self._build_llm_node(spec)
        elif node_type == "conditional":
            return self._build_conditional_node(spec)
        else:
            # Standard python_function: module + function import
            key = f"{spec['module']}.{spec['function']}"
            if key not in self._func_cache:
                import importlib
                mod = importlib.import_module(spec["module"])
                self._func_cache[key] = getattr(mod, spec["function"])
            return self._func_cache[key]

    def _build_llm_node(self, spec: dict) -> Callable:
        """Factory: returns an async callable that invokes the LLM."""
        prompt_template = spec.get("prompt_template", "")
        model = spec["model"]
        max_tokens = spec.get("max_tokens", 1024)

        async def llm_node(deps: dict) -> dict:
            # Load and render prompt template
            from jinja2 import Template
            template_path = self.template_dir / prompt_template
            if template_path.exists():
                template = Template(template_path.read_text())
                prompt = template.render(**deps)
            else:
                prompt = str(deps.get("query", ""))

            response = await llm_client.chat.completions.create(
                model=model, messages=[{"role": "user", "content": prompt}],
                max_tokens=max_tokens,
            )
            return {"text": response.choices[0].message.content,
                    "model": model, "tokens": response.usage.total_tokens}

        return llm_node

class WorkflowInstance:
    """A loaded, runnable workflow — created from a template."""

    def __init__(self, nodes: dict[str, Callable], adjacency: dict[str, list[str]],
                 config: dict | None = None):
        self.nodes = nodes
        self.adjacency = adjacency
        self.config = config or {}

    async def run(self, init_context: dict) -> dict[str, Any]:
        """Execute the workflow with the given initial context."""
        order = self._resolve_order()
        results = dict(init_context)

        for nid in order:
            deps = {dep: results[dep] for dep in self.adjacency.get(nid, [])}
            results[nid] = await self.nodes[nid](deps)

        return results

    def _resolve_order(self) -> list[str]:
        in_degree = {nid: len(self.adjacency.get(nid, [])) for nid in self.nodes}
        from collections import deque
        q = deque([n for n, d in in_degree.items() if d == 0])
        order = []
        while q:
            node = q.popleft()
            order.append(node)
            for nid, deps in self.adjacency.items():
                if node in deps:
                    in_degree[nid] -= 1
                    if in_degree[nid] == 0:
                        q.append(nid)
        return order
```

### 7.2 多租户隔离

当工作流引擎服务多个团队或客户时，需要多租户隔离。隔离的维度包括：数据隔离（每个租户的工作流数据不互通）、资源隔离（CPU/GPU/内存配额隔离）、和速率隔离（每个租户的API调用配额独立）。

```python
# === Multi-tenant isolation for workflow engine ===
from dataclasses import dataclass, field

@dataclass
class TenantQuota:
    tenant_id: str
    max_concurrent_workflows: int = 10
    max_tokens_per_hour: int = 1_000_000
    max_gpu_seconds_per_day: int = 3600
    allowed_models: list[str] = field(default_factory=lambda: ["gpt-4o-mini", "gpt-4o"])
    priority: int = 0  # higher = more urgent

class TenantIsolationMiddleware:
    """Enforce tenant isolation: separate state, quotas, and rate limits."""

    def __init__(self, redis: aioredis.Redis):
        self.redis = redis
        self._tenants: dict[str, TenantQuota] = {}

    def register_tenant(self, quota: TenantQuota) -> None:
        self._tenants[quota.tenant_id] = quota

    async def check_quota(self, tenant_id: str, tokens_requested: int) -> bool:
        """Check if tenant can execute a workflow without exceeding quotas."""
        quota = self._tenants.get(tenant_id)
        if not quota:
            return False

        # Check concurrent workflow count
        current = await self._get_concurrent_count(tenant_id)
        if current >= quota.max_concurrent_workflows:
            return False

        # Check hourly token consumption
        consumed = await self._get_hourly_token_usage(tenant_id)
        if consumed + tokens_requested > quota.max_tokens_per_hour:
            return False

        return True

    async def record_usage(self, tenant_id: str, tokens_used: int,
                           gpu_seconds: float) -> None:
        """Record tenant resource consumption."""
        pipe = self.redis.pipeline()
        # Token usage (hourly rolling window)
        key_hr = f"tenant:{tenant_id}:tokens:hourly"
        pipe.incrby(key_hr, tokens_used)
        pipe.expire(key_hr, 3600)

        # GPU usage (daily)
        key_day = f"tenant:{tenant_id}:gpu:daily"
        pipe.incrbyfloat(key_day, gpu_seconds)
        pipe.expire(key_day, 86400)

        await pipe.execute()

    async def _get_concurrent_count(self, tenant_id: str) -> int:
        """Active workflow count for this tenant."""
        keys = await self.redis.keys(f"wf:active:{tenant_id}:*")
        return len(keys)

    async def _get_hourly_token_usage(self, tenant_id: str) -> int:
        val = await self.redis.get(f"tenant:{tenant_id}:tokens:hourly")
        return int(val) if val else 0
```

### 7.3 Rate Limiting + Budget Control

AI Pipeline的预算控制是一个独特挑战：每次LLM调用都在消耗真金白银。必须实现**Token Consumption Tracking**和**Quota Enforcement**来防止预算失控。

```python
# === Budget control: token tracking and quota enforcement ===
from datetime import datetime, timedelta

class TokenBudgetController:
    """
    Track token consumption and enforce budget quotas.
    Supports per-workflow, per-tenant, and global budgets.
    """

    def __init__(self, redis: aioredis.Redis):
        self.redis = redis

    async def check_budget(self, workflow_id: str, estimated_tokens: int,
                           budget_config: dict) -> bool:
        """
        Check multiple budget layers before allowing a costly LLM call.
        budget_config:
            max_tokens_per_run: int
            max_tokens_per_day: int
            cost_limit_per_run: float
            cost_limit_per_month: float
        """
        # Layer 1: per-workflow run budget
        run_used = await self._get_workflow_usage(workflow_id)
        run_limit = budget_config.get("max_tokens_per_run", 50_000)
        if run_used + estimated_tokens > run_limit:
            raise BudgetExceeded(f"Workflow {workflow_id}: run token budget exceeded")

        # Layer 2: daily budget (across all workflows for this tenant)
        daily_used = await self._get_daily_usage()
        daily_limit = budget_config.get("max_tokens_per_day", 1_000_000)
        if daily_used + estimated_tokens > daily_limit:
            raise BudgetExceeded(f"Daily token budget exceeded: {daily_used + estimated_tokens} > {daily_limit}")

        # Layer 3: cost budget (USD)
        model_cost_per_1k_tokens = budget_config.get("model_cost", 0.01)
        estimated_cost = estimated_tokens / 1000 * model_cost_per_1k_tokens
        monthly_cost = await self._get_monthly_cost()
        monthly_limit = budget_config.get("cost_limit_per_month", 100.0)
        if monthly_cost + estimated_cost > monthly_limit:
            raise BudgetExceeded(
                f"Monthly cost budget exceeded: ${monthly_cost + estimated_cost:.2f} > ${monthly_limit:.2f}"
            )

        return True

    async def record_usage(self, workflow_id: str, tokens_used: int) -> None:
        """Persist token consumption and decrement remaining budget."""
        pipe = self.redis.pipeline()

        # Per-workflow running count
        pipe.incrby(f"wf:usage:{workflow_id}:tokens", tokens_used)

        # Daily aggregate
        today = datetime.utcnow().strftime("%Y-%m-%d")
        pipe.incrby(f"daily_usage:{today}", tokens_used)

        await pipe.execute()

    async def get_remaining_budget(self, tenant_id: str) -> dict:
        """Return remaining budget for observability and alerting."""
        daily_key = f"daily_usage:{datetime.utcnow().strftime('%Y-%m-%d')}"
        daily_used = int(await self.redis.get(daily_key) or 0)
        daily_limit = 1_000_000

        return {
            "daily_used": daily_used,
            "daily_remaining": max(0, daily_limit - daily_used),
            "daily_budget": daily_limit,
            "usage_percent": round(daily_used / daily_limit * 100, 1),
        }

    async def _get_workflow_usage(self, workflow_id: str) -> int:
        val = await self.redis.get(f"wf:usage:{workflow_id}:tokens")
        return int(val) if val else 0

    async def _get_daily_usage(self) -> int:
        key = f"daily_usage:{datetime.utcnow().strftime('%Y-%m-%d')}"
        val = await self.redis.get(key)
        return int(val) if val else 0

    async def _get_monthly_cost(self) -> float:
        month = datetime.utcnow().strftime("%Y-%m")
        val = await self.redis.get(f"monthly_cost:{month}")
        return float(val) if val else 0.0

class BudgetExceeded(Exception):
    """Raised when a workflow exceeds its budget allocation."""
    pass

# Rate limiter: sliding window + token bucket
class SlidingWindowRateLimiter:
    """Sliding-window rate limiter for LLM API calls."""

    def __init__(self, redis: aioredis.Redis):
        self.redis = redis

    async def check_rate(self, key: str, max_requests: int, window_seconds: int = 60) -> bool:
        """Check if we are within the rate limit for a given key."""
        now = datetime.utcnow().timestamp()
        window_start = now - window_seconds

        # Remove stale entries
        await self.redis.zremrangebyscore(f"ratelimit:{key}", "-inf", window_start)

        # Count current window
        count = await self.redis.zcard(f"ratelimit:{key}")
        if count >= max_requests:
            return False

        # Add current request
        await self.redis.zadd(f"ratelimit:{key}", {str(now): now})
        await self.redis.expire(f"ratelimit:{key}", window_seconds * 2)
        return True
```

### 7.4 工作流版本管理与回滚策略

AI工作流的版本管理比传统软件更复杂——不仅代码在变，LLM模型也在变，prompt也在变。每个版本应当包含完整的管线定义、prompt模板、模型选择、参数配置和quality gate阈值。

```python
# === Workflow version management with rollback ===
from datetime import datetime

@dataclass
class WorkflowVersion:
    version_id: str
    template_name: str
    spec: dict
    created_at: str
    deployed_by: str
    changelog: str
    status: str  # active | deprecated | rolled_back

class WorkflowVersionManager:
    """Manages workflow versions, deploys new versions, and supports rollback."""

    def __init__(self, db_connection):
        self.db = db_connection

    async def deploy_version(self, template_name: str, spec: dict,
                             deployed_by: str, changelog: str) -> WorkflowVersion:
        """Create and deploy a new version of a workflow."""
        version_id = f"{template_name}_v{await self._next_version(template_name)}"
        version = WorkflowVersion(
            version_id=version_id,
            template_name=template_name,
            spec=spec,
            created_at=datetime.utcnow().isoformat(),
            deployed_by=deployed_by,
            changelog=changelog,
            status="active",
        )

        # Mark previous active versions as deprecated
        await self.db.execute(
            "UPDATE workflow_versions SET status = 'deprecated' "
            "WHERE template_name = ? AND status = 'active'",
            (template_name,),
        )

        # Insert new version
        await self.db.execute(
            "INSERT INTO workflow_versions VALUES (?, ?, ?, ?, ?, ?, ?)",
            (version.version_id, version.template_name, str(version.spec),
             version.created_at, version.deployed_by, version.changelog, version.status),
        )
        await self.db.commit()

        return version

    async def rollback(self, template_name: str,
                       target_version: str | None = None) -> WorkflowVersion:
        """Rollback to a previous version. If no target specified, go to previous active."""
        if target_version:
            # Explicit rollback target
            cursor = await self.db.execute(
                "SELECT * FROM workflow_versions WHERE template_name = ? AND version_id = ?",
                (template_name, target_version),
            )
            version = await cursor.fetchone()
            if not version:
                raise ValueError(f"Version {target_version} not found")

            # Set as active, deprecate current
            await self.db.execute(
                "UPDATE workflow_versions SET status = 'rolled_back' "
                "WHERE template_name = ? AND status = 'active'",
                (template_name,),
            )
            await self.db.execute(
                "UPDATE workflow_versions SET status = 'active' WHERE version_id = ?",
                (target_version,),
            )
        else:
            # Auto-rollback: find the version immediately before current active
            cursor = await self.db.execute(
                "SELECT * FROM workflow_versions WHERE template_name = ? "
                "AND status = 'deprecated' ORDER BY created_at DESC LIMIT 1",
                (template_name,),
            )
            prev = await cursor.fetchone()
            if not prev:
                raise ValueError(f"No previous version to rollback to for {template_name}")

            # Rollback
            await self.db.execute(
                "UPDATE workflow_versions SET status = 'rolled_back' "
                "WHERE template_name = ? AND status = 'active'",
                (template_name,),
            )
            version = WorkflowVersion(*prev)
            await self.db.execute(
                "UPDATE workflow_versions SET status = 'active' WHERE version_id = ?",
                (version.version_id,),
            )

        await self.db.commit()
        return version

    async def list_versions(self, template_name: str) -> list[WorkflowVersion]:
        cursor = await self.db.execute(
            "SELECT * FROM workflow_versions WHERE template_name = ? ORDER BY created_at DESC",
            (template_name,),
        )
        rows = await cursor.fetchall()
        return [WorkflowVersion(*row) for row in rows]

    async def canary_deploy(self, template_name: str, new_spec: dict,
                            traffic_percent: int = 10) -> str:
        """
        Canary deploy: route a small percentage of traffic to the new version.
        Returns the canary version ID for monitoring.
        """
        version = await self.deploy_version(template_name, new_spec,
                                            "canary_deploy", "Canary deployment for testing")
        # In a real system, the router would check this config:
        await self.db.execute(
            "INSERT INTO canary_config (template_name, version_id, traffic_percent) "
            "VALUES (?, ?, ?) ON CONFLICT(template_name) DO UPDATE SET "
            "version_id = excluded.version_id, traffic_percent = excluded.traffic_percent",
            (template_name, version.version_id, traffic_percent),
        )
        await self.db.commit()
        return version.version_id
```

**回滚策略**在生产中至关重要。一个常见的错误场景是：升级prompt后LLM输出质量骤降，需要秒级回滚到上一个稳定版本。版本管理支持：
- **全量回滚**：直接切回上一个active版本
- **Canary回滚**：新版本仅接收10%流量，有问题自动切回
- **蓝绿部署**：两套完整管线并行，通过负载均衡切换

## 总结

AI工作流编排正从简单的Pipeline向复杂的多模态DAG演进。本文从七个维度系统性地剖析了其工程实现：

1. **执行模型**上，DAG以其表达能力和并行性成为主流，但需要拓扑排序保证无环
2. **框架选型**中，LangGraph适合LLM-native的图构建，Temporal保障分布式可靠性，Airflow/Prefect定位在离线数据制备层
3. **组件化**要求每个节点（数据处理、LLM调用、多模态处理、质量控制）可独立替换和测试
4. **异步架构**的选择取决于规模：asyncio适合单机，Task Queue适合跨机器，Actor模型适合GPU持久化
5. **状态管理**通过Checkpoint实现断点续传，Redis Redlock解决分布式并发，幂等性设计保证安全重放
6. **可观测性**以OpenTelemetry为核心，实现节点级追踪和Quality Gate的条件路由
7. **生产化部署**需要模板化、多租户隔离、预算控制和版本管理，将工作流从"实验脚本"升级为"生产服务"

AI工作流引擎的本质，是把不可预测的LLM行为装进可预测的系统架构中。好的编排不是消除不确定性，而是为不确定性设计安全边界。
