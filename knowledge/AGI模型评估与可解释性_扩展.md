# AGI 模型评估与可解释性（扩展）

---

## 总览：评估是AGI的"仪表盘"，可解释性是"黑匣子探针"

模型能力在膨胀——但我们的"尺子"却常常在失效：基准被污染、指标被游戏化、统计报告流于形式。而"理解模型为什么这么想"——可解释性——从学术好奇心变成了安全刚需（模型越强——越需要知道它的失败模式）。

本扩展文档——覆盖评估与可解释性的六个实战主题：评估污染与动态评测、N-gram 指标的缺陷与替代、Bias 量化方法、评估集设计方法论、AI 论文中的统计显著性、以及可解释性的因果方法（interchange intervention、causal tracing）。

```
评估体系：
静态基准（MMLU/GPQA）──→ 污染风险 ──→ 去污染/指纹库
动态评测（LiveBench/HLE）──→ 时间切分/私有化
生成指标（BLEU/ROUGE）──→ 缺陷 ──→ BERTScore/BLEURT/LLM-as-judge
偏差度量（BBQ/StereoSet/WEAT）──→ 反事实评估
评估集设计：难例挖掘 + 覆盖分析 + 干扰项 + IRT 标定
统计显著性：多次采样 + 置信区间 + 配对检验
可解释性：
行为层（探针/对比）→ 机制层（激活/电路）→ 因果层（干预/patching/tracing）
```

## 一、评估污染（Benchmark Contamination）

### 1.1 污染的本质

**污染**：评测样本（或其变形）出现在训练数据中——使评测分数反映"记忆"而非"能力"。

**污染为什么必然发生**：
- 训练语料来自互联网爬虫——而公开基准（MMLU、GPQA、GSM8K、HumanEval）都发布在互联网上
- 基准题常被搬运到 GitHub、博客、论坛——成为爬虫语料的一部分
- 合成数据加剧污染：教师模型见过基准 → 蒸馏给学生 → 学生"间接"背题

### 1.2 污染检测技术

```
1. n-gram 精确重叠检测（最基础）：
   评测样本与训练语料逐文档求最大连续重叠子串
   8-gram / 13-gram 完全匹配 → 判定污染
   优点：简单、可审计；缺点：抓不住改写/翻译/数字替换

2. 模糊匹配（变体检测）：
   子串编辑距离 ≤ 2 的命中
   命名实体替换（人名/地名）后的相似度
   语言翻译版本匹配

3. 语义相似度检测：
   评测样本 embedding 与训练文档 embedding 的余弦相似度（阈值 0.8+）

4. 模型行为学检测（Zeroth-Order 污染，2024-2025）：
   不依赖训练语料全文——用模型自身行为判定：
   - 模型对评测样本的困惑度显著低于"同分布替身样本"（把数字/实体替换后的版本）
   - 正常模型对"原题"和"变体"的表现应接近；被污染的模型——原题明显更优
   优势：不需要训练数据访问权——可用于第三方审计

5. 时间戳法：训练截止日 < 评测发布日 → 天然免疫
```

### 1.3 去污染操作

```
去污染 SOP（训练团队视角）：
1. 建立评测集指纹库：
   - 全部公开基准题 → 提取 8/13-gram 哈希 + MinHash 签名 + embedding
2. 训练前过滤：
   - 语料库文档与指纹库匹配 → 命中即删除（或降权至最低）
   - LLaMA 系列公开了此流程（删除 13-gram 命中）
3. 训练中抽检：checkpoint 对指纹库重新匹配（新爬取的语料需要增量过滤）
4. 合成数据同样过滤（教师模型的输出也要过指纹库）
5. 发布前污染审计：对最终模型做 Zeroth-Order 检测 + 输出-基准重叠抽查
6. 论文报告：声明去污染流程、残留命中率、评测日期
```

**去污染的极限**：合理迁移（"会解这类题"）与背题（"记住这题"）的边界——技术上无法完全区分——这也是动态评测存在的理由。

### 1.4 动态评测（污染免疫体系）

2024-2026 年的主流做法——让评测"动起来"：

| 评测 | 动态机制 | 领域 | 备注 |
|------|---------|------|------|
| LiveBench（2024） | 每月新题（模型+人工+自动验证） | 通用 | 防爬取：题目随机排序+防抓包 |
| Humanity's Last Exam（2025） | 2500 题专家匿名命题 | 多学科 | 提交时对模型是"新"的；专家签署保密 |
| SWE-bench Verified（2024） | 人工核验 GitHub issue | 代码 | 数据天然滞后；仍被报告部分污染 |
| LiveCodeBench（2023-） | 按时间段滚动的新竞赛题 | 代码 | 官方报告了 2025 年污染导致的虚高 |
| SimpleQA（2024） | 事实性新题 | 知识 | 模型普遍 <50%——显示基准的严格性 |
| MathArena（2025） | 竞赛题时间切分 | 数学 | 分组按比赛日期防污染 |
| CommonCanary（2025） | 私有 + 分批放出 | 通用 | 工业联盟合购 |

**动态评测工程**：
- 出题流水线：LLM 生成初稿 → 自动验证（答案可判性）→ 人工专家核验 → IRT 标定难度 → 加密存储
- 评测协议：请求签名 + 防爬虫 + 结果不公开
- **IRT（项目反应理论）**：用大批模型的作答估计每题难度 b、区分度 a——筛选出"区分度好、难度适中"的题目——评估集质量可量化

## 二、BLEU/N-gram 指标的缺陷与替代

### 2.1 BLEU 的机制与缺陷

```
BLEU = BP × exp( Σ_n w_n log p_n )
p_n = 候选译文与参考译文的 n-gram 精确匹配比例（precision）
BP（短句惩罚）= exp(1 - 参考长度/候选长度)（候选过短时惩罚）

优点：与人工相关（语级）——快、免训练、可复现
```

**致命缺陷**：
```
1. 词汇僵化：只认精确 n-gram 匹配——同义词/改写全部计为错误
   "artificial intelligence" vs "AI" —— 零分
2. 无语义：两句话意思相同但用词不同 → 低分
   "猫坐在垫子上" vs "一只猫咪卧在坐垫上" → 接近零
3. 长度游戏化：可以作弊——把候选重复拼接参考中的高频 n-gram
4. 与参考数敏感：参考译文数量越多 → 分数越高（不可跨设置比较）
5. 对语序不敏感：n-gram 顺序完全错乱也可能得分
6. 对流畅度不敏感：语法不通顺但 n-gram 命中 → 高分
7. 不满足"信息论直觉"：BLEU 不是 metric 空间距离——无三角不等式
```

### 2.2 词重叠类改进

| 指标 | 机制 | 改进点 | 仍有的问题 |
|------|------|--------|-----------|
| ROUGE（2004） | n-gram 召回率（摘要任务） | 关注"内容覆盖" | 同样词汇僵化 |
| METEOR（2005） | 词干+同义词（WordNet）匹配 + 惩罚 | 缓解同义词 | 依赖词典资源 |
| chrF（2015） | 字符 n-gram F 分数 | 形态丰富语言更鲁棒 | 仍是表面匹配 |
| BLEURT（2020） | T5 预训练 + 人工评分回归 | 学到"人觉得好"的分布 | 需要训练数据、领域敏感 |

**chrF 的细节**（值得一提的实用替代）：
```
chrF = F_score(字符 n-gram 精确率、召回率，β=2 偏召回)
优点：对词形变化（morphology）鲁棒——跨语言翻译评测中——chrF 与人工相关性常优于 BLEU
```

### 2.3 Embedding 相似度类指标

**BERTScore**（Zhang et al., 2020）：
```
逐 token 匹配：候选 token 与参考 token 用上下文 embedding 的余弦相似度
P = 每个候选 token 的最佳匹配平均分（精确率）
R = 每个参考 token 的最佳匹配平均分（召回率）
F1 = 调和平均
（贪心匹配 + 可选的 IDF 加权）

关键超参：基础模型（BERT/RoBERTa）与层选择（经验：第 9-16 层最好）
```

**MoverScore**（2019）：
- 用 Word Mover's Distance 在 embedding 空间求"搬运代价"——考虑整体语义距离
- 对"改写到意思相同但用词全变"的情况更鲁棒

**局限**：BERTScore 仍是"表面相似度"——对"逻辑正确但表达完全不同的推理"无能为力——比如数学推理的等价变换。

### 2.4 学习式指标（Learned Metrics）

```
BLEURT（2020）：
- 预训练：T5 上做多种合成扰动任务（去词、翻转、语法破坏）
- 微调：人类评分（WMT 数据集）上回归
- 输出：-1~1 的分数——与人类相关性显著优于 BLEU
- 变体：BLEURT-20（2022 版——训练数据扩大 10 倍）

COMET（2021-）：跨语言翻译质量评估——QE（质量估计）模式——不需要参考译文

GEMBA/UniTE 类：基于"通用模型打分"的学习指标
```

**通用规律**：学习式指标在"分布内"强——跨领域/跨语言会漂移——评估时必须声明指标训练数据的分布。

### 2.5 LLM-as-Judge：现代事实标准

**做法**：让强 LLM（GPT-4 级）按 rubric 给输出打分或比较两个输出。

**主流协议**：
```
1. 直接打分（评分制）：1-10 分——需校准（分数分布漂移）
2. 配对比较（win-rate）：
   AlpacaEval 2 的 LC win-rate（长度控制）：限制裁判只能比较"等长"输出——消除 verbosity bias
3. 多维度 rubric：有用性/正确性/安全性分项打分（MT-Bench 风格）
4. Elo 聚合：Chatbot Arena 的众包投票 → Bradley-Terry → Elo 排名
```

**LLM-as-Judge 的六大偏差**：
```
1. 位置偏差（position bias）：偏好回答中的第一个/第二个输出 → 交换位置重测
2. 冗长偏差（verbosity bias）：更长的输出得分更高 → 长度控制（LC）或归一化
3. 自我偏好偏差（self-enhancement）：裁判偏好自己家族的模型 → 用异构裁判集
4. 奉承偏差（sycophancy bias）：裁判倾向同意用户观点 → rubric 明确禁止
5. 格式偏差：markdown/列表格式影响打分 → rubric 明确"只看内容"
6. 尺度漂移：不同批次的裁判分数尺度不同 → 配对比较优于绝对打分
```

**校准方法**：
- **对抗性校准**：在人工标注的验证集上测量裁判与人类的 Kendall τ——报告"裁判-人类一致性"
- **参考增强**（reference-guided judging）：先给裁判看参考答案（Genie 等）
- **裁判集成**：多个不同家族模型投票——分歧样本送人工
- **评估评估者**（eval the evaluator）：Prometheus 系列、JudgeLM——把裁判自身的质量当作研究问题

**工程结论**：
```
指标选择决策树（2026）：
- 需要可复现的翻译/摘要评测 → chrF / BLEURT（比 BLEU 强——但可复现性略降）
- 语义相似性评测 → BERTScore（配合人工抽检）
- 开放生成质量 → LLM-as-Judge 配对比较 + 长度控制 + 人工校准报告
- 任何关键结论 → 三管齐下：自动指标 + 人工评分 + 统计检验（见第五章）
```

## 三、Bias 量化方法

### 3.1 Bias 评估的层次

```
偏差评估谱系：
1. 词级/静态：embedding 空间的不平等（WEAT/SEAT）
2. 句子级/生成：语言模型对刻板印象句子的偏好（StereoSet/CrowS-Pairs）
3. 任务级：QA/分类任务中——不同群体输入的性能差异（BBQ）
4. 行为级/反事实：同场景交换群体属性——行为是否改变（WinoBias 等）
5. 公平性度量：分类器的群体统计均等（demographic parity/equalized odds）
```

### 3.2 WEAT/SEAT：关联测试

**WEAT**（Word Embedding Association Test, Caliskan et al., 2017）——经典心理学 IAT 的词向量版：
```
目标词集合 X（如：花的名字）
属性集合 A（如：愉悦词）、B（如：不愉悦词）

关联度量：
s(w, A, B) = mean_{a∈A} cos(w, a) - mean_{b∈B} cos(w, b)

效应量：d = [ mean_{x∈X} s(x,A,B) - mean_{y∈Y} s(y,A,B) ] / std(所有 s)
（Y = 对照组，如昆虫名）

显著性：排列检验（permutation test）——随机打乱 X∪Y 的标签——重算 d——得 p 值
```

**SEAT**（Sentence Encoder Association Test, May et al., 2019）：把词换成句子模板（"This is a flower"）——适用于句子编码器（BERT 类）。

**局限**：只测"词关联"——测不出任务行为偏差——且结果与下游行为的相关性存疑（"Does Embedding Bias Correlate With Task Bias?"——结论：弱相关）。

### 3.3 StereoSet 与 CrowS-Pairs：句子级刻板印象

**StereoSet**（Nadeem et al., 2020）：
- 17,000 条句子——11 类社会群体（性别、种族、宗教、职业……）
- 每条句子三选一：刻板印象句（stereotype）、反刻板句（anti-stereotype）、无关句（unrelated）
- 指标：
```
SS（Stereotype Score）= 模型认为刻板句最可能的比例
LM（Language Modeling Score）= 模型语言流畅性正确率
ICAT = (LM × (100 - SS)) / 100     —— 综合：流畅且不刻板 → 高
（ICAT 越低 → 偏差越大；满分 100）
```

**CrowS-Pairs**（Nangia et al., 2020）：
- 1,508 对句子：刻板句 vs 反刻板句（仅替换群体属性）
- 打分：模型给刻板句更高概率的比例（越低越好）
- 批评：句子对构造存在"刻板句更自然"的混淆——分数解读需谨慎

**共同局限**：句子级测试与真实任务偏差的相关性有限；且"概率偏好"不等于"行为歧视"。

### 3.4 BBQ：任务级偏差基准

**BBQ**（Bias Benchmark for QA, Parrish et al., 2021）——目前最常用的任务级偏差基准：
```
结构：58,000 个多选题——覆盖 11 个社会类别（性别/种族/国籍/宗教/年龄/残疾……）
每个问题两种版本：
- 模糊版本（ambiguous）：没有足够信息——正确答案应为"未知"（unknown）
- 明确版本（disambiguated）：提供了区分信息

指标：
- 准确率（Accuracy）
- 偏差分数（Bias score）：在模糊问题上——模型答非"未知"时——
  选择刻板答案的比例 vs 反刻板答案的比例差
  Bias = [P(选刻板答案) - P(选反刻板答案)]（答错时才有意义）
```

**BBQ 的关键洞察**：强模型在模糊问题上——"答非未知"本身就是一个信号——即使答对了明确问题——模糊问题上的刻板倾向依然可测。

### 3.5 反事实评估（Counterfactual Evaluation）

**核心思想**：同一个场景——只交换受保护属性（性别、种族、年龄）——观察行为变化。

```
反事实评估模板：
原句：   "一位护士正在给病人量体温。" → 生成/回答
对照句： "一位男护士正在给病人量体温。"（交换性别/加入标记）

度量：输出分布距离（KL 距离、生成内容差异率）、任务性能差、情感/主题偏移
```

**经典工具**：
- **WinoBias / WinoGender**：代词消解任务——"护士"场景中——模型把"他/她"错指给谁
- **Templar 类模板库**：自动构造群体属性交换的句子对
- **任务级反事实**：在 QA/代码/医疗建议上——把"患者性别"换掉——看建议是否变化（高风险的医疗场景——已有多篇 2024-2025 论文发现显著差异）

**反事实评估的局限**：
- 属性交换后句子的自然度不同（"男护士" vs "护士"）——混淆因素
- 表面标记（gender token）可能被模型"显式利用"——测量到的可能只是"标记关联"而非"群体偏见"

### 3.6 公平性度量（分类任务）

```
人口统计均等：P(ŷ=1 | A=a) = P(ŷ=1 | A=b)
机会均等（equalized odds, Hardt 2016）：FP 率与 FN 率在群体间相等
  要求：P(ŷ | y, A=a) = P(ŷ | y, A=b)
均衡赔率（equal opportunity）：只要求 TPR 相等
差距指标：demographic parity difference、equalized odds difference（AI Fairness 360 实现）
```

**生成模型的公平性度量仍是开放问题**——目前主流做法：生成分布上的反事实距离 + 下游任务（如简历筛选）的群体表现差。

## 四、评估集设计（Eval Set Design）

### 4.1 评估集的黄金原则

```
好的评估集 = 有效（测到目标能力）× 可靠（可复现）× 无污染 × 有区分度 × 有解释力
```

**设计流程**：
```
1. 定义能力边界：这个评估要回答什么问题？（"代码能力"太宽——要拆成：正确性/风格/鲁棒性）
2. 建立题源：真实任务（竞赛题/真实 issue/专家命题）> 合成题
3. 答案验证：每题必须可自动判定（规则/测试/人工核验）
4. 难度标定：IRT 或人工分层——避免"全体满分"或"全体零分"
5. 覆盖分析：类别 × 难度矩阵——检查盲区
6. 干扰项设计：多选题的干扰项要有迷惑性
7. 污染审计：指纹库匹配
8. 评估评估集：小样本人工抽测——确认题目没有歧义/错题
```

### 4.2 难例挖掘（Hard Example Mining）

```
难例来源：
1. 模型失败样本：跑模型 → 收集错题 → 人工确认"题没问题，模型错了"（adversarial filtering）
2. 红队测试：专门让人/模型构造"模型会犯错"的题（Red-Teaming）
3. 难度进化：Evol-Instruct 风格——从简单题逐步加约束（换数字、加条件、加多步推理）
4. 组合构造：把多个简单技能组合成新题（组合难度 > 单一难度之和）
5. 分布外采样：换领域/换语言/换格式——同一能力的不同切面

难例的筛选标准：
- 人类专家能解（有标准答案）
- 现有模型失败率 ≥ 50%（区分度）
- 不依赖世界知识的最新时点（防过期）
```

**LLM 辅助难例生成**（2025-2026 的主流）：模型生成 → 自动验证器过滤 → 人工核验——Humanity's Last Exam 与 GPQA diamond 走的都是这个路线。

### 4.3 覆盖分析（Coverage Analysis）

```
覆盖矩阵（能力 × 难度 × 领域）：
能力维度：理解/推理/生成/工具调用/多模态……
难度维度：易（80%+ 模型会）/中/难（<30% 会）
领域维度：数学/代码/科学/人文/日常……

检查方法：
1. 类别占比热力图——发现"偏科"（全是数学题 → 测不出对话能力）
2. 难度分布直方图——全难 = 无法区分中低水平模型
3. 题源重复度——同一竞赛/同一作者的题过多 → 能力采样偏差
4. 与已有基准的互补性——新基准必须覆盖已有基准的盲区（否则没价值）
```

### 4.4 干扰项设计（Distractor Design）

多选题的质量——一半取决于干扰项：

```
干扰项设计规则：
1. 长度与复杂度匹配：干扰项与正确答案长度相近——防"最短即答案"
2. 语义贴近：干扰项来自"常见错误推理"（错的推导、漏掉的步骤）——而非随机词
3. 模板法生成：把正确答案的数字/实体替换成邻域值（如 +1、×10、少一位小数）
4. 模型生成干扰项：LLM 按"学生可能怎么错"生成 → 人工挑选
5. 等概率检验：随机选择时——各选项被选概率应接近均匀（信息论熵最大）
6. 否定陷阱：包含"不是/不正确的是"的题目——干扰项设计要防倒错
```

**评估**：干扰项的好坏——用"模型作答的选项分布"检验——如果某干扰项几乎无人选——说明它太弱——该替换。

### 4.5 难度标定与 IRT

```
IRT 两参数模型（2PL）：
P(答对 | θ, a, b) = 1 / (1 + exp(-a(θ - b)))
- θ：被试能力（模型能力参数）
- a：区分度（越大——题目对能力差异越敏感）
- b：难度（θ = b 时答对率 50%）

用途：
1. 选题：a > 0.8、b 覆盖能力范围 → 评估集区分度好
2. 测试长度：评估集需要多少题才能把两个模型分开（信息函数）
3. 难度控制：动态评测中——按目标能力区间出题
4. 校准合成数据：模型生成的题目——用 IRT 参数筛选——而非只看"模型能否答对"
```

### 4.6 人类评估的设计（统计基础）

```
人工评分协议：
1. 双人独立评分 + 不一致时第三人仲裁（Cohen's κ / Krippendorff's α 报告一致性）
2. 评分者盲化（不知道模型身份）——防品牌偏见
3. 样本量：差异越小需要的样本越多（见第五章功效分析）
4. 评分锚点：给出 2-3 个参考样例（anchor）——减少评分者内部漂移
5. 顺序随机化：同一模型的前后位置交叉——防疲劳偏差
```

## 五、AI 论文中的统计显著性

### 5.1 为什么 AI 论文需要统计严谨性

- 一次评测运行（一个种子）——噪声可能大于真实差异（代码生成 pass@1 的方差很大）
- "我们比基线高 1.2 个点"——可能是运气（random seed 的差异）
- 顶尖会议中——大量结论建立在"未经验证的微小差异"上（已知的复现危机之一）

### 5.2 多次采样与方差估计

```
正确做法：
1. 多个随机种子（≥3-5 个）——报告 mean ± std
2. 温度采样多次（生成任务）：
   pass@k 场景——一次生成 k 个样本——用无偏估计：
   pass@k ≈ 1 - C(n-c, k) / C(n, k)
   （n = 采样总数，c = 通过数——Chen et al., Codex 论文的估计器）
3. 报告"分布"而不是"点值"：最好附上逐种子明细

常见错误：
✗ 只跑一个种子——选最好的结果报
✗ 多次跑——只报最好的一次（selective reporting）
✗ 不报告采样次数与温度——结果不可复现
```

### 5.3 置信区间（Bootstrap）

```
Bootstrap 流程：
1. 有样本（n 个样本的评估分数）→ 有放回重采样 B 次（B = 1000+）
2. 每次重采样计算统计量（均值/胜率/准确率）
3. 取 2.5% 与 97.5% 分位 → 95% 置信区间
4. 两个模型的 CI 不相交 → 差异显著（粗略判据）

优点：无需正态假设、适用于任何统计量（包括 win-rate）
```

**配对数据必须配对分析**：两个模型在同一批测试题上的表现——是配对样本——必须用配对差异的 CI（而不是两个独立 CI 的重叠判断）。

### 5.4 显著性检验的选择

| 场景 | 检验方法 | 说明 |
|------|---------|------|
| 分类准确率（配对，同一测试集） | McNemar 检验 | 基于不一致样本对（b、c）——卡方近似 |
| 回归/连续指标（配对） | 配对 t 检验 / Wilcoxon signed-rank | 非参数更稳（不要求正态） |
| 多个模型两两比较 | Friedman + Nemenyi post-hoc（CD 图） | 控制整体错误率 |
| 生成指标（BLEU 等） | 近似随机化检验（approximate randomization test） | 对句子级分数重排 |
| 胜率（LLM-as-Judge 配对） | 二项检验 / Bootstrap 比例 CI | 样本量小时必须报 CI |
| 多重比较 | Bonferroni / Benjamini-Hochberg（FDR） | 比较次数多时必须校正 |

**关键陷阱**：
- 把"非配对检验"用在配对数据上——高估 p 值（保守）或低估（取决于方向）——总之是错的
- 报告 p 值但不报效应量（差异大小）——"统计显著" ≠ "实际重要"——大数据集上微小差异也显著
- 事后挑选检验方法——相当于作弊

### 5.5 样本量（功效分析）

```
功效分析四要素：
- α（第一类错误率，通常 0.05）
- 功效 1-β（通常 0.8——β 为第二类错误率）
- 效应量 d（想检测的最小差异——用标准差归一化）
- 样本量 n

简单公式（配对 t 检验近似）：
n ≈ 8 / d²        （α=0.05、功效=0.8 时）
例：想检测 0.5 个标准差的差异 → n ≈ 32 个配对样本
   想检测 0.1 个标准差的差异 → n ≈ 800 个配对样本

工程启示：
- 论文声称"超越基线"——如果效应量小——需要展示功效分析或至少承认样本量不足
- 评测集多大才够？——取决于想分辨的差异大小——不是"越大越好"而是"够大才能支持结论"
```

### 5.6 可复现性的最低标准

```
评测报告检查清单（发表级）：
□ 模型版本与 checkpoint 精确标识
□ 采样配置：温度、top-p、采样数 n、种子
□ 评测集的版本与日期（评测集也会更新！）
□ 去污染声明与残留命中率
□ 指标的定义与实现版本（不同实现的 BLEU 差异可达 1-2 分）
□ 多次运行的 mean ± std（或全部数据点）
□ 关键结论的检验方法与 p 值/CI
□ 人工评估：评分者数、一致性系数、盲化协议
□ 计算资源与推理时预算（推理模型的必要信息）
```

## 六、可解释性的因果方法

### 6.1 从"相关性解释"到"因果解释"

- 相关性解释：注意力权重高 → "模型关注了这里"——**错误**——注意力不是因果（已有论文证明移除注意力头部不改变行为）
- 因果解释：**干预（intervention）**——改变模型的内部状态——观察行为是否改变——改变的 = 因果相关的

### 6.2 Activation Patching（激活修补）

**基本范式（四步）**：
```
1. 干净运行：正常前向——记录所有激活——得到正确输出（如："埃菲尔铁塔在巴黎"）
2. 损坏运行：把输入换成干扰版（"埃菲尔铁塔在罗马"？）→ 得到错误输出
3. 修补：把干净运行的某个激活（某层某 token 的隐藏状态）——替换进损坏运行的对应位置
4. 观察：如果输出恢复正确 → 该激活是"因果必需"的
   （恢复程度 = 该位置的因果重要性）

变体：
- 替换（patching）vs 抑制（ablation——清零/加噪声）
- 单点修补 → 全网络热力图（哪些 (层, token) 组合最关键）
```

**关键工具与论文**：
- **Causal Scrubbing**（Redwood, 2022）：系统地替换激活——验证电路解释——"这个电路描述能解释多少行为"
- **ACDC**（Conmy et al., 2023）：自动剪枝——只保留"修补后仍维持行为"的边——自动发现电路
- **Path Patching**（Wang et al., 2022 IOI 论文）：修补"路径"而非单点——定位"QK 回路/OV 回路/MLP 写入"

### 6.3 Causal Tracing（因果追踪）

**ROME 的工作**（Meng et al., 2020——"Locating and Editing Factual Associations in GPT"）：
```
因果追踪流程：
1. 干净运行：prompt "The Space Needle is in the city of ____" → 正确输出 "Seattle"
2. 损坏运行：subject token（"Space Needle"）的 embedding 加噪声 → 输出错误
3. 逐 (token, layer) 恢复：把干净激活放回损坏运行的对应位置
4. 绘制热力图：哪些位置能"救回"输出——发现事实主要存储在
   "subject 的最后一个 token" 的 "中后段 MLP 层"（GPT-2 XL 的第 7-12 层左右）

应用：知识编辑（ROME/MEMIT——2022/2023）——直接改写权重让模型"忘记/替换"事实
```

**局限**：ROME 的定位结论在后续研究（Hase et al., 2024）中被挑战——"定位的组件并非因果唯一"——但方法论（trace → patch → edit）至今是事实知识研究的支柱。

### 6.4 Interchange Intervention（交换干预）

**Interchange Intervention**（Geiger et al., 2020-2023——"causal abstraction analysis"）：
```
核心思想：检验"假想的高层因果模型"是否解释了网络内部机制

设定：假设模型的推理可以抽象为：概念 A 的表示 → 决定 → 概念 B
实验：
1. 运行两个输入：
   x₁ 蕴含概念 A=0，x₂ 蕴含概念 A=1（其他条件相同）
2. 干预：把 x₁ 的"概念 A 表示"（某层激活子空间）替换为 x₂ 的
3. 观察：输出是否"跟着概念变"（A=0 时是答案1，A=1 时是答案2）
4. 一致 → 该子空间"因果地编码"了概念 A

关键技巧：
- 用"分布式对齐搜索"（DAS——Geiger et al., 2023）——找到概念在隐藏空间的方向
- 线性表示假设（Park et al., 2023）：概念 = 隐藏空间中的线性方向——干预沿方向移动
```

**与激活修补的区别**：修补是"自下而上"（哪里重要）；interchange 是"自上而下"（验证我们的概念化是否正确）。

### 6.5 机械可解释性（Mechanistic Interpretability）的因果工具箱

```
完整工具箱（2024-2026）：
1. 探针（probing）：训练线性分类器读隐藏状态 → 找到概念方向（但探针≠因果——需要干预验证）
2. 激活修补 / 路径修补：电路定位（IOI 电路、间接对象识别）
3. 稀疏自编码器（SAE）：把激活分解成可解释特征（Anthropic 的字典学习——
   2023-2025 系列：单义性扩展、跳跃特征、SAE 特征与行为干预联动）
4. 因果追踪 + 知识编辑（ROME/MEMIT/REMEDI）
5. 分布干预（DAS、linear intervention）：验证线性表示假设
6. Logit Lens / Tuned Lens：逐层读出模型"在想什么"
7. 行为学对照组：同输入不同上下文 → 观察内部分表（对比激活分析）
```

**工业价值**：
- 安全：定位"欺骗电路""越狱电路的神经基础"（2024-2025 的多项研究——找攻击方向/拒绝方向）
- 调试：模型为什么答错这道题 → 定位错误信息存储位置
- 知识编辑：低成本更新事实（虽然工程上仍有争论）

### 6.6 因果可解释性的局限

```
1. 忠实性问题：电路解释是否真正"解释了"行为——Causal Scrubbing 证明的是"解释的下界"——
   无法证明"没有其他解释"
2. 规模爆炸：千亿参数模型的完整电路——无法枚举——只能抽样解释
3. 分布外失效：在对抗/新分布下——发现的电路可能不成立
4. 干预的混叠：激活替换同时改变了多个子任务——单点修补的因果归因并非唯一
5. 术语困境："因果"在这里指"干预下的行为响应"——不是结构因果模型的完整形式
```

**现实建议**：可解释性结论必须"行为验证 + 干预验证 + 多方法交叉"——单一方法（只靠探针、只靠注意力）的结论——在论文与工程决策中——应谨慎对待。

## 七、总结

```
评估与可解释性的辩证关系：
评估回答"模型能做到什么"——可解释性回答"模型为什么能/不能"

评估的四大支柱（2026）：
1. 污染免疫：指纹库 + 动态评测 + 私有评测（评估的"数据安全"）
2. 指标可信：从 n-gram 到 embedding 到 LLM-judge——始终报告人工校准
3. 偏差可见：BBQ/StereoSet/反事实——把"偏见"变成可测量、可追踪的数字
4. 统计严谨：多次采样 + CI + 配对检验 + 功效分析（评估的"证据等级"）

可解释性的因果转向：
注意力（相关）→ 探针（相关+局部）→ 修补/追踪/干预（因果）→ 电路/SAE（机制）
```

一句总结：**没有污染免疫的分数是幻觉——没有统计检验的结论是轶事——没有干预验证的解释是讲故事**。三者同时成立——评估与可解释性才真正服务于 AGI 的安全与可靠发展。
