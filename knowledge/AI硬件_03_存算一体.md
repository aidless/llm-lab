# 存算一体与近存计算：打破冯·诺伊曼瓶颈

## 1. 冯·诺伊曼瓶颈的量化分析

### 1.1 Memory Wall 的数学定义

冯·诺伊曼架构自1945年提出以来，其核心矛盾——处理器与存储器之间的性能鸿沟——随着工艺微缩的放缓而日益尖锐。这一矛盾的量化表达由 Memory Wall 概念给出：处理器性能年均增长约 50-60%，而 DRAM 访问延迟年均仅改进 7-10%，导致两者间的差距以指数级扩大 [Wulf & McKee, 1995]。若将处理器性能增长曲线与 DRAM 延迟改善曲线分别建模，可定义**内存强度 (Operational Intensity)** 为每字节数据加载所能完成的浮点运算次数（FLOPs/Byte）。Roof-line 模型使用该指标将程序性能分为 Compute-bound 与 Memory-bound 两个区域 [Williams et al., 2009]：

```
 attainable_performance = min(peak_flops, memory_bandwidth × operational_intensity)
```

对于现代深度学习工作负载，operational_intensity 通常落在 0.1-10 FLOPs/Byte 区间。以 ResNet-50 推理为例，其卷积层的 operational_intensity 约为 1-5 FLOPs/Byte，而 Transformer 类模型的 self-attention 计算受限于序列长度，往往更低。这意味着在典型 GPU 系统上，大部分时间消耗在等待数据而非实际计算上——Memory Wall 直接限制了神经网络推理和训练的性能上限。

### 1.2 能耗分布：计算 vs 数据移动

能耗分析进一步揭示了冯·诺伊曼瓶颈的物理本质。Horowitz [2014] 给出了 65nm 工艺下各类操作的典型能耗数据：

- **ALU 运算**：整数加法 ≈ 1 pJ，32-bit 整数乘法 ≈ 3 pJ
- **寄存器文件访问**：约 0.5-1 pJ
- **SRAM 缓存访问 (8KB-32KB)**：约 5-10 pJ
- **DRAM 访问 (片外)**：约 200-600 pJ（取决于 I/O 功耗密度）
- **NAND Flash 读访问**：约 10-100 fJ/bit（但延迟在 μs 级别）
- **片间互连 (off-chip link)**：约 20 pJ/bit

最关键的对比在于：**一次 32-bit 加法消耗约 1 pJ，而从片外 DRAM 读取相应操作数的能耗高出两个数量级以上。** Sze et al. [2017] 在 Eyeriss 加速器设计中量化了这一比例：数据移动（DRAM + SRAM 各级访问）占 Eyeriss 系统总能耗的 63-90%，取决于数据流映射策略。这一结论具有普适性——几乎所有现代 AI 加速器系统中，能耗的主要分量并非计算本身，而是数据的搬移。

从物理层面看，DRAM 访问的高能耗来源于几个方面：(1) DRAM 单元的电荷感应需要灵敏放大器(sense amplifier)的精密比较，每次操作需充放电 bitline 上的大电容；(2) DDR/HBM 接口的 I/O 驱动需匹配 PCB 或硅中介层的传输线阻抗；(3) 片外协议本身的编码与同步开销。相比之下，存内/近存计算的根本动机正是在于消除或极大缩短数据搬移的物理距离，从而压缩这部分能耗。

### 1.3 Roof-line 瓶颈分析的实践案例

以 NVIDIA A100 GPU（80GB HBM2e，带宽 2 TB/s，FP16 算力 312 TFLOPS）为例，Roof-line 模型的 ridge point 为 312 TFLOPS ÷ 2 TB/s ≈ 156 FLOPs/Byte。这意味着只有当 operational_intensity > 156 时，A100 才能达到满算力。而在实际 Transformer 层中（如 BERT-Large self-attention），矩阵乘法的 operational_intensity 通常为 30-100 FLOPs/Byte[^1]，远低于 ridge point，因此实际计算吞吐被内存带宽所 ceiling。这一差距正是存算/近存计算试图弥合的根本动机。

[^1]: 以 batch=1、seq_len=512、d_model=1024 的 QK^T 矩阵乘为例：总计算量 2×512×1024×512 ≈ 537M FLOPs，总数据搬运量约 2×512×1024×4×2 ≈ 8.4 MB，operational_intensity ≈ 64 FLOPs/Byte。

## 2. Processing-in-Memory（PIM / 近存计算）

### 2.1 三星 HBM-PIM

三星于 2021 年 VLSI 会议上首次公布了 HBM-PIM (Processing-in-Memory) 架构 [Lee et al., 2021]，将 16 个可编程计算单元（PCU）直接集成到 HBM2 的每个 die 中，每个 PCU 放置在 bank 附近，共享 bank group 的数据通道。关键设计决策包括：

- **PCU 微架构**：每个 PCU 包含 1 个 SIMD 矢量单元（支持 FP16/INT8）、本地寄存器文件和指令存储器，工作频率约 300 MHz。PCU 与所在 bank group 之间的数据路径仅为 1-2mm 长的片上金属线，相比于传统路径（需经过 TSV、硅中介层、GPU die 上的存储控制器）缩短了 10-100 倍物理距离。
- **数据流控制**：HBM-PIM 通过修改 DRAM 的指令集，在标准 READ/WRITE 命令之外增加了 PIM 专用的计算命令。Host 侧将 PIM 内核代码（类似轻量级 GPU kernel）加载到 PCU 的指令存储器中，随后通过 PIM 命令触发就地计算。计算结果可留在 DRAM 中供后续操作，也可通过常规 READ 路径输出。
- **性能数据**：在 GEMM（通用矩阵乘法）和 GEMV（矩阵向量乘）基准测试中，HBM-PIM 相比标准 HBM2 获得 2.5-4.5 倍的延迟降低，同时能耗降低约 60%。在推荐系统 MLP 层的端到端推理中，整体加速比约 2.1 倍 [Heo et al., 2022]。

HBM-PIM 的局限性在于：(1) PCU 必须与 3D 堆叠 DRAM 共用一个热预算和面积预算，计算能力受限于 DRAM 工艺的晶体管性能（通常落后逻辑工艺 2-3 代）；(2) 数据必须预先组织为适合 PIM 处理的连续格式，对于非规则访问模式（如 SpMM、GNN 的 gather/scatter）增益有限。

### 2.2 AxDIMM 与 SK Hynix AiM

与 HBM-PIM 面向高端 HPC/AI 训练场景不同，AxDIMM（由三星与阿里云联合开发）和 SK Hynix 的 AiM (Accelerator-in-Memory) 定位为服务器 DIMM 级别的近存计算方案。

**AxDIMM** 将 FPGA 或 ASIC 加速器放置在 DIMM 的缓冲区（buffer chip）位置，在不修改 DRAM 颗粒本身的前提下，在存储控制器的数据路径上插入计算能力。这一设计的优势在于兼容现有 DDR4/DDR5 内存模块的物理接口和协议，部署成本较低。在 AliGraph 图神经网络训练场景中，AxDIMM 针对 gather/scatter 操作实现了 2.5-3 倍的端到端加速 [Li et al., 2022]。

**SK Hynix AiM** (GDDR6-AiM) 则走了一条与 HBM-PIM 类似的路线：在 GDDR6 内存颗粒中嵌入 1024 个 bit-level 处理单元（PU），每个 PU 可在一个时钟周期内完成 16 次 FP16 MAC 操作。AiM 的峰值计算吞吐可达 1.2 TFLOPS per stack，而功耗仅增加约 5W per stack [Kim et al., 2022]。与 HBM-PIM 相比，GDDR6-AiM 的优势在于其高带宽（单颗 GDDR6 可达 64 GB/s）和更成熟的封装成本，更适用于中高端 GPU 加速卡的近存增强。

### 2.3 UPMEM 的 DRAM 内计算

法国创业公司 UPMEM 采用完全不同的技术路线：**将通用处理核心直接嵌入 DRAM 芯片的空置子字线(sub-wordline)区域**。每个 UPMEM DRAM 芯片包含 8-16 个 DPU (DRAM Processing Unit)，每个 DPU 包含一个多线程 RISC 处理器核心、24 KB 指令 SRAM 和 64 KB 工作内存。DPU 可直接操作所在 DRAM bank 内的数据，无需经过外部总线 [Devaux, 2019]。

UPMEM 的定位是**数据密集型任务卸载**(data-intensive offload)，而非 AI 专用加速。在数据库查询（如哈希连接、排序）、图分析（BFS、PageRank）、和稀疏线性代数的基准测试中，UPMEM 相比纯 CPU 方案实现了 3-10 倍的加速和 60-80% 的能效提升。但对于密集矩阵乘法等算力密集型任务，由于 DPU 运算能力有限（约 1-2 GOPS per DPU），加速效果远不如 HBM-PIM。

UPMEM 的商业化已进入第二代产品（PIM-C 架构），服务于金融风控、实时数据分析和基因组学等领域，证明了 DRAM 内计算在特定垂直场景中的可行性。

### 2.4 PIM 编程模型与现代 AI 工作负载适配性

PIM 系统面临的核心编程挑战是**异构内存层次的自适应管理**。程序必须显式管理数据在常规 DRAM 与 PIM 计算区域之间的放置、迁移和同步。学术界提出了几种解决方案：

- **PINATUBO** [Oliveira et al., 2021]：一个基于 OpenMP 的 PIM 编程框架，通过编译器指令 pragma 将指定的循环迭代卸载到 PIM 设备，自动处理数据分片和结果收集。
- **PIMFlow** [Giannoula et al., 2022]：面向数据流图的 PIM 编译器，将深度学习计算图映射到 PIM 系统中的多个内存库，利用库级并行和流水线隐藏计算与通信的延迟。

适配性分析表明，PIM 最适合**算子内并行度高、数据局部性好、访存模式规则**的 AI 计算：
- ✅ **元素级运算**（ReLU, BatchNorm, LayerNorm）：运算与数据比例低，通常被访存带宽 ceiling，PIM 可大幅减少数据移动。
- ✅ **GEMV/稀疏线性层**：权重矩阵一次加载多次重用，PIM 的 bank 级并行性能显著优于传统架构。
- ⚠️ **大型密集 GEMM**：需要跨多个 bank 和矩阵 tiles 的协同调度，通信和同步开销增加。
- ❌ **不规则访存**（GNN、Transformer 的 top-k 稀疏注意力）：PIM 在非连续访问和高随机性场景下的性能优势大幅缩水。

## 3. Compute-in-Memory（CIM / 存内计算）

### 3.1 SRAM CIM

SRAM CIM 利用 SRAM 位单元的存储节点直接参与模拟或数字运算，避免了数据从存储阵列到计算单元的搬移。这是目前产业化程度最高的 CIM 技术路线。

**6T SRAM 位单元的模拟 CIM**：标准的 6T SRAM 单元在正常读操作中，通过预充电 bitline 并检测电压降来读取存储值。在 CIM 模式下，通过对多个字线(wordline)同时激活，使对应单元的电流在位线上自然累加，实现**模拟域的多输入加法**。若输入（激活值）以脉冲宽度调制（PWM）或位串行方式施加，则可实现完整的乘累加运算。

然而，6T 单元的模拟 CIM 存在固有的精度困境：位线电压的累加是电流驱动的连续值，容易受工艺偏差(process variation)和工作环境影响。为此，**8T SRAM 单元**增加了独立的读端口（由额外的两个晶体管构成），将读路径与写路径分离，可显著提高读稳定性和线性度 [Biswas & Chandrakasan, 2018]。

**数字 CIM** 避免了模拟精度的困扰：每个 SRAM 单元在存储值的位线级完成数字布尔运算（如 AND 和 popcount），累加结果由数字加法器树完成。代表设计如清华大学的**存算一体宏架构** [Jiang et al., 2020]，在 28nm 工艺下实现了 8-bit 输入 × 8-bit 权重的 INT8 乘累加运算，能效比达 10-20 TOPS/W，远高于同等工艺下的纯数字加速器（约 1-5 TOPS/W）。

数字 CIM 的代价是面积：8T 或 10T 单元面积约为标准 6T 单元的 1.5-2 倍，且每个计算周期能够支持的乘累加密度低于模拟方案。但数字 CIM 在 -40°C 到 125°C 温度范围内能保持一致的精度，这对工业级和汽车级部署至关重要。

### 3.2 RRAM/Memristor CIM

阻变随机存取存储器（RRAM，或称忆阻器/Memristor）的 CIM 实现利用其**电阻值可连续编程**的特性，在 Crossbar 阵列中直接执行模拟矩阵乘法 [Ielmini & Wong, 2018]：

```
I_j = Σ_i (G_ij × V_i)
```

其中 G_ij 为 Crossbar 节点处 RRAM 单元的电导值（代表权重），V_i 为输入行线电压（代表激活值），I_j 为输出列线的累加电流（代表乘累加结果）。这一物理定律的直接利用使 O(N²) 次乘累加在 O(1) 时间内完成——理想的 Crossbar 阵列可在单个读周期中完成一整层矩阵乘法。

**ADC 精度与面积的权衡**是 RRAM CIM 的核心工程挑战。模拟累加电流必须经模数转换（ADC）后才能供后续数字逻辑使用，而 ADC 是 CIM 宏中面积和能耗的主要来源之一：

| ADC 精度 | 面积 (28nm) | 能耗/转换 | 可分辨权重状态数 |
|---------|------------|---------|--------------|
| 4-bit   | ~200 μm²  | ~0.5 pJ | 16 |
| 6-bit   | ~800 μm²  | ~2 pJ   | 64 |
| 8-bit   | ~3000 μm² | ~8 pJ   | 256 |

以 TSMC 28nm 工艺为基准，一个 256×256 的 RRAM Crossbar 阵列需要每列一个 ADC，即 256 个 ADC 的芯片面积（8-bit 方案约 0.77 mm²）占总宏面积的 30-50%。降低 ADC 精度至 4-5 bit 可将面积和能耗分别减少 4-8 倍，但代价是权重表示的动态范围收窄，模型推理精度下降 [Jain et al., 2020]。

Mythic 公司的 M1076 模拟 CIM 芯片[^2]采用了 4-bit RRAM 方案，在 35W TDP 内提供约 1.5 PetaOps/s (INT4) 的峰值性能，但实际部署中的等效精度相当于 INT4/INT5 量化的神经网络，对 ResNet-50 的 Top-1 准确率（ImageNet）约为 74.5%，比 FP32 基线（76.1%）低约 1.6 个百分点。

[^2]: Mythic 于 2022 年发布，2023 年因融资困难停止运营，其 IP 和团队后续被收购。这一商业结果也从侧面反映了模拟 CIM 在精度与产业化成熟度之间面临的挑战。

### 3.3 NAND Flash 中的计算：SmartSSD 与计算存储

NAND Flash 的计算能力嵌入呈现出与 DRAM 类 PIM 截然不同的权衡局面。三星 SmartSSD 和 ScaleFlux 的 CSD 系列将 FPGA 或 ASIC 加速器放置在 SSD 控制器旁，数据在从 NAND 闪存读取后、经 PCIe 返回主机之前，由就近加速器处理。

**SmartSSD** 在单个 U.2 外形中集成了 Samsung V6/V7 NAND 闪存、FPGA（Xilinx Kintex/Kria）和 DRAM 缓冲区。其优势在于能够以接近磁盘内部带宽（约 6-7 GB/s）处理数据，而无需将原始数据经过 PCIe 发送到主机 DRAM。在数据库扫描、压缩解压、KV 存储过滤等场景中延迟降低 50-70% [Jo et al., 2020]。

但 NAND Flash CIM 有两个根本限制：(1) NAND 的读延迟在 50-100 μs 级别，比 DRAM（50-100 ns）高出三个数量级，对于激活值需频繁切换的神经网络推理场景效果不佳；(2) NAND 的擦写耐久度有限（TLC NAND 约 1000-3000 P/E 周期），不适合在线权重更新或训练。因此 NAND 计算存储更适合**权重固化的推理场景**和**数据处理过滤**，而非通用 AI 加速。

## 4. 模拟计算的精度挑战

### 4.1 ADC/DAC 的能耗与速度瓶颈

模拟 CIM 的数据转换开销是学术界争论最激烈的问题之一。从能量角度看，一次 8-bit ADC 转换约需 8 pJ（28nm 工艺），而一次 8-bit 的数字 MAC 仅需约 0.5-1 pJ。Shafiee et al. [2016] 在 ISAAC 架构的能耗分析中指出，当 ADC/DAC 的开销被计入系统总功耗后，模拟 CIM 相对于纯数字加速器的能效优势从"两个数量级"缩小到约 2-5 倍。

更关键的是**速度瓶颈**：ADC 的采样率有限（高精度 ADC 通常在 GS/s 以下），限制了 Crossbar 阵列的单周期吞吐。对于一个 256×256 的模拟 CIM 宏，若列 ADC 的采样率为 1 GS/s，则每行的计算时间受限于 ADC 转换时间而非 RRAM 的开关时间——这使得 Crossbar 阵列的串行行激活成为性能路径上的关键制约。

### 4.2 精度与准确率的 Trade-off

从实际部署角度看，模拟 CIM 的精度损失取决于权重编码方式、ADC 精度和阵列非理想性三个因素的综合效应。

Reis et al. [2020] 系统评估了不同 ADC 精度对神经网络推理准确率的影响：

| 网络模型 | FP32 基线 Top-1 | 6-bit ADC Top-1 | 4-bit ADC Top-1 |
|---------|-------------|--------------|--------------|
| ResNet-34 (ImageNet) | 73.3% | 72.8% | 71.5% |
| ResNet-50 (ImageNet) | 76.1% | 75.4% | 73.9% |
| BERT-Base (SQuAD F1) | 88.5 | 87.9 | 86.2 |
| Llama-7B (量化至INT4) | 因CIM实测数据不足, 采用仿真: 6-bit ADC → 约0.8% perplexity退化 | — | — |

对于 ResNet 系列的图像分类任务，6-bit ADC 精度下准确率退化约 0.5-0.7 个百分点，在可接受范围内。但 BERT 类的语言模型精度退化更为显著（约 1.5-2.3 F1），这说明 NLP 任务对权重动态范围的敏感性高于视觉任务。

### 4.3 混合信号 vs 全数字 CIM 的争论

学术界目前分为两派：

**混合信号 CIM（模拟 MAC + 数字周边电路）** 主张利用模拟域的物理法则实现极致能效，周边辅助以数字处理逻辑。代表性工作包括前述的 ISAAC [Shafiee et al., 2016] 和 MIT 的基于 RRAM 的模拟 CIM 宏。混合信号方案的支持者认为：在先进制程（7nm 以下），模拟计算特有的线性度和噪声问题可通过电路设计技术（如差分位线、自适应参考阵列）得到控制，而在同样制程下，纯数字方案面临的漏电流和静态功耗问题更难以克服。

**全数字 CIM** 则坚持使用数字形式（如 AND + popcount + 加法树）在 SRAM 阵列内完成计算，避免 ADC/DAC 的转换开销和精度损失。清华大学的 Thinking-NPU [Yin et al., 2022] 代表了数字 CIM 路线的最新成果：在 28nm 工艺下，该设计实现了 39.4 TOPS/W（INT8）的能效——这是迄今为止公开报道的最高数字 CIM 能效数据之一，甚至超过了大多数模拟 CIM 在同等精度的表现。

这场争论本质上反映了两种设计哲学的差异：混合信号追求**峰均比(peak-to-average ratio)的极致**，全数字追求**全工况下的确定性精度**。从产业化角度看，全数字 CIM 的低精度损失和工艺兼容性更受代工厂欢迎；而从探索性研究角度看，RRAM/忆阻器的混合信号路线可能克服精度障碍后，在三维集成和能效上获得更根本的突破。

## 5. 新兴存储技术

### 5.1 STT-MRAM 的 CIM 潜力

自旋转移矩磁存储器（STT-MRAM）利用磁性隧道结（MTJ）的电阻状态来存储数据，具有非易失性、高耐久度（>10^15 次）和与逻辑工艺良好的兼容性。STT-MRAM 在芯片内可作为嵌入式非易失存储器（eMRAM）替代嵌入式 Flash/eDRAM，但其 CIM 应用潜力近年才引起重视 [Kang et al., 2017]。

STT-MRAM 的 CIM 优势在于：(1) MTJ 的电阻-电流关系在特定偏置条件下表现出可编程性，使其可实现类似 RRAM 的模拟权重存储；(2) 由于 MTJ 的非易失性，CIM 阵列在睡眠模式下可不维持供电，显著降低静态功耗——这对边缘和 IoT 场景至关重要；(3) 工艺成熟度已推进到 22nm FD-SOI 和 12nm FinFET，与逻辑工艺的集成密度正在快速提升。

然而，STT-MRAM 的隧道磁阻比（TMR）通常在 100-200% 范围，意味着区分不同电阻态的信号窗口远小于 RRAM（通常 >1000%），限制了每个 MTJ 可存储的比特数和模拟计算精度。目前 STT-MRAM CIM 的研究主要集中在 1-2 bit 权重的超低精度场景（如二值化神经网络）。

### 5.2 PCM 的模拟计算能力

相变存储器（PCM）利用硫系化合物（如 GST：Ge₂Sb₂Te₅）在晶态（低电阻）与非晶态（高电阻）之间的相变来存储数据。PCM 的中间电阻态可被部分编程，形成 4-8 个可分辨的电导级别，这使得 PCM 成为实现多比特模拟权重的有竞争力的候选材料 [Sebastian et al., 2020]。

IBM 是 PCM CIM 研究的先驱之一。在 2020 年 IEDM 会议上，IBM 展示了基于 14nm 工艺的 256×256 PCM Crossbar 阵列，在 CIFAR-10 图像分类任务上达到 92.8% 的准确率（等效于 8-bit 精度权重下的软件基线）。此外，PCM 的**累加归并(accumulation drift)**特性——即多次写入之间的电阻漂移会累计——是模拟 CIM 面临的核心物理挑战之一。IBM 开发的闭环编程(closed-loop program)技术可减轻漂移效应的影响，但对电路设计复杂度有显著增加。

### 5.3 FeFET CIM

铁电场效应晶体管（FeFET）以铁电材料（如 HfO₂ 基材料）替代传统 MOSFET 的栅介质层，通过铁电极化翻转来调控沟道电导。FeFET 在 CIM 中的独特价值在于：(1) 铁电体的非易失性极化状态可提供类似 RRAM/PCM 的可编程电阻；(2) FeFET 本质上是三端器件，可实现读/写路径分离，避免了 RRAM 和 PCM 双端器件的 sneak path 问题；(3) HfO₂ 基 FeFET 与 CMOS 前道工艺（FEOL）兼容，无需额外的材料沉积或后道工艺，制造成本最低 [Ni et al., 2019]。

Ferroelectric FET 的模拟 CIM 演示主要来自 UC Berkeley 和 NaMLab 等研究团队。在 28nm 工艺上实现的 FeFET CIM 宏，在 MNIST 手写识别任务中达到约 97.5% 的准确率（FP32 基线为 99.2%），差距约 1.7 个百分点。当前 FeFET 面临的主要挑战是铁电保持特性（retention）和循环耐久度（10^4-10^6 次）不如 STT-MRAM 和 PCM，限制了在线学习等需要频繁权重更新的场景。

## 6. 商业产品与路线图

### 6.1 三星 HBM-PIM 的商业化现状

三星 HBM-PIM 于 2021 年流片验证，2022 年正式宣布商用。然而，量产和广泛部署面临两重阻碍：第一，HBM-PIM 要求 GPU 侧具备对应的 PIM 主机接口和 Runtime 软件栈支持，目前仅三星自家的 AI 芯片（如 Mobile AP 原型）和少数客户进行了紧密集成；第二，HBM 市场规格由 JEDEC 标准化委员会定义，HBM-PIM 的计算命令目前仍是非标准扩展。截至 2025 年，HBM-PIM 的部署场景仍集中在三星内部和少数战略合作伙伴的数据中心原型中，尚未进入大规模商业化阶段。

### 6.2 创业公司 CIM 产品

- **Mythic**（美国）：Mythic M1076 模拟 AI 加速卡基于 40nm eFlash 工艺，集成 1152 个模拟 CIM 核心，标称算力 1.5 PetaOps/s（INT4），典型功耗 35W。2022 年量产后，主要面向智能摄像头、无人机和工业视觉的边缘推理部署。2023 年 Mythic 因融资困难停止运营，IP 被收购。

- **Knowm**（美国）：专注于 Thermodynamic Computing 和 RRAM CIM，其 AHaH (Anti-Hebbian and Hebbian) 计算架构采用 29 亿个 RRAM 单元构成可编程电阻阵列。Knowm 的产品定位为**片上增量学习（on-chip incremental learning）**，允许模型在部署后继续学习新样本，而非静态推理。Knowm 还开源了基于其硬件的 KDash 开发板和软件 SDK，但芯片的商用规模远小于 Mythic。

- **Witmem**（中国苏州）：苏州微度芯创（Witmem）专注于基于 28nm 的 SRAM CIM 芯片，目标场景为语音唤醒、关键字识别和传感器融合。其 WTM2101 芯片在 1.2mm² 的宏面积内实现 0.5 TOPS 的 INT8 计算，功耗仅 1.2 mW，适用于无电池（能量采集）设备。

### 6.3 台积电的 CIM 工艺节点

台积电在其 N7/N6 和 N5 工艺节点上开始提供**针对存算一体优化的存储宏单元**。2023 年 ISSCC 上，台积电联合学术界发表了基于 N7 工艺的 64Kb SRAM CIM 宏测试芯片，展示了 0.43 pJ/MAC（INT8）的超低功耗数据，同时 DNN 推理准确率与数字基线差距控制在 0.3% 以内。

台积电 CIM 工艺节点的主要特征包括：
- **专用 8T/10T 位单元库**，为 CIM 的模拟/数字多行同时访问提供高读稳定性
- **适配 ADC/DAC 的外围电路 IP** 集成在 SRAM 宏边界处
- **前道兼容性**：CIM 宏插入不影响标准逻辑库的 placement 和 routing

台积电的工艺支撑被认为是 CIM 技术走向主流的关键推动力。

## 7. 适用场景分析

### 7.1 推理加速 vs 训练的可行性

CIM 的近存/存内特性使其天然适合**推理加速**而非训练，原因有三：

1. **权重的单向性**：推理中权重矩阵是只读的，CIM 宏将权重重写一次后即可长时间复用，DRR (data read to weight rewrite ratio) 极高。训练的 forward/backward 双重过程要求频繁更新权重，而模拟 CIM 中权重的非易失性编程本身就需要数十纳秒到微秒级（RRAM 写需约 10-100 ns，PCM 写约 100-500 ns），这比 SRAM/registers 的写操作（<1 ns）慢 1-3 个数量级。

2. **梯度更新的精度需求**：训练过程中梯度通常以 FP16/BF16 精度保存和计算，梯度更新累积误差的敏感度高。模拟 CIM 在 8-bit 以下的精度退化在训练场景中会快速放大为收敛失败或模型质量严重下降。

3. **可编程性要求**：训练需要频繁修改计算图拓扑（如动态学习率调整、梯度裁剪），而大多数 CIM 架构的计算图是静态映射到 Crossbar 阵列的。

因此，学术界和产业界的主流共识是：**CIM 在近期定位为推理加速引擎，训练的迭代训练仍需依赖传统数字加速器**。混合方案（如训练在 GPU/GPU 集群完成，量化后部署到 CIM 推理芯片）是目前最务实的工程路径。

### 7.2 边缘设备的 CIM 优势

CIM 在边缘场景（IoT、可穿戴设备、终端 AI）中展现出比云侧更显著的竞争力：

- **能耗优势的绝对性**：边缘设备的电池容量通常在 100-5000 mAh 范围，CIM 芯片的 μW/mW 级功耗使持续在线 AI 推理在功耗预算内成为可能。以 WTM2101 为例，在 1.2 mW 下持续运行语音识别，可用纽扣电池（如 CR2032, 225 mAh）运行约 150 小时。
- **数据搬运能耗的占比更大**：在边缘设备中，DRAM 访问占系统总能耗的比例往往比服务器端更高（60-80%），因为边缘 SoC 的缓存层次较浅且 DRAM 带宽较窄。CIM 消除数据搬运后获得的能耗收益因而更加显著。
- **成本结构的特殊适配**：边缘设备不需要复杂的训练可编程性和通用性，使用 CIM 硬连线加速器处理固定推理任务（人脸检测、关键词识别、人体姿态估计）的成本最优。

### 7.3 大模型时代 CIM 的架构价值

大语言模型（LLM）和大视觉模型参数量的指数级增长——从 GPT-3（175B）到 GPT-4（~1.8T）——对 Memory Wall 的压力达到了前所未有的高度。以 Llama-2-70B 推理为例，单次 forward 需要加载约 140 GB 的参数（FP16 下），即使使用 HBM3（带宽约 3.2 TB/s），参数加载的理论最小延迟约 44 ms——这还没算入 KV cache 访问和算子执行的时间。

CIM 在大模型场景中存在独特的架构价值：

1. **权重驻留（Weight Stationarity）**：若将 LLM 的权重矩阵映射到 Crossbar 阵列中，权重物理驻留在计算单元内，**单 Token 生成的计算不再受限于 HBM 带宽**。一个 CIM 宏的等效"带宽"由阵列的模拟计算吞吐决定，而非外部接口。

2. **KV Cache 的近存优化**：LLM 的自回归生成中，KV cache 的读取是 Memory-bound 瓶颈的核心。将 KV cache 驻留在近存计算引擎（如 HBM-PIM）的 DRAM bank 内，可避免每一步生成都从远程 DRAM 读取完整的 KV cache。

3. **Attention 的定制化 CIM 映射**：自注意力运算中 QK^T 矩阵乘和 PV 加权和的操作模式完全不同。前者计算量密集（适合 SRAM 数字 CIM），后者是数据搬运密集（适合 HBM-PIM）。

然而，现有 SRAM CIM 宏的容量上限（通常在 64-512 Kb 级别）远不满足 LLM 权重的需求（数十到数百 GB）。**跨多个宏的权重重分布和数据分区**、**三维堆叠 CIM**、以及**多芯片互连**是 CIM 走向大模型部署必须攻克的可扩展性难题。

## 8. 结论与展望

存算一体技术正处于从学术探索向混合产业部署过渡的关键阶段。HBM-PIM 和 GDDR-AiM 为代表的近存路线在数据中心场景已逐步得到部署验证，SRAM 数字 CIM 在边缘端开始商业化落地（以 Witmem、Mythic 为代表），而新型非易失存储（RRAM、PCM、FeFET）的模拟 CIM 仍在精度-面积-能效的三元权衡中寻找最优工程解。

从十年尺度看，CIM 和 PIM 并非要"取代"冯·诺伊曼架构，而是在其外延不断扩展的计算生态中，为特定瓶颈场景提供高能效的通路。**最可能的主导模式是异构动态调度**：计算密集的算子由传统加速器执行，数据搬运密集的算子由 CIM/PIM 处理，而编译器/运行时系统自动将计算图分区映射到最合适的器件——这一愿景的实现需要存储工艺、计算架构和编译后端的协同演进。
