# AGI 数据工程（扩展）

---

## 总览：数据是AGI的第二定律

模型参数决定"上限"——数据决定"能不能到达"。扩展定律（Scaling Law）告诉我们——loss 与数据量 D 之间——存在幂律关系——但真实训练中——决定成败的往往不是"有多少数据"——而是"数据是什么"。

本扩展文档——是核心系列"AGI 深挖"的数据工程伴侣——覆盖五个实战主题：数据配比优化、去重的高级语法、合成数据质量、版权与合规工程、数据飞轮与评测污染防护。

```
原始语料 ──→ 清洗与过滤 ──→ 去重（精确/近邻/语义/跨模态）
                  │
                  ↓
           质量分级与打分 ←── 小模型分类器 / 困惑度 / 人工标注
                  │
                  ↓
         数据配比（domain mixing） ←── 小规模代理实验（RegMix/DoReMi）
                  │
                  ↓
         合成数据补充（蒸馏/自生成） ←── 质量门控与配方管理
                  │
                  ↓
         tokenize → 训练 → 数据飞轮（部署反馈回流）
                  │
                  ↓
        版权合规审计（opt-out / 许可） + 评测集污染防护（去污染/动态评测）
```

关键直觉：**数据配比 ≈ 营养配方**——同样的热量（token 数）——不同的营养结构（领域比例）——产出完全不同的模型。

## 一、数据配比优化（Data Mixing）

### 1.1 为什么配比如此重要

Hoffmann 等人的 Chinchilla 定律——给出的是"总量"最优——D ≈ 20N（每参数约 20 个 token）——但它没有回答"这 20 个 token 里——该有多少代码、多少中文、多少数学"。

**核心公式**（Chinchilla 损失分解）：
```
L(N, D) = E + A / N^α + B / D^β
```
- L = 交叉熵损失
- N = 参数数量
- D = 训练 token 数
- E = 不可约熵（数据本身的"噪音底"）
- A、B、α、β = 拟合常数（约 α≈0.34、β≈0.28）

**实践要点**：
- Chinchilla 最优——在"预算固定"时成立；实际训练中——许多模型为了"少用数据"而过度训练（如 LLaMA-1 用 1.4T token 训 65B——约 21.5 倍于 Chinchilla 推荐的 1.4T/65B×20≈1.3T——正好接近）
- 数据配比问题：给定总预算 D——如何分配 D = Σ_d D_d（d 遍历领域）——使得下游任务损失最小

### 1.2 跨领域配比实验——工业界的经验法则

**LLaMA 系列**（Meta）：
- LLaMA-1：67% 英文网页（C4/CommonCrawl 过滤版）、15% 其他语言（维基等）、4.5% 代码（GitHub）、4.5% 书籍、2.5% 科学论文（ArXiv）、2% 其他
- LLaMA-2：总量提到 2T——把代码和书籍占比上调——因为代码数据对推理能力贡献显著
- LLaMA-3：15T token——做了大量配比消融——关键发现：**代码与数学数据"用不完"**——从 5% 加到 25% 仍有增益；多语言数据需要"合成翻译"来补足——因为天然高质量非英语数据不足

**DeepSeek 系列**：
- DeepSeek-V2：8.1T token——其中 87% 中文、13% 英文（当时的中英混合偏好）；到了 V3 调整为更均衡的多语言
- 经验：中文语料"量多质杂"——必须强化去重与质量过滤——否则中文占比高反而拖累英文能力

**通用经验法则**（截至 2026 年中期）：
1. **代码与数学是"放大器"**：小配比（3-8%）能带来显著的推理提升——因为结构化、可验证
2. **多语言配比遵循"平方根法则"**：低资源语言的占比——通常按其天然语料量的平方根上采样（如 LLaMA-3 对非英语数据 6 倍上采样）
3. **书籍与长文档**：占比 2-5% 即可——提供长程依赖与写作风格——但收益递减快
4. **重复数据比"脏数据"更危险**：配比优化前——必须做高质量去重（见第二章）

### 1.3 配比的科学化：从手工到优化

**DoReMi**（Xie et al., 2023）：
- 用"群体 DRO（分布鲁棒优化）"——训练一个小代理模型——自动学习领域权重——使最差领域的损失也下降
- 流程：先均匀训练一个参考模型 → 再用 DRO 更新权重 → 得到配比 α_d

**RegMix / Data Mixing Laws**（Ye et al., 2024）：
- 观察：领域配比 α 与最终 loss 之间——存在可预测的关系（近似线性/对数线性）
- 做法：跑 20-50 个小规模代理实验（同配比、小模型、短训练）→ 用回归模型拟合 loss(α) → 在拟合曲面上选最优配比——"预测模型性能来选择配比"
- 结果：配比选择能把下游平均性能提升数个点——且成本仅为完整训练的 1%

**DSIR**（Importance Resampling）：
```
目标分布 p_target（少量高质量种子样本）
备选池 p_raw（海量网络数据）

权重 w(x) = p_target(x) / p_raw(x)   （用 n-gram 特征估计）
采样：按 w(x) 加权随机采样
```
- 与配比的关系：配比是"领域级"的粗粒度调节；DSIR 是"样本级"的细粒度重采样——两者可叠加

**Gradient-based / Influence-based 方法**：
- 计算每个领域梯度与目标领域梯度的余弦相似度——选择正相关领域
- 成本高（需要反向传播）——多用于 SFT 数据筛选（如 DataComp、D4）

### 1.4 数据受限的扩展：重复 epoch 的数学

Muennighoff et al.（2023）——"数据受限语言模型扩展"：
```
重复数据 1 epoch ≈ 新数据 3 个 epoch 的收益  （经验关系）
约 4 epoch 后——收益几乎归零
```
**核心公式**（重复数据的有用性衰减）：
```
ΔL(重复) ≈ (1 - 0.14 × E) × ΔL(新数据)    （E = 重复 epoch 数，近似拟合）
```
**实践含义**：
- 不要为了"省数据"把同一份高质量语料翻来覆去用超过 3-4 次
- 合成数据可以"无限生成"——但同样受"多样性饱和"限制——这就是合成数据需要质量门控的原因（第三章）

### 1.5 配比实验的操作细节

```
配比实验 SOP：
1. 固定：模型架构（≈1B 参数）、训练步数、学习率、batch size
2. 变量：一个配比向量 α = (α_web, α_code, α_math, α_multilingual, α_book, ...)
3. 代理实验数：30-60 组（每组 ≤ 5B token）
4. 观测：预训练 loss + 一组"冻结评测集"（不参与训练、不参与调参）
5. 回归：loss_i = f(α_i) → 选出使加权下游分数最高的 α*
6. 放大验证：把 α* 用于大规模训练——确认代理实验结论不反转
```

**常见坑**：
- 用"训练集上的 loss"选配比 → 必然过拟合到噪声领域
- 代理模型太小（<100M）→ 配比结论不迁移
- 评测集与训练数据重叠 → 配比"最优解"其实是"作弊解"

## 二、去重的高级语法（Deduplication）

### 2.1 为什么去重是数据工程的"第一性原理"

重复数据——会成倍地"过度放大"某些模式——导致：
- 记忆化（memorization）——模型背诵训练样本——在版权与隐私上危险
- 训练效率下降——同一梯度反复出现
- 配比失真——某领域实际 token 数被重复数据虚增

**精确去重**：对全文做哈希（md5/sha1）——仅删除完全相同的文档——这是"最低要求"——远远不够——因为网络爬虫产生的重复大多是"近似重复"（加了一行广告、换了链接、模板页）。

### 2.2 MinHash 与 LSH：近邻去重的工业标准

**原理**（Charikar 的 MinHash 思想——Broder 应用于文档）：
```
文档 → tokenize（5-gram 或 13-gram）→ shingles 集合 S
对 S 中的每个元素 e：h(e) = 哈希函数
MinHash 签名：mh(S) = min_{e∈S} h(e)   （重复 k 次不同哈希 → k 维签名）

Jaccard(S1, S2) ≈ P[mh(S1) == mh(S2)]   （MinHash 的核心性质）
```

**LSH banding 技巧**——避免 O(n²) 两两比较：
```
签名矩阵分成 b 个 band，每 band r 行
若两个文档在某一个 band 内 r 个签名完全相同 → 候选对（candidate）
参数：b、r 决定相似度阈值 s ≈ (1/b)^(1/r)

例：b=10, r=5 → 阈值 ≈ 0.63；b=20, r=4 → 阈值 ≈ 0.47
```

**工业实现细节**（LLaMA-2 的实践——开源可复现）：
- token 化：取 5-gram（字符级）——比词级更抗变形
- 哈希：xxhash 或 md5 取 64 位
- 签名：128 个 MinHash 值——每个取 64 位中的低 32 位
- 分桶：b=20 个 band × r=4 行——在两两候选对上验证精确 Jaccard
- 阈值：Jaccard > 0.8 判定为近邻重复——删除保留一份

**MinHash 变体**：
- **加权 MinHash**（WMH）：给不同 shingle 加权（如 IDF 权重）——对常见短语降权
- **SuperMinHash**：更紧凑的签名——同等精度下减少 30% 存储
- **OddSketch**：用奇数计数器的组合哈希——对"部分重复"更鲁棒
- **SimHash**：超平面随机投影 + 汉明距离——适合"全网页去重"的海量场景（Google 经典方案）——但召回不如 MinHash

### 2.3 语义去重：SemDeDup 与质量聚类

近邻去重只能抓"措辞级"重复——抓不住"语义级"重复（同一篇文章被改写、同源新闻的不同报道）。Abbas et al.（2023）的 SemDeDup——用模型表示做语义去重：

```
SemDeDup 流程：
1. 用一个小模型（如 BERT 或数据引擎的 embedding 模型）——给每篇文档算向量
2. 对向量做 k-means 聚类（k 取几十万到百万级）
3. 每个簇内——按两两余弦相似度建图——删掉与"代表点"相似度 > τ 的文档
4. 保留簇内"代表性"文档（多样性保持：保留离中心远的、保簇覆盖）
```

**关键参数与经验**：
- embedding 维度 768 足够；聚类数 k ≈ 文档数的 1/2000
- 相似度阈值 τ：0.7-0.9 之间；τ 太低删除过多多样性
- **重要发现**：语义去重比近邻去重"多删约 30% 的冗余"——且在去重数据上训练的模型——每 epoch 的困惑度下降更快

**扩展：质量聚类（Quality Clusters）**——Meta 在 LLaMA-3 中采用：
- 对文本聚类 → 每个簇打质量分 → 簇内按质量过滤——而不是按相似度
- 好处：同一语义簇里既有高质量又有低质量样本——直接按质量保留——比"只留代表点"更优

### 2.4 跨模态去重

多模态数据（图像-文本对、视频-字幕）的去重——比纯文本复杂得多：

**图像侧**：
- 感知哈希（pHash/dHash）——抓像素级重复
- CLIP/DINO 特征做近邻搜索——抓语义级重复（同一照片的不同压缩、不同裁剪）
- **跨模态键**：用文本 + 图像特征联合构建签名——防止"同一张图配了 100 个不同 caption"的隐形重复

**文本-图像对去重（LAION 的实践）**：
- 图像特征用 CLIP ViT-L/14——文本用 CLIP 文本编码器
- 文本去重（MinHash）后再对"相似文本对应的图像"做 pHash 去重
- 实测：CLIP 去重能删掉约 10-15% 的重复对——显著改善下游图像生成质量

**视频数据**：抽帧 → 帧级 pHash → 跨帧匹配去重——同时用 ASR 文本做 MinHash——两种键交叉验证

### 2.5 去重的工程架构

```
海量去重流水线（分布式）：
┌──────────────────────────────────────────────┐
│ 1. 分片（shard by hash）→ 每台机器独立处理     │
│ 2. 精确去重：布隆过滤器（n-gram 级）先行        │
│ 3. MinHash 签名生成（并行）                    │
│ 4. LSH banding → 候选对生成（MapReduce 风格）  │
│ 5. 候选对精确 Jaccard 验证                     │
│ 6. 图连通分量（并查集）→ 每簇保留一个           │
│ 7. 语义层：embedding → 聚类 → 簇内过滤          │
└──────────────────────────────────────────────┘
```

**记忆化防护**：即使去重——也要在数据管线里标记"重复度低/中/高"——对高重复度样本（如经典代码片段）——可在训练时降采样——防止记忆化带来的隐私与版权风险。

## 三、合成数据质量（Synthetic Data）

### 3.1 为什么要合成数据

天然数据有三个硬约束：
1. **质量分布不均**：互联网上"教科书级"数据占比极低
2. **长尾覆盖不足**：罕见语言、罕见领域、罕见推理模式
3. **规模天花板**：LLaMA-3 已经用掉 15T token——优质天然语料接近枯竭

**关键事实**（截至 2026 年中期）：**前沿模型的训练数据中——合成数据占比已达到 50-90%**——且合成数据对"推理、代码、数学、指令遵循"的贡献已超过天然数据。

### 3.2 自生成数据（Self-Generation）

**Self-Instruct**（Wang et al., 2022）——合成指令数据的鼻祖：
```
1. 种子任务池（175 个手工指令）
2. 每轮采样种子 → 让模型生成新的指令（few-shot 引导）
3. 为指令生成输入/输出（输入优先——防止指令-输出模式塌缩）
4. 过滤：指令与已有池的 ROUGE 相似度过高 → 丢弃
5. 迭代 8 轮 → 约 52k 条
```

**Evol-Instruct**（WizardLM）——指令进化：
```
三种进化算子：
- 深入化（in-depth）：加约束、加步骤、加难度
- 广度化（in-breadth）：换主题、换场景
- 具体化（in-variable）：代入具体数字/实体
逐轮进化 → 指令难度单调上升
```

**Magpie 方法**（2024）：让 Llama-3 类模型"自己问自己"——利用对话模板的格式偏差（format bias）——从预训练模型的续写行为中"无监督地"提取出高质量的 user 指令——一次采样即可获得百万级指令——比 Self-Instruct 便宜一个数量级。

### 3.3 蒸馏数据（Distillation）

**定义**：用强模型（teacher）的输出——去训练弱模型（student）——输出包括：答案、推理链（CoT）、解释、反思。

**代表性实践**：
- **phi 系列**（Microsoft）：只用"教科书级"数据——其中合成数据扮演核心——主题先由模型生成——再用人工/模型过滤保证"教科书感"
- **Orca 系列**：用 GPT-4 生成带"逐步解释"的答案——"解释性调优"（explanation tuning）——比仅给答案的学生模型强 15-20%
- **DeepSeek-R1 的蒸馏**：R1 生成 80 万条带推理链的样本 → 蒸馏给 Qwen/Llama 系列小模型——小模型在数学/代码上大幅提升——且成本远低于自己跑 RL
- **Gemma 系列**：Google 用 Gemma 2 26B 作为 teacher 蒸馏——合成数据 + 知识蒸馏（KD）联合

**蒸馏数据的关键风险——"教师幻觉传染"**：
- 学生模型会继承教师的错误模式（幻觉、过度自信）
- 缓解：对教师输出做正确性验证（RLVR 式可验证任务）、多教师投票、置信度过滤

### 3.4 质量分级筛选（Quality Filtering）

合成数据"管够"之后——瓶颈从"量"变成"质"。工业级筛选栈：

**1. 规则/启发式层**：
- 长度过滤（过长过短都删）
- 语言识别（fastText lid.176——或更现代的 NLLB 分类器）
- 格式校验（代码能否编译、JSON 能否解析）
- 有害内容过滤（关键词 + 分类器）

**2. 困惑度/模型打分层**：
```
方法：训练一个"高质量分类器"（如 DistilBERT 在人工标注的高/低质量数据上训练）
或：用目标模型的困惑度（perplexity）分布——取中位数区间
经验：困惑度"过低"（近似重复/记忆）与"过高"（噪声）都应删除
```

**3. 质量分布对齐（Quality Scoring）**：
- OpenAI 用 GPT-4 作为"质量判别器"对合成数据打分——保留分数前 20-50%
- 更细粒度：按任务类型（数学/代码/写作/对话）分别打分——因为"对话质量"和"代码质量"不是同一个概念
- **难度分层**：保留一定比例的"中等难度"样本——全部高难会导致分布偏移

**4. 多样性控制**：
- embedding 聚类 + 每簇限额采样（保证指令覆盖）
- **组采样**：对同簇样本设置上限——防止合成数据塌缩成少数模式

### 3.5 SFT 数据配方（Recipe）

SFT 阶段——数据量远小于预训练（通常 10k-1M 条）——但配方直接影响对齐质量：

**LIMA 的启示**（Zhou et al., 2023）：1,000 条精心筛选的数据——就能达到大幅对齐效果——"对齐是肤浅的"（alignment is superficial）——能力主要来自预训练。

**工业级 SFT 配方结构**：
```
配方 = 多个数据源的加权混合：

1. 指令数据（self-instruct / 人工标注）—— 40-60%
2. 代码数据（代码+自然语言混合，含注释补全、bug 修复、解释）—— 15-25%
3. 推理数据（数学+逻辑+CoT，含可验证答案）—— 10-20%
4. 对话/多轮数据（真实对话 + 合成多轮）—— 5-15%
5. 安全/拒答数据（对齐红线）—— 1-5%
6. 多语言数据—— 5-15%（按目标语言分布）
```

**配方的关键调参维度**：
- **重复轮数**：指令数据通常重复 3-10 轮（SFT 数据少——可重复）
- **难度混排**：从易到难排序（curriculum）或随机混排——两派都有支持
- **平衡"有用"与"无害"**：完全拒答会伤害有用性——需要精细比例

**高质量合成 SFT 数据的"黄金标准"**（Nemotron-4 的 98% 合成管线、UltraChat、OpenAssistant）：
```
人工/强模型标注 → 种子池
→ 多样化扩展（改写、翻译、难度进化）
→ 质量门控（打分模型 + 人工抽检）
→ 去重（指令级 MinHash + 语义去重）
→ 难度/类型覆盖分析（缺口补齐）
→ 配方 → 训练 → 用"留出集"（held-out）验证配方的有效性
```

## 四、数据版权与合规工程

### 4.1 法律与监管背景（截至 2026 年中期）

- **美国**：多起版权诉讼（纽约时报诉 OpenAI/Microsoft、Getty 诉 Stability 等）——2025-2026 年间有部分案件和解或部分驳回——但"训练数据是否构成合理使用"仍是悬而未决的问题
- **欧盟 AI 法案（2024 年 8 月生效、分阶段实施）**：第 10 条要求基础模型提供者制定训练数据治理政策——包括版权政策、数据来源说明（摘要公开）、以及训练数据文本的机器可读摘要
- **中国《生成式人工智能服务管理暂行办法》**：要求使用合法来源数据——不得侵犯知识产权
- **日本**：文化厅立场——训练使用原则上无需许可——但需尊重权利人声明
- **结论**：合规工程 = 流程 + 记录 + 技术工具——而不只是"法律咨询"

### 4.2 Opt-out 机制工程

**主流 opt-out 通道**（截至 2026 年）：
1. **robots.txt**：爬虫协议中声明 `Disallow: /` 的站点——不应被纳入训练爬虫——实践中大型爬虫（如 Common Crawl、OpenAI、Google）均部分遵守
2. **x-robots-tag / meta robots**：HTTP 响应头或 HTML meta——支持 `noai`、`noimageai` 等扩展值——2024-2025 年间成为事实标准
3. **Spawning AI 的 DoNotTrain 注册表**：作品级（按 URL/艺术家/作品）的 opt-out——被多家公司（Stability、EleutherAI 等）订阅
4. **Cloudflare 的 Block AI 爬虫**（2025 年）：一键阻止 AI 爬虫——大幅改变可爬取语料的构成
5. **平台级 opt-out**：Reddit 等平台与模型公司直接签约授权——绕过爬虫

**工程要点**：
```
opt-out 合规流水线：
1. 训练前：抓取 robots.txt + DoNotTrain 清单 + 平台授权清单
2. 构建"排除集合"（URL 模式 / 域名 / 作品 ID）
3. 数据管线中：URL 过滤 → 内容指纹匹配（哈希 + MinHash）→ 双重校验
4. 训练后：留存"来源日志"（每条训练样本可追溯来源与授权状态）
5. 定期更新：opt-out 是动态的——需要增量同步
```

### 4.3 许可管理（License Management）

**训练数据常用许可证谱系**：
- **公共领域**：CC0、公有领域（美国联邦政府作品等）——最安全
- **宽松许可**：MIT、Apache-2.0、BSD——允许任意使用——但需注意版权声明保留义务
- **CC BY**：需要署名——实践中常通过"作者清单"满足
- **CC BY-NC**：非商用——商用模型不可用
- **CC BY-SA**：相同方式共享——传染性——与商业模型冲突
- **代码类**：GPL/AGPL 传染性——许多公司明确从训练集中排除 GPL 代码（微软曾为此调整 GitHub 数据使用）
- **专门训练许可**：OpenRAIL（BigScience）、CC-BY-NC-4.0 的模型权重许可——以及 2024-2025 年出现的"AI 训练专用许可"（如 Spawning 的 Source 协议）

**工程实现**：
```
许可证元数据管理：
- 数据带"来源三元组"：(来源URL, 抓取时间, 许可证)
- 许可证归一化（SPDX 标识符）存入数据目录（manifest）
- 训练配置按"许可白名单"过滤
- 发布时：生成训练数据的许可证报告（对应 EU AI 法案的机器可读摘要）
```

### 4.4 记忆化、去重与版权风险的交叉

**记忆化（Memorization）**：模型能逐字复现训练数据——是版权风险的技术根源。

**缓解技术**：
- 去重降低记忆化（第二章）
- 重复数据降采样（对高重复度样本降权）
- **差分隐私式微调**（DP-SGD）——代价是精度损失——工业界很少用
- **机器遗忘（Machine Unlearning）**：训练后删除特定数据的影响——2024-2026 年热度上升——但"删除权"（欧盟 GDPR 第 17 条、美国各州法案）在生成模型上仍未形成可靠技术标准
- **对齐式抑制**：RLHF 中注入"不要复述长文本"的偏好——软性缓解

### 4.5 合规工程的组织形态

```
数据合规角色与流程：
- 数据律师（评估来源与许可证）
- 数据治理团队（登记表：数据源→许可→用途→责任人）
- 工程团队（opt-out 同步、指纹匹配、来源日志）
- 审计流程（季度审查：新增数据源、opt-out 变更、诉讼动向）
- 突发响应（收到删除请求 → 评估 → 技术缓解 + 记录）
```

## 五、数据飞轮与评测集污染防护

### 5.1 数据飞轮（Data Flywheel）

**定义**：部署 → 用户反馈 → 数据回流 → 再训练 → 更好模型 → 更多部署——的正反馈循环。

**真实世界中的飞轮结构**：
```
用户交互（对话/生成/评分/隐式反馈）
        │
        ↓
反馈信号提取：
- 显式：点赞/踩、复制行为、人工标注、审核流
- 隐式：重试次数、编辑距离、是否采纳（代码）、会话终止模式
- 自动：任务完成信号（代码编译、数学判对、工具调用成功）
        │
        ↓
筛选与清洗 → 质量门控（打分模型）→ 去重（含与历史数据的交叉去重）
        │
        ↓
分配：预训练增量 / SFT 数据集 / 奖励模型（RM）偏好对 / RL 在线奖励
        │
        ↓
再训练 → 部署（循环）
```

**关键工程点**：
1. **反馈延迟管理**：在线 RL 需要"即时奖励"——人工反馈有小时-天级延迟——用"延迟反馈缓存 + 批量回放"解决
2. **分布漂移监测**：生产流量分布与训练分布偏离时——飞轮数据会引入偏差——需要监控 embedding 距离
3. **反馈被操纵风险**：用户恶意刷反馈（如推广自己的网站）——需要异常检测与人工抽检
4. **飞轮的冷启动**：没有部署流量时——用"红队 + 内部试玩 + 公开评测基准"代替

### 5.2 评测集污染：定义与检测

**污染（Contamination）**——评测样本或其变体出现在训练数据中——导致评测分数虚高——"模型在背题而不是做题"。

**检测方法谱系**：
```
1. n-gram 重叠检测（最常用）：
   评测样本与训练数据求最大 n-gram 连续重叠（8-13 gram）
   超过阈值 → 判定污染 → 从训练数据删除

2. 困惑度对比法：
   模型对评测样本的困惑度显著低于"同分布随机样本"
   （Zeroth-Order 污染检测：用模型本身的语言建模行为判定——不需要训练数据全文）

3. 时间戳法：发布日晚于训练截止日的评测 → 天然无污染

4. 变体模糊匹配：语义改写、数字替换、语言翻译后的污染——需要 embedding 相似度
```

**实例数据**：
- GPT-3 论文：对基准测试做 8-gram 重叠过滤——删除了 2.5%-15% 不等的测试样本
- LLaMA 系列：公开了过滤流程——从训练语料中移除与评测集 13-gram 重叠的样本
- 多项 2023-2025 研究：主流模型在多个公开基准上——因污染原因——分数显著虚高（如部分 C++ 代码基准、StackExchange 类问答）

### 5.3 去污染方法

```
去污染操作顺序：
1. 建立"评测集指纹库"：所有内部评测的哈希 + MinHash 签名 + embedding
2. 训练前：指纹库与语料库匹配 → 删除命中样本（或降权到最低优先级）
3. 训练中监控：每个 checkpoint 对指纹库抽检——发现泄漏立即溯源
4. 发布前：对最终模型的输出做"污染审计"（抽查输出与评测集的重叠度）
```

**难点**：
- 评测集内部也不断更新（新题注入）——指纹库需增量维护
- "合理引用"与"污染"的边界：模型学会"如何解这类题"是能力——逐字背题才是污染——去污染无法区分两者——只能靠"变体检测"缓解

### 5.4 动态评测与污染免疫

**动态评测（Dynamic Evaluation）**是 2024-2026 年的主流趋势：

| 评测 | 动态机制 | 特点 |
|------|---------|------|
| LiveBench（2024） | 每月发布新题（社区贡献 + 自动生成） | 数学/代码/推理全覆盖，开放榜单 |
| SimpleQA（2024） | 静态但"后训练"发布 | 测事实性（GPT-4 系 ~50% 以下）——污染难防但基准新 |
| SWE-bench Verified（2024） | 人工核验的 GitHub issue | 真实软件工程任务——数据天然滞后于训练 |
| LiveCodeBench（2023-） | 按时间段滚动出题 | 代码生成——报告 2025 年污染导致虚高分数 |
| Humanity's Last Exam（2025） | 2500 题专家命题（匿名+防搜） | 多学科难题——发布时对模型是新的 |
| MathArena（2025） | 按比赛/时间切分的新题 | 数学竞赛题滚动加入 |
| CommonCanary（2025） | 完全私有 + 逐步放出 | 工业界合购的防污染评测 |

**动态评测的工程化**：
- 出题流水线：LLM 生成初稿 → 专家/自动验证（答案可验证性）→ 难度标定（IRT 模型）→ 发布
- **IRT（项目反应理论）校准**：用模型的作答数据估计题目难度与区分度——保证评测集难度分布可控
- 私有评测：不与任何第三方共享——只在发布前一次性使用

### 5.5 评测治理的元原则

```
评测治理清单：
1. 评测集与训练数据"隔离"——物理隔离（不同仓库/权限）+ 指纹隔离
2. 训练团队与评测团队分离——评测集不让训练组接触（"blind eval"）
3. 每轮训练前重新做污染审计——包括合成数据（合成数据也会"背题"——因为教师模型见过评测集）
4. 报告污染风险等级——论文中声明去污染流程与残留风险
5. 以"动态评测 + 私有评测 + 人工评测"三支柱替代单一静态基准
```

## 六、总结

```
数据配比  → 决定"能力结构"——用代理实验科学选择
去重      → 决定"数据纯度"——近邻（MinHash/LSH）+ 语义（SemDeDup）+ 跨模态
合成数据  → 决定"上限突破"——自生成/蒸馏/质量门控/配方管理
合规工程  → 决定"可发布性"——opt-out、许可、来源日志、机器遗忘
数据飞轮  → 决定"进化速度"——反馈回流、漂移监测、防操纵
污染防护  → 决定"评测可信度"——指纹库、去污染、动态评测、IRR/IRT
```

数据工程的核心矛盾——始终是"规模、质量、多样性、合规"四者之间的权衡。2026 年的事实是：**合成数据已从"补充"变成"主力"**——而配比优化与质量门控——正在取代"堆天然语料"成为数据工程的胜负手。

未来的数据工程——大概率是"天然语料做种子、合成数据做主体、可验证信号做筛选、动态评测做闭环"的循环体系——数据不再是"挖矿"——而是"耕作"。
