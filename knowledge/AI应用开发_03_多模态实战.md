# 多模态AI应用开发：从图文到视频到跨模态实战

## 1. 多模态模型架构基础

多模态AI的核心挑战在于如何让模型同时理解并关联不同模态的信息——图像、文本、视频、音频等。目前主流的架构范式可以归纳为三种：双塔对比架构（CLIP）、融合编码器架构（Flamingo）和投影桥接架构（LLaVA）。理解这三种架构的设计理念和适用场景，是多模态应用开发的基石。

### 1.1 CLIP 双塔对比学习架构

CLIP（Contrastive Language-Image Pre-training）由 OpenAI 于2021年提出，其核心理念是用对比学习将图像和文本映射到同一语义空间。双塔架构包含独立的图像编码器（通常是 ViT 或 ResNet）和文本编码器（通常是 Transformer），通过 InfoNCE Loss 进行端到端的对比训练。

这种架构的优雅之处在于，一旦训练完成，模型可以在零样本（zero-shot）条件下完成图像分类、图文检索等任务——无需针对下游任务做任何微调。在实际应用中，CLIP 的 Embedding 被广泛用作多模态搜索的特征向量和图像生成的条件控制信号。

```python
# clip_contrastive.py
import torch
import torch.nn as nn
import torch.nn.functional as F

class CLIPModel(nn.Module):
    """CLIP dual-tower contrastive learning model.
    
    Architecture:
      ImageEncoder (ViT or ResNet) -> img_embedding
      TextEncoder  (Transformer)   -> txt_embedding
      Both projected to d=512 shared space, then L2-normalized.
    """
    def __init__(self, img_dim: int = 768, txt_dim: int = 512,
                 proj_dim: int = 512, temperature: float = 0.07):
        super().__init__()
        self.temperature = nn.Parameter(torch.tensor(temperature))
        self.img_encoder = nn.Sequential(
            nn.Linear(img_dim, proj_dim * 2),
            nn.GELU(),
            nn.Linear(proj_dim * 2, proj_dim),
        )
        self.txt_encoder = nn.Sequential(
            nn.Linear(txt_dim, proj_dim * 2),
            nn.GELU(),
            nn.Linear(proj_dim * 2, proj_dim),
        )

    def encode_image(self, x: torch.Tensor) -> torch.Tensor:
        h = self.img_encoder(x)
        return F.normalize(h, dim=-1)

    def encode_text(self, x: torch.Tensor) -> torch.Tensor:
        h = self.txt_encoder(x)
        return F.normalize(h, dim=-1)

    def forward(self, img_feat: torch.Tensor,
                txt_feat: torch.Tensor) -> tuple[torch.Tensor, torch.Tensor, torch.Tensor]:
        img_z = self.encode_image(img_feat)
        txt_z = self.encode_text(txt_feat)
        logits = img_z @ txt_z.T * self.temperature.exp()
        return logits, img_z, txt_z


def infonce_loss(logits: torch.Tensor) -> torch.Tensor:
    """InfoNCE loss with symmetric cross-entropy.
    
    For a batch of N (image, text) pairs, treat the N correct
    pairs as positives and N^2 - N incorrect pairs as negatives.
    Loss = (CE_img2txt + CE_txt2img) / 2
    """
    device = logits.device
    batch_size = logits.shape[0]
    labels = torch.arange(batch_size, device=device)
    loss_img = F.cross_entropy(logits, labels)
    loss_txt = F.cross_entropy(logits.T, labels)
    return (loss_img + loss_txt) / 2.0


def train_step(model: CLIPModel, img_batch: torch.Tensor,
               txt_batch: torch.Tensor, optimizer: torch.optim.Optimizer):
    model.train()
    logits, _, _ = model(img_batch, txt_batch)
    loss = infonce_loss(logits)
    loss.backward()
    optimizer.step()
    optimizer.zero_grad()
    return loss.item()
```

**InfoNCE Loss 的数学原理**。给定一个 batch 中的 N 个图文对，我们将第 i 个图像与第 i 个文本视为正例，其余 N-1 个文本作为负例。Image→Text 方向的交叉熵计算公式如下：

$$L_{i2t} = -\frac{1}{N}\sum_{i=1}^N \log \frac{\exp(s_{ii}/\tau)}{\sum_{j=1}^N \exp(s_{ij}/\tau)}$$

其中 $s_{ij} = \text{cosine}(I_i, T_j)$ 是余弦相似度，$\tau$ 是可学习的温度参数。温度参数的作用是控制相似度分布的"尖锐程度"——温度越低，模型对正负例的区分越严格。实际训练时通常将 $\tau$ 初始化为 0.07 并作为可学习参数参与反向传播。

CLIP 的双塔设计有一个重要的工程优势：图像和文本的 Embedding 可以预先计算并独立缓存。这意味着在线推理时，图像库的 Embedding 只需要计算一次，查询端的文本 Embedding 计算后直接与索引做相似度搜索即可，非常适合大规模检索场景。

### 1.2 Flamingo 式融合编码器

DeepMind 的 Flamingo 模型代表了另一种思路：在冻结的预训练视觉模型和语言模型之间插入 GATED Cross-Attention 层，用极少的可训练参数实现强大的多模态理解能力。Flamingo 最关键的创新是 Tanh 门控机制——门控参数初始化为零，使得训练开始时视觉信息完全不流入语言模型，随着训练逐渐"打开闸门"。

这种设计的意义在于：它完美地保留了预训练语言模型的原有能力，同时让模型学会在需要时参考视觉信息。这使得 Flamingo 在 few-shot 场景下表现尤为出色——即使只有少量图文示例，模型也能通过 in-context learning 完成图像描述、视觉问答等任务。

```python
# flamingo_gated_xattn.py
import torch
import torch.nn as nn
import math

class GatedCrossAttention(nn.Module):
    """GATED Cross-Attention from Flamingo.
    
    Key design:
      - Tanh-gated mechanism: output = tanh(alpha) * attn_output
        where alpha is a learnable scalar initialized to 0.
      - This lets the model start from the frozen LM and
        gradually "open the gate" to visual information.
    """
    def __init__(self, d_model: int, n_heads: int = 8):
        super().__init__()
        assert d_model % n_heads == 0
        self.d_model = d_model
        self.n_heads = n_heads
        self.head_dim = d_model // n_heads
        self.q_proj = nn.Linear(d_model, d_model, bias=False)
        self.k_proj = nn.Linear(d_model, d_model, bias=False)
        self.v_proj = nn.Linear(d_model, d_model, bias=False)
        self.out_proj = nn.Linear(d_model, d_model, bias=False)
        self.gate = nn.Parameter(torch.zeros(1))

    def forward(self, lang_hidden: torch.Tensor,
                vision_hidden: torch.Tensor,
                vision_mask: torch.Tensor | None = None) -> torch.Tensor:
        B, L, D = lang_hidden.shape
        _, V, _ = vision_hidden.shape
        Q = self.q_proj(lang_hidden).view(B, L, self.n_heads, self.head_dim).transpose(1, 2)
        K = self.k_proj(vision_hidden).view(B, V, self.n_heads, self.head_dim).transpose(1, 2)
        V_ = self.v_proj(vision_hidden).view(B, V, self.n_heads, self.head_dim).transpose(1, 2)
        attn = (Q @ K.transpose(-2, -1)) / math.sqrt(self.head_dim)
        if vision_mask is not None:
            attn = attn.masked_fill(~vision_mask[:, None, None, :], float('-inf'))
        attn_weights = torch.softmax(attn, dim=-1)
        attn_out = (attn_weights @ V_).transpose(1, 2).contiguous().view(B, L, D)
        attn_out = self.out_proj(attn_out)
        return torch.tanh(self.gate) * attn_out
```

Flamingo 的架构设计对后续模型产生了深远影响。例如，OpenFlamingo、IDEFICS 等开源模型直接沿用了 GATED Cross-Attention 的设计。在实际部署中，这种架构的优势在于视觉和语言部分都可以使用冻结的预训练权重，训练成本主要集中在新增的 Cross-Attention 层上。

### 1.3 LLaVA 式投影桥接架构

LLaVA（Large Language and Vision Assistant）在2023年提出了一种极其简洁且高效的多模态对齐方案。它的核心思想是使用一个轻量级的 MLP Projector 将视觉编码器的输出特征映射到 LLM 的词嵌入空间。这个 Projector 通常只有两层线性变换加 GELU 激活函数，却在多模态对齐任务上取得了惊人的效果。

LLaVA 的成功揭示了两个重要结论：第一，预训练视觉模型和语言模型的特征空间虽然维度不同，但通过一个足够简单的线性变换就能实现有效的对齐；第二，多模态能力的涌现主要来自语言模型的强大推理能力，视觉部分只需要提供足够好的特征表示。

```python
# llava_projection.py
import torch
import torch.nn as nn

class LLaVAProjector(nn.Module):
    """Two-layer MLP projector that bridges vision encoder and LLM.
    
    Visual features (ViT [CLS] or patch tokens) are projected
    into the LLM's word embedding space so the LLM can "see" images.
    
    Architecture:
      Linear(d_vision, d_llm*2) -> GELU -> Linear(d_llm*2, d_llm)
    """
    def __init__(self, d_vision: int = 1024, d_llm: int = 4096):
        super().__init__()
        self.projector = nn.Sequential(
            nn.Linear(d_vision, d_llm * 2),
            nn.GELU(),
            nn.Linear(d_llm * 2, d_llm),
        )

    def forward(self, vision_features: torch.Tensor) -> torch.Tensor:
        return self.projector(vision_features)


class LLaVAModel(nn.Module):
    """Minimal LLaVA-style vision-language model.
    
    Components:
      1. Vision Encoder (frozen ViT)
      2. MLP Projector
      3. LLM Decoder (frozen, with trainable LoRA or projector only)
    """
    def __init__(self, d_vision: int = 1024, d_llm: int = 4096,
                 vocab_size: int = 32000):
        super().__init__()
        self.vision_encoder = nn.Identity()
        self.projector = LLaVAProjector(d_vision, d_llm)
        self.embed_tokens = nn.Embedding(vocab_size, d_llm)
        self.lm_head = nn.Linear(d_llm, vocab_size, bias=False)

    def forward(self, pixel_values: torch.Tensor,
                input_ids: torch.Tensor,
                attention_mask: torch.Tensor) -> torch.Tensor:
        vis_feat = self.vision_encoder(pixel_values)
        vis_tokens = self.projector(vis_feat)
        txt_embeds = self.embed_tokens(input_ids)
        combined = torch.cat([vis_tokens, txt_embeds], dim=1)
        logits = self.lm_head(combined)
        return logits
```

在 LLaVA 的训练流程中，通常分两阶段进行：第一阶段冻结视觉编码器和语言模型，只训练 Projector，让项目器学会将视觉特征映射到文本空间；第二阶段解冻语言模型（或使用 LoRA 等技术进行参数高效微调），让语言模型学会理解视觉 Token 序列并进行多模态对话。这种两阶段训练策略在计算效率和模型性能之间取得了很好的平衡。

### 1.4 多模态统一建模趋势

当前多模态建模正在经历从"独立编码器加融合模块"到"原生统一架构"的范式转变。以下表格总结了几个代表性工作的架构演进脉络：

| 模型 | 架构范式 | 关键创新 |
|------|---------|---------|
| **CLIP** | 双塔对比 | InfoNCE loss，零样本迁移 |
| **Flamingo** | 融合编码器 | GATED cross-attention，少样本上下文学习 |
| **LLaVA** | 投影桥接 | 两层 MLP Projector，SFT 训练 |
| **CogVLM** | 深度融合 | 每层 Transformer 加入 visual expert |
| **LLaVA-NeXT** | 动态分辨率 | AnyRes 网格切分，支持高分辨率输入 |
| **Qwen2-VL** | 原生多模态 | 动态分辨率、多模态理解加生成统一 |

统一的趋势意味着未来的多模态模型不再需要单独设计视觉编码器和语言模型的拼接逻辑，而是从模型架构层面原生支持多种模态的输入和输出。Qwen2-VL 和 GPT-4o 等模型已经展示了这种统一架构的潜力——它们可以同时处理图像、视频、文本，并能生成图文混合的输出。

```python
# unified_multimodal.py
"""Conceptual comparison of unified multimodal architectures."""

def dynamic_resolution_grid(image_size: tuple, grid_size: int = 2):
    """LLaVA-NeXT style dynamic resolution.
    
    Instead of resizing to a fixed size, split the image into
    a grid of sub-images, each encoded independently.
    """
    H, W = image_size
    crop_h, crop_w = H // grid_size, W // grid_size
    global_view = (H, W)
    patches = [(i * crop_h, j * crop_w) for i in range(grid_size)
               for j in range(grid_size)]
    return {"global": global_view, "patches": patches}
```

## 2. 图像理解应用

图像理解是多模态应用中最成熟的领域之一，从基础的图像描述到复杂的文档理解和视觉问答，已经有大量经过生产验证的技术方案。

### 2.1 Image Captioning — BLIP 系列

图像描述（Image Captioning）要求模型同时理解图像内容和生成自然语言描述。BLIP（Bootstrapping Language-Image Pre-training）系列在这一领域取得了突破性进展。BLIP 的创新在于联合优化三个训练目标：图像-文本对比学习（ITC，类似 CLIP）、图像-文本匹配（ITM，二分类判断是否匹配）和语言建模（LM，自回归描述生成）。

BLIP2 进一步引入 Q-Former（Querying Transformer），用一个轻量级的 Transformer 在冻结的图像编码器和语言模型之间架起桥梁。Q-Former 通过学习一组可学习的查询向量，从图像特征中"提取"最关键的信息传递给语言模型。这种设计使得 BLIP2 可以用极少的训练参数（约 1% 的模型参数量）实现强大的图像理解和描述能力。

```python
# blip_captioning.py
import torch
import torch.nn as nn

class BLIPCaptionDecoder(nn.Module):
    """BLIP-style image captioning decoder.
    
    BLIP uses three training objectives jointly:
      - ITC (Image-Text Contrastive): like CLIP
      - ITM (Image-Text Matching): binary classification
      - LM (Language Modeling): autoregressive caption generation
    """
    def __init__(self, d_model: int = 768, vocab_size: int = 30522,
                 num_layers: int = 6):
        super().__init__()
        self.visual_embed = nn.Linear(2048, d_model)
        self.text_embed = nn.Embedding(vocab_size, d_model)
        decoder_layer = nn.TransformerDecoderLayer(d_model, nhead=8)
        self.decoder = nn.TransformerDecoder(decoder_layer, num_layers)
        self.lm_head = nn.Linear(d_model, vocab_size, bias=False)

    def forward(self, image_features: torch.Tensor,
                caption_ids: torch.Tensor) -> torch.Tensor:
        vis_emb = self.visual_embed(image_features)
        txt_emb = self.text_embed(caption_ids)
        out = self.decoder(txt_emb.transpose(0, 1), vis_emb.transpose(0, 1))
        logits = self.lm_head(out.transpose(0, 1))
        return logits

    def generate(self, image_features: torch.Tensor,
                 start_token: int = 101, end_token: int = 102,
                 max_len: int = 50, temperature: float = 1.0) -> torch.Tensor:
        """Greedy autoregressive generation."""
        batch_size = image_features.size(0)
        device = image_features.device
        vis_emb = self.visual_embed(image_features)
        generated = torch.full((batch_size, 1), start_token,
                               dtype=torch.long, device=device)
        for _ in range(max_len):
            txt_emb = self.text_embed(generated)
            out = self.decoder(txt_emb.transpose(0, 1), vis_emb.transpose(0, 1))
            logits = self.lm_head(out.transpose(0, 1))[:, -1, :]
            logits = logits / temperature
            next_token = logits.argmax(-1, keepdim=True)
            generated = torch.cat([generated, next_token], dim=-1)
            if (next_token == end_token).all():
                break
        return generated
```

在实际的 BLIP 生成过程中，温度参数（temperature）控制着生成结果的多样性。温度越低，生成越倾向于高概率 Token，结果更确定但可能重复；温度越高，采样越随机，多样性增加但可能产生不连贯的描述。在工程实践中，图像描述通常使用 0.7-1.0 的温度值，并在 beam search（束搜索，通常 beam size=3-5）的结果中选择最合理的输出。

### 2.2 VQA 系统

视觉问答（Visual Question Answering）要求模型理解图像并回答关于图像的自然语言问题。与图像描述不同，VQA 需要更精细的图像-文本对齐能力——模型必须定位到图像中的特定区域来回答问题。

VQA 系统的核心挑战在于跨模态的细粒度对齐。例如，当用户问"图片中左边那个人穿着什么颜色的衣服？"，模型需要理解"左边"的空间关系，定位到对应的人物区域，识别服装的颜色，然后生成答案。这要求视觉注意力和语言理解能力的紧密结合。

```python
# vqa_system.py
import torch
import torch.nn as nn
import torch.nn.functional as F

class VQAModel(nn.Module):
    """Visual Question Answering with cross-modal attention.
    
    Architecture: Vision Encoder + Text Encoder + Co-Attention + Classifier
    """
    def __init__(self, d_vision: int = 2048, d_text: int = 768,
                 d_hidden: int = 512, num_answers: int = 3129):
        super().__init__()
        self.vision_proj = nn.Linear(d_vision, d_hidden)
        self.text_proj = nn.Linear(d_text, d_hidden)
        self.cross_attn_img2txt = nn.MultiheadAttention(d_hidden, num_heads=8)
        self.cross_attn_txt2img = nn.MultiheadAttention(d_hidden, num_heads=8)
        self.classifier = nn.Sequential(
            nn.Linear(d_hidden * 2, d_hidden),
            nn.GELU(),
            nn.Dropout(0.1),
            nn.Linear(d_hidden, num_answers),
        )

    def forward(self, img_features: torch.Tensor,
                question_features: torch.Tensor,
                question_mask: torch.Tensor) -> torch.Tensor:
        V = self.vision_proj(img_features)
        Q = self.text_proj(question_features)
        V_attn, _ = self.cross_attn_txt2img(
            Q.transpose(0, 1), V.transpose(0, 1), V.transpose(0, 1))
        Q_attn, _ = self.cross_attn_img2txt(
            V.transpose(0, 1), Q.transpose(0, 1), Q.transpose(0, 1))
        v_pool = V_attn.mean(dim=0)
        q_pool = Q_attn.mean(dim=0)
        fused = torch.cat([v_pool, q_pool], dim=-1)
        return self.classifier(fused)
```

在 VQA 的工程实践中，问题类型检测是一个常用的预处理步骤。通过识别问题是关于"是什么"、"在哪里"、"有多少"还是"是不是"，可以引导模型关注不同的视觉特征。例如，"有多少"类问题需要模型具备计数能力，而"是不是"类问题只需要二分类判断。

### 2.3 OCR-Free 文档理解

传统文档理解系统依赖 OCR 提取文本后送入 NLP 模型，这种级联架构存在错误传播、处理速度慢、对复杂排版适应能力差等问题。Donut（Document Understanding Transformer）提出了一种彻底不同的思路：完全抛弃 OCR，直接用视觉 Transformer（Swin Transformer）编码文档图像，用 BART Decoder 生成结构化输出。

```python
# donut_document_understanding.py
import torch
import torch.nn as nn

class DonutModel(nn.Module):
    """Donut: OCR-free Document Understanding Transformer.
    
    Key insight: replace OCR pipeline with a Vision Encoder
    (Swin Transformer) that directly processes document images,
    and a Text Decoder (BART) that generates structured JSON.
    No OCR dependency -> faster inference, fewer cascading errors.
    """
    def __init__(self, vocab_size: int = 50265,
                 d_model: int = 1024, d_decoder: int = 768):
        super().__init__()
        self.encoder = nn.Identity()
        self.proj = nn.Linear(d_model, d_decoder)
        self.embed = nn.Embedding(vocab_size, d_decoder)
        decoder_layer = nn.TransformerDecoderLayer(d_decoder, nhead=8)
        self.decoder = nn.TransformerDecoder(decoder_layer, num_layers=6)
        self.lm_head = nn.Linear(d_decoder, vocab_size, bias=False)

    def forward(self, pixel_values: torch.Tensor,
                input_ids: torch.Tensor) -> torch.Tensor:
        patch_features = self.encoder(pixel_values)
        memory = self.proj(patch_features)
        tgt = self.embed(input_ids)
        out = self.decoder(tgt.transpose(0, 1), memory.transpose(0, 1))
        logits = self.lm_head(out.transpose(0, 1))
        return logits
```

Donut 的端到端设计带来了几个显著优势。第一，推理速度快，省去了 OCR 的额外处理步骤；第二，对复杂排版（如表格、多栏布局、手写体）的适应能力更强，因为 Swin Transformer 直接学习的是图像的视觉特征而非字符序列；第三，支持结构化输出，可以直接生成 JSON 格式的解析结果，便于下游系统消费。

Donut 的后续工作 Nougat（Neural Optical Understanding for Academic Documents）进一步优化了这一思路，专门针对学术论文和数学文档进行优化。Nougat 的改进主要包括：更高的输入分辨率（896×896）、专门处理 LaTeX 数学符号的 SentencePiece 分词器（包含约 30k 个数学 Token），以及通过合成数据进行的教师-学生预训练。在实际测试中，Nougat 对数学公式的识别准确率显著优于基于 OCR 的传统方案。

### 2.4 多页文档理解 — LayoutLM 系列

对于发票、合同、研究报告等多页文档的理解，纯视觉方案往往不够充分，因为这些文档的语义很大程度上依赖于文本的布局位置。LayoutLM 系列通过将文本、视觉和布局信息（2D 位置编码）统一建模来解决这个问题。

LayoutLM 的核心创新是 2D Position Embedding。它将每个文本 Token 的边界框坐标（x0, y0, x1, y1）编码为嵌入向量，与文本嵌入相加后送入 Transformer。这样模型不仅能理解文本的内容，还能理解文本在页面上的位置关系——例如，"总金额"下面的数字是一个金额，而不是一个日期。

```python
# layoutlm_document.py
import torch
import torch.nn as nn

class LayoutEmbedding(nn.Module):
    """LayoutLM-style 2D position embedding.
    
    Encodes bounding box coordinates (x0, y0, x1, y1) into
    the same embedding space as text tokens.
    """
    def __init__(self, d_model: int = 768, max_position: int = 1024):
        super().__init__()
        self.x_embed = nn.Embedding(max_position, d_model)
        self.y_embed = nn.Embedding(max_position, d_model)
        self.w_embed = nn.Embedding(max_position, d_model)
        self.h_embed = nn.Embedding(max_position, d_model)

    def forward(self, bbox: torch.Tensor) -> torch.Tensor:
        """bbox: [B, seq_len, 4] normalized to [0, 1000]"""
        x0, y0, x1, y1 = bbox.unbind(-1)
        w = (x1 - x0).clamp(min=0).long()
        h = (y1 - y0).clamp(min=0).long()
        return (self.x_embed(x0.long()) + self.y_embed(y0.long()) +
                self.w_embed(w) + self.h_embed(h))


class LayoutLMPlusEncoder(nn.Module):
    """LayoutLMv3: unified text + layout + image encoder.
    
    Features:
      - Word-level text embeddings from RoBERTa
      - 2D layout embeddings from bounding boxes
      - Patch-level visual embeddings from ViT
      - All three fused through a shared transformer
    """
    def __init__(self, d_model: int = 768, vocab_size: int = 50265):
        super().__init__()
        self.text_embed = nn.Embedding(vocab_size, d_model)
        self.layout_embed = LayoutEmbedding(d_model)
        self.visual_proj = nn.Linear(2048, d_model)
        encoder_layer = nn.TransformerEncoderLayer(d_model, nhead=12)
        self.encoder = nn.TransformerEncoder(encoder_layer, num_layers=12)

    def forward(self, input_ids: torch.Tensor,
                bbox: torch.Tensor,
                patch_features: torch.Tensor) -> torch.Tensor:
        txt = self.text_embed(input_ids)
        lay = self.layout_embed(bbox)
        vis = self.visual_proj(patch_features)
        combined = torch.cat([txt + lay, vis], dim=1)
        return self.encoder(combined.transpose(0, 1))
```

LayoutLMv3 进一步将文本、布局和图像三种模态在特征层面统一融合。它使用一个共享的 Transformer 编码器同时处理文本 Token（含布局嵌入）和图像 Patch Token，让模型在自注意力过程中自动学习三种模态之间的关联。在实际应用中，LayoutLM 系列模型在发票信息提取、合同条款分析、表单理解等任务上明显优于纯 NLP 或纯视觉方案。

## 3. 视频理解应用

视频理解是多模态应用中最具挑战性的方向之一。视频不仅包含空间信息，还包含时间维度，计算成本和建模复杂度远高于静态图像。目前的主流方案可以分为"逐帧加时序聚合"和"3D 时序建模"两大路线。

### 3.1 Video LLM 架构对比

Video-LLaMA 和 Video-ChatGPT 代表了视频理解 LLM 的两种典型技术路线。Video-LLaMA 采用"先逐帧编码、再时序聚合"的策略，每帧独立通过 ViT 编码后，使用 Q-Former 跨帧聚合时序信息。Video-ChatGPT 则使用 3D 卷积直接在特征层面建模时序关系。

Video-LLaMA 的 Q-Former 方案中，一组可学习的查询向量通过交叉注意力机制从所有帧的特征中提取关键信息。这种方式的好处是：帧与帧之间的计算是独立的，可以并行处理，而且 Q-Former 的查询数量控制着向 LLM 传递的信息量，是一个有效的 Token 压缩机制。

Video-ChatGPT 使用 3D 卷积在 ViT 输出的特征序列上建模时序关系。3D 卷积核同时在空间和时间维度上滑动，能够捕获帧间的运动模式。这种方式对动作识别类任务更加有效，因为连续的帧序列中包含了运动信息。

```python
# video_llm_architectures.py
import torch
import torch.nn as nn

class VideoLLaMAQFormer(nn.Module):
    """Video-LLaMA: Frame-wise encoding + Q-Former temporal aggregation.
    
    Steps:
      1. Sample N frames from the video
      2. Each frame goes through a frozen ViT
      3. Q-Former (learnable queries) attends to all frame features
         simultaneously, performing temporal aggregation
      4. Output queries are projected to LLM embedding space
    """
    def __init__(self, d_vision: int = 1408, d_query: int = 768,
                 num_queries: int = 32, num_heads: int = 8):
        super().__init__()
        self.query_tokens = nn.Parameter(torch.randn(1, num_queries, d_query))
        self.vision_proj = nn.Linear(d_vision, d_query)
        self.cross_attn = nn.MultiheadAttention(d_query, num_heads, batch_first=True)
        self.ffn = nn.Sequential(
            nn.Linear(d_query, d_query * 4),
            nn.GELU(),
            nn.Linear(d_query * 4, d_query),
        )
        self.layer_norm = nn.LayerNorm(d_query)

    def forward(self, frame_features: torch.Tensor,
                frame_mask: torch.Tensor = None) -> torch.Tensor:
        """frame_features: [B, N, P, d_vision] (N=num_frames)"""
        B, N, P, D = frame_features.shape
        vis = self.vision_proj(frame_features)
        vis = vis.view(B, N * P, -1)
        queries = self.query_tokens.expand(B, -1, -1)
        attn_out, _ = self.cross_attn(queries, vis, vis)
        out = self.layer_norm(queries + attn_out)
        out = self.layer_norm(out + self.ffn(out))
        return out


class VideoChatGPT3DConv(nn.Module):
    """Video-ChatGPT: 3D Conv + Frame Encoder + Projector.
    
    Alternative: use 3D convolutions on a stack of frame
    features to model temporal relationships before projection.
    """
    def __init__(self, d_vision: int = 1024, d_llm: int = 4096, num_frames: int = 8):
        super().__init__()
        self.conv3d = nn.Sequential(
            nn.Conv3d(d_vision, d_vision, kernel_size=(3, 3, 3), padding=(1, 1, 1)),
            nn.GELU(),
            nn.Conv3d(d_vision, d_vision, kernel_size=(3, 1, 1), padding=(1, 0, 0)),
            nn.GELU(),
        )
        self.projector = nn.Sequential(
            nn.Linear(d_vision, d_llm * 2),
            nn.GELU(),
            nn.Linear(d_llm * 2, d_llm),
        )

    def forward(self, frame_features: torch.Tensor,
                patch_grid: tuple = (16, 16)) -> torch.Tensor:
        """frame_features: [B, N, P, D]"""
        B, N, P, D = frame_features.shape
        H, W = patch_grid
        x = frame_features.transpose(1, 3)
        x = x.view(B, D, N, H, W)
        x = self.conv3d(x)
        x = x.mean(dim=[2, 3, 4])
        return self.projector(x)
```

这两种方案各有优劣。Video-LLaMA 的 Q-Former 方案更适合长视频理解，因为它可以处理更多帧且计算可控；Video-ChatGPT 的 3D 卷积方案在短视频动作识别上更优，但对计算资源的要求更高。在实际系统设计中，我们经常根据视频时长和任务需求混合使用这两种策略。

### 3.2 时序建模方法 — Frame Sampling

视频帧采样是视频理解流水线的第一步，也是最容易被忽视但在工程上影响巨大的环节。采样策略的选择直接影响模型的性能和计算成本。目前主流的采样策略有三种：均匀采样、密集采样和关键帧采样。

均匀采样最简单直接——从视频中均匀抽取 N 帧。这种方式能覆盖视频的整体内容，但可能错过短暂但关键的事件。密集采样则从视频中选取一个连续片段后在其中均匀抽样，更适合动作识别等需要时序连续性的任务。关键帧采样通过额外的评分模型（基于帧间差异、显著性检测等）选择信息量最大的帧，能有效减少冗余帧的处理。

```python
# frame_sampling.py
import random
import torch

def uniform_sampling(total_frames: int, num_samples: int) -> list[int]:
    """Uniform sampling: evenly spaced frames across the video."""
    if total_frames <= num_samples:
        return list(range(total_frames))
    step = total_frames / num_samples
    return [int(i * step) for i in range(num_samples)]

def dense_sampling(total_frames: int, num_samples: int,
                   window_size: int = 3) -> list[int]:
    """Dense sampling: sample a contiguous clip then uniformly sample."""
    if total_frames <= num_samples:
        return list(range(total_frames))
    start = random.randint(0, max(0, total_frames - window_size))
    clip = list(range(start, min(start + window_size, total_frames)))
    if len(clip) < num_samples:
        clip.extend(uniform_sampling(total_frames, num_samples - len(clip)))
    return clip[:num_samples]

def keyframe_sampling(frame_scores: list[float], num_samples: int) -> list[int]:
    """Keyframe sampling: select frames with highest importance scores."""
    if len(frame_scores) <= num_samples:
        return list(range(len(frame_scores)))
    sorted_idx = sorted(range(len(frame_scores)),
                        key=lambda i: frame_scores[i], reverse=True)
    return sorted(sorted_idx[:num_samples])
```

在工程实践中，我们还需要考虑视频的解码效率。直接解码所有帧再采样会导致大量不必要 I/O。一个常见的优化是使用 FFmpeg 的"关键帧模式"——只解码 I 帧（关键帧），然后在这些 I 帧中进行采样。对于时长较长（>10分钟）的视频，还可以结合镜头分割检测（shot boundary detection）先切分场景，再在每个场景内采样，确保采样的帧能代表视频的所有内容段落。

### 3.3 视频问答与视频摘要

视频问答（Video QA）和视频摘要（Video Summarization）是视频理解的核心应用。Video QA 要求模型理解视频内容并回答自然语言问题，Video Summarization 则要求模型生成视频的简洁文字描述。

这两个任务的关键在于时序信息的有效压缩。一个分辨率为 224×224、帧率 30fps、时长 60 秒的视频包含 1800 帧，每帧经过 ViT 产生 256 个 Patch Token，总共有超过 46 万个 Token——远超大多数 LLM 的上下文窗口。因此，视频 Token 压缩是视频 LLM 工程化的核心瓶颈。

```python
# video_qa_summary.py
import torch
import torch.nn as nn

class VideoQAModel(nn.Module):
    """Video QA: jointly encode video frames + question, decode answer."""
    def __init__(self, d_vision: int = 1024, d_llm: int = 4096,
                 vocab_size: int = 32000):
        super().__init__()
        self.frame_encoder = nn.Identity()
        self.temporal_pool = nn.Conv1d(d_vision, d_vision, kernel_size=3, padding=1)
        self.projector = nn.Sequential(
            nn.Linear(d_vision, d_llm * 2),
            nn.GELU(),
            nn.Linear(d_llm * 2, d_llm),
        )
        self.embed = nn.Embedding(vocab_size, d_llm)
        decoder_layer = nn.TransformerDecoderLayer(d_llm, nhead=8, batch_first=True)
        self.decoder = nn.TransformerDecoder(decoder_layer, num_layers=6)
        self.lm_head = nn.Linear(d_llm, vocab_size, bias=False)

    def forward(self, frames: torch.Tensor, question_ids: torch.Tensor,
                answer_ids: torch.Tensor = None) -> torch.Tensor:
        B, N = frames.shape[:2]
        frame_feats = self.frame_encoder(
            frames.view(B * N, *frames.shape[2:])
        ).view(B, N, -1)
        frame_feats = self.temporal_pool(frame_feats.transpose(1, 2)).transpose(1, 2)
        video_feat = frame_feats.mean(dim=1)
        video_emb = self.projector(video_feat).unsqueeze(1)
        q_emb = self.embed(question_ids)
        if answer_ids is not None:
            a_emb = self.embed(answer_ids)
            combined = torch.cat([video_emb, q_emb, a_emb], dim=1)
        else:
            combined = torch.cat([video_emb, q_emb], dim=1)
        out = self.decoder(combined, combined)
        logits = self.lm_head(out)
        return logits
```

视频摘要的实现通常分为抽取式（extractive）和生成式（abstractive）两种。抽取式方法从视频中选择最具代表性的帧或片段作为摘要，生成式方法则用语言模型生成视频的文字描述。在实际产品中，两者经常联合使用——先用抽取式方法选出关键帧，再基于关键帧生成文字摘要。

## 4. 图文生成应用

图文生成是扩散模型时代最具影响力的多模态应用方向。从 Stable Diffusion 到 Sora，从 ControlNet 到视频生成模型，这一领域在过去两年经历了爆发式发展。

### 4.1 Text-to-Image — Stable Diffusion

Stable Diffusion 的核心是潜在扩散模型（Latent Diffusion Model）。它的关键创新是在 VAE 的潜在空间（而非像素空间）中执行扩散过程，大幅降低了计算成本。具体来说，Stable Diffusion 的流水线包含三个组件：

第一，VAE（变分自编码器）将 512×512 的像素图像压缩为 64×64 的潜在表示，压缩率达到 64 倍。第二，U-Net 在潜在空间中进行扩散去噪，通过 Cross-Attention 层注入文本条件。第三，文本编码器（CLIP Text Encoder）将文本提示转为条件嵌入。

U-Net 中的 Cross-Attention 是实现文本控制的关键。在 U-Net 的每个空间分辨率层中，Cross-Attention 层让图像特征图作为 Query，文本嵌入作为 Key/Value，从而让模型"知道"要在图像的哪个位置生成什么东西。

```python
# stable_diffusion_core.py
import torch
import torch.nn as nn
import torch.nn.functional as F
import math

class SinusoidalTimeEmbedding(nn.Module):
    """Time embedding for diffusion timestep conditioning."""
    def __init__(self, dim: int = 320):
        super().__init__()
        self.dim = dim

    def forward(self, t: torch.Tensor) -> torch.Tensor:
        half = self.dim // 2
        freqs = torch.exp(-math.log(10000) * torch.arange(half, device=t.device) / half)
        args = t[:, None].float() * freqs[None, :]
        return torch.cat([torch.sin(args), torch.cos(args)], dim=-1)


class CrossAttentionLayer(nn.Module):
    """Cross-Attention for text-conditioned image generation.
    
    In Stable Diffusion's U-Net, every spatial resolution block
    has cross-attention layers that inject text embeddings.
    """
    def __init__(self, d_model: int, d_context: int = 768, n_heads: int = 8):
        super().__init__()
        self.n_heads = n_heads
        self.head_dim = d_model // n_heads
        self.to_q = nn.Linear(d_model, d_model, bias=False)
        self.to_k = nn.Linear(d_context, d_model, bias=False)
        self.to_v = nn.Linear(d_context, d_model, bias=False)
        self.to_out = nn.Linear(d_model, d_model)

    def forward(self, x: torch.Tensor, context: torch.Tensor,
                mask: torch.Tensor = None) -> torch.Tensor:
        """x: [B, H*W, d]; context: [B, T, d_context]"""
        B, N, D = x.shape
        Q = self.to_q(x).view(B, N, self.n_heads, self.head_dim).transpose(1, 2)
        K = self.to_k(context).view(B, -1, self.n_heads, self.head_dim).transpose(1, 2)
        V = self.to_v(context).view(B, -1, self.n_heads, self.head_dim).transpose(1, 2)
        attn = (Q @ K.transpose(-2, -1)) / math.sqrt(self.head_dim)
        if mask is not None:
            attn = attn.masked_fill(~mask[:, None, None, :], float('-inf'))
        attn = torch.softmax(attn, dim=-1)
        out = (attn @ V).transpose(1, 2).contiguous().view(B, N, D)
        return self.to_out(out)


class StableDiffusionSampler:
    """DDIM sampler for non-Markovian reverse diffusion.
    
    Instead of predicting noise epsilon directly, predict x0
    and use it for deterministic decoding.
    """
    def __init__(self, num_steps: int = 50, beta_start: float = 0.00085,
                 beta_end: float = 0.012):
        self.num_steps = num_steps
        betas = torch.linspace(beta_start, beta_end, 1000)
        alphas = 1 - betas
        alphas_cumprod = torch.cumprod(alphas, dim=0)
        step_indices = torch.linspace(0, 999, num_steps, dtype=torch.long)
        self.alphas_cumprod = alphas_cumprod[step_indices]

    @torch.no_grad()
    def sample(self, model: nn.Module, noise: torch.Tensor,
               text_embeddings: torch.Tensor,
               guidance_scale: float = 7.5) -> torch.Tensor:
        """DDIM sampling with classifier-free guidance."""
        x = noise.clone()
        for i in range(self.num_steps - 1, -1, -1):
            t = torch.full((x.shape[0],), i, device=x.device, dtype=torch.long)
            alpha_t = self.alphas_cumprod[i]
            alpha_prev = self.alphas_cumprod[i - 1] if i > 0 else torch.tensor(1.0)
            x_in = torch.cat([x] * 2)
            t_in = torch.cat([t] * 2)
            c_in = torch.cat([text_embeddings, torch.zeros_like(text_embeddings)])
            pred_noise = model(x_in, t_in, c_in)
            pred_cond, pred_uncond = pred_noise.chunk(2)
            pred_noise = pred_uncond + guidance_scale * (pred_cond - pred_uncond)
            x0_pred = (x - torch.sqrt(1 - alpha_t) * pred_noise) / torch.sqrt(alpha_t)
            x = torch.sqrt(alpha_prev) * x0_pred + torch.sqrt(1 - alpha_prev) * pred_noise
        return x
```

Classifier-Free Guidance（CFG）是扩散模型中的一项关键技术。在采样时，模型同时计算有条件（给定文本）和无条件（空白文本）的噪声预测，然后外推两者的差异：$\hat{\epsilon} = \epsilon_{uncond} + w \cdot (\epsilon_{cond} - \epsilon_{uncond})$。当引导系数 $w$ 大于 1 时，生成的图像更紧密地遵循文本提示，但过度增大会导致图像饱和度过高或失真。在实际使用中，7.5 是常用的默认值，创意类生成可以降低到 4-5，精确遵循提示则使用 10-12。

### 4.2 LoRA 微调

LoRA（Low-Rank Adaptation）是目前最流行的参数高效微调方法之一。LoRA 的核心思想是对预训练权重矩阵 W 施加一个低秩约束：$W' = W + AB$，其中 A 和 B 是低秩矩阵，秩 r 远小于原始矩阵的维度。训练时只有 A 和 B 被更新，原始权重 W 保持冻结。

LoRA 在 Stable Diffusion 微调中的典型应用是将低秩适配器插入到 U-Net 的 Cross-Attention 层的 Q/K/V 投影中。这使得用户可以用少量图片（10-100 张）和有限的 GPU 资源（12GB 显存即可）微调出特定风格或人物的模型。

```python
# lora_finetune.py
import torch
import torch.nn as nn

class LoRALayer(nn.Module):
    """Low-Rank Adaptation (LoRA) for efficient fine-tuning.
    
    Instead of updating the full weight matrix W (d x k),
    learn a low-rank decomposition W' = W + A @ B
    where A (d x r) and B (r x k), with r << min(d, k).
    """
    def __init__(self, in_dim: int, out_dim: int, rank: int = 4, alpha: float = 1.0):
        super().__init__()
        self.scale = alpha / rank
        self.A = nn.Parameter(torch.randn(in_dim, rank) * 0.01)
        self.B = nn.Parameter(torch.randn(rank, out_dim) * 0.01)

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        return x @ (self.A @ self.B) * self.scale


def apply_lora_to_unet(unet: nn.Module, rank: int = 4,
                       target_modules: list[str] = ["to_q", "to_k", "to_v"]):
    """Inject LoRA layers into a Stable Diffusion U-Net's attention layers."""
    lora_params = []
    for name, module in unet.named_modules():
        if any(t in name for t in target_modules) and isinstance(module, nn.Linear):
            in_dim, out_dim = module.weight.shape
            lora = LoRALayer(out_dim, in_dim, rank)
            original_forward = module.forward

            def lora_forward(x, lora=lora, orig=original_forward):
                return orig(x) + lora(x)

            module.forward = lora_forward
            lora_params.extend([lora.A, lora.B])
    for p in unet.parameters():
        p.requires_grad = False
    for p in lora_params:
        p.requires_grad = True
    return lora_params


def train_lora_sd(unet, vae, text_encoder, tokenizer, dataloader,
                  rank=4, lr=1e-4, num_epochs=5, device="cuda"):
    lora_params = apply_lora_to_unet(unet, rank)
    optimizer = torch.optim.AdamW(lora_params, lr=lr)
    noise_scheduler = StableDiffusionSampler(num_steps=1000)

    for epoch in range(num_epochs):
        for batch in dataloader:
            images, captions = batch
            images = images.to(device)
            with torch.no_grad():
                latents = vae.encode(images).latent_dist.sample() * 0.18215
            tokens = tokenizer(captions, return_tensors="pt",
                               padding=True, truncation=True).to(device)
            with torch.no_grad():
                text_emb = text_encoder(tokens.input_ids)
            noise = torch.randn_like(latents)
            timesteps = torch.randint(0, 1000, (latents.shape[0],), device=device)
            noisy_latents = noise_scheduler.add_noise(latents, noise, timesteps)
            noise_pred = unet(noisy_latents, timesteps, text_emb)
            loss = F.mse_loss(noise_pred, noise)
            loss.backward()
            optimizer.step()
            optimizer.zero_grad()
        print(f"Epoch {epoch+1}, Loss: {loss.item():.6f}")
```

在 LoRA 的工程实践中，秩 r 的选择需要在表达能力和过拟合之间取得平衡。对于风格微调（如动漫风格、油画风格），r=8-16 通常足够；对于人物/物体微调，r=16-32 效果更好。LoRA 权重文件通常只有 5-50MB，远比完整模型权重小，便于存储和分发。这也是 LoRA 在社区中如此受欢迎的原因之一。

### 4.3 Text-to-Video 生成

文本到视频生成将扩散模型从图像扩展到视频领域。核心挑战在于保持帧间的时序一致性——生成的每一帧必须与前后帧在内容、风格和运动上自然衔接。目前主流的方案是在图像 U-Net 的基础上加入时序模块（Temporal Layer）。

Temporal Layer 的实现方式主要有两种：3D 卷积和时间注意力。3D 卷积核同时在空间和时间维度上滑动，能够捕获局部运动模式；时间注意力则让每一帧的每个位置都可以关注其他帧的对应位置，实现全局时序建模。在实际的 Video LDM（Latent Diffusion Model）中，这两种方式通常组合使用。

```python
# text_to_video_diffusion.py
import torch
import torch.nn as nn

class TemporalConv3D(nn.Module):
    """Temporal convolution for video diffusion models.
    
    Inserted after each spatial block in the U-Net.
    Operates on the time dimension with 1x3x3 or 3x1x1 kernels.
    """
    def __init__(self, dim: int, kernel_size: tuple = (3, 1, 1)):
        super().__init__()
        self.conv = nn.Conv3d(dim, dim, kernel_size, padding='same')
        self.norm = nn.GroupNorm(32, dim)
        self.silu = nn.SiLU()

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        """x: [B, C, F, H, W] where F = num_frames"""
        return self.silu(self.norm(self.conv(x)))


class VideoUNet(nn.Module):
    """3D U-Net for video diffusion with temporal layers.
    
    Architecture:
      Spatial blocks (2D Conv) — shared across frames
      + Temporal blocks (3D Conv / Temporal Attention)
      + Cross-Attention to text embeddings
    """
    def __init__(self, d_model: int = 320, d_text: int = 768,
                 num_frames: int = 16):
        super().__init__()
        self.num_frames = num_frames
        self.time_embed = SinusoidalTimeEmbedding(d_model)
        self.spatial_conv_in = nn.Conv2d(4, d_model, 3, padding=1)
        self.temporal_conv = TemporalConv3D(d_model)
        self.cross_attn = CrossAttentionLayer(d_model, d_text)
        self.spatial_conv_out = nn.Conv2d(d_model, 4, 3, padding=1)

    def forward(self, x: torch.Tensor, t: torch.Tensor,
                text_emb: torch.Tensor) -> torch.Tensor:
        """x: [B, C, F, H, W]; t: [B]; text_emb: [B, T, d_text]"""
        B, C, F, H, W = x.shape
        t_emb = self.time_embed(t)
        x_s = x.permute(0, 2, 1, 3, 4).reshape(B * F, C, H, W)
        h = self.spatial_conv_in(x_s)
        _, C_h, H_h, W_h = h.shape
        h = h.view(B, F, C_h, H_h, W_h).permute(0, 2, 1, 3, 4)
        h = self.temporal_conv(h)
        B2, C2, F2, H2, W2 = h.shape
        h_2d = h.permute(0, 2, 1, 3, 4).reshape(B * F, C2, H2, W2)
        h_2d = h_2d + t_emb[:, None, None, :].expand(-1, H2, W2, -1).permute(0, 3, 1, 2)
        h_2d = h_2d.permute(0, 2, 3, 1)
        h_2d = self.cross_attn(h_2d.view(B * F, -1, C2),
                               text_emb.unsqueeze(1).expand(-1, F, -1, -1)
                               .reshape(B * F, -1, text_emb.shape[-1]))
        h_2d = h_2d.view(B * F, H2, W2, C2).permute(0, 3, 1, 2)
        out = self.spatial_conv_out(h_2d)
        _, C_out, H_out, W_out = out.shape
        out = out.view(B, F, C_out, H_out, W_out).permute(0, 2, 1, 3, 4)
        return out
```

视频扩散模型的训练通常分为两步：先用海量图像数据预训练空间层（获得高质量的单帧生成能力），再用视频数据微调时序层（学习帧间一致性）。这种方法充分利用了图像数据的丰富性，降低了视频训练的数据门槛。在实际部署中，视频生成长度通常限制在 2-10 秒（16-40 帧），更长的视频需要额外的时序外推策略。

### 4.4 Image Editing 应用

图像编辑是文生图模型的重要应用方向，包括 Inpainting（局部填充）、Outpainting（外延扩展）和 ControlNet（条件控制生成）。

ControlNet 的技术方案最为通用。它的核心思路是克隆 U-Net 编码器的一个可训练副本，通过 Zero Convolution 层与原始冻结的 U-Net 连接。Zero Convolution 的权重初始化为零，因此在训练开始时 ControlNet 对原始模型没有任何影响，随着训练推进逐渐学习到新的条件控制能力。这种设计保证了 ControlNet 在任何现有扩散模型上都可以即插即用，而不会破坏模型原有的生成能力。

```python
# controlnet_inpainting.py
import torch
import torch.nn as nn

class ControlNet(nn.Module):
    """ControlNet: add spatial conditioning to pretrained diffusion models.
    
    Key idea: clone the U-Net encoder (trainable), copy weights,
    add zero-conv layers, and connect to the frozen U-Net via
    skip connections.
    """
    def __init__(self, unet: nn.Module):
        super().__init__()
        self.control_encoder = copy.deepcopy(unet.encoder)
        self.zero_convs = nn.ModuleList([
            nn.Conv2d(d, d, 1, bias=False) for d in [320, 640, 1280]
        ])
        for conv in self.zero_convs:
            nn.init.zeros_(conv.weight)

    def forward(self, control_image: torch.Tensor,
                encoder_hidden_states: list[torch.Tensor]) -> list[torch.Tensor]:
        control_features = self.control_encoder(control_image)
        residuals = []
        for feat, zconv in zip(control_features, self.zero_convs):
            residuals.append(zconv(feat))
        return residuals


def controlnet_inference(unet, controlnet, vae, text_encoder, tokenizer,
                          image: torch.Tensor, prompt: str,
                          control_strength: float = 1.0):
    """Run ControlNet-guided inpainting inference."""
    tokens = tokenizer(prompt, return_tensors="pt")
    text_emb = text_encoder(tokens.input_ids)
    with torch.no_grad():
        latents = vae.encode(image.to("cuda")).latent_dist.sample()
    noise = torch.randn_like(latents)
    noisy = noise
    sampler = StableDiffusionSampler()
    for step in range(sampler.num_steps):
        t = torch.full((1,), step, device="cuda")
        with torch.no_grad():
            unet_features = unet.get_encoder_features(noisy, t, text_emb)
        control_residuals = controlnet(control_image, unet_features)
        noise_pred = unet.forward_with_control(
            noisy, t, text_emb, control_residuals, control_strength)
        noisy = sampler.step(noise_pred, t, noisy)
    with torch.no_grad():
        generated = vae.decode(noisy)
    return generated
```

ControlNet 支持多种条件控制信号，包括 Canny 边缘图、深度图、人体骨架、语义分割图等。不同的控制信号适用于不同的场景：Canny 边缘图适合保持构图结构，深度图适合保持三维空间关系，人体骨架适合控制人物姿势。在实际应用中，还可以将多个 ControlNet 叠加使用，同时施加多种控制条件。

## 5. 跨模态检索系统

跨模态检索是多模态 AI 在生产环境中部署最广泛的应用之一。其核心思路是将图像和文本映射到同一向量空间，通过向量相似度搜索实现跨模态匹配。

### 5.1 CLIP Embedding 在线服务化

将 CLIP Embedding 部署为在线服务需要考虑吞吐量、延迟和资源效率。典型部署方案是在 GPU 上运行模型推理，通过 RESTful API 提供服务。在服务化部署中，文本编码通常走在线推理（因为查询是实时输入的），而图像编码可以通过离线批处理预先计算。


在线服务化的性能调优主要关注三个方面：第一，批处理策略——将多个查询打包成 batch 一次推理，充分利用 GPU 并行计算能力；第二，模型量化——将 FP16 精度的模型进一步量化为 INT8，在几乎不损失检索精度的前提下将吞吐量提升 2-3 倍；第三，缓存策略——对高频查询的文本 Embedding 进行缓存，避免重复计算。

### 5.2 多模态搜索工程实现

一个工业级的多模态搜索系统通常采用"多路召回→跨模态重排序→精排"的三级流水线架构。第一级召回使用 FAISS 等高效向量索引，从海量候选中快速筛选出 top-100 候选；第二级使用更重的跨模态模型（如 BLIP-2）对候选进行精细化评分；第三级结合业务特征（价格、销量、用户偏好等）进行最终排序。

```python
# multimodal_search_pipeline.py
import numpy as np
import faiss
from typing import Any

class MultiStageMultimodalSearch:
    """Multi-stage multimodal search: recall -> re-rank -> fine-rank.
    
    Stage 1 (Recall): Efficient ANN search on CLIP embeddings.
    Stage 2 (Re-rank): Cross-modal re-ranker (BLIP-2 style).
    Stage 3 (Fine-rank): Domain-specific ranking model.
    """
    def __init__(self, clip_dim: int = 512):
        self.recall_index = faiss.IndexFlatIP(clip_dim)
        self.reranker = lambda q, c: np.random.rand(len(c))
        self.fine_ranker = lambda q, c: np.random.rand(len(c))

    def recall(self, query_emb: np.ndarray, k: int = 100) -> tuple:
        scores, indices = self.recall_index.search(query_emb.reshape(1, -1), k)
        return scores[0], indices[0]

    def rerank(self, query_emb: np.ndarray,
               candidates: list[Any], k: int = 30) -> list[Any]:
        scores = self.reranker(query_emb, candidates)
        ranked = sorted(zip(candidates, scores), key=lambda x: -x[1])
        return [item for item, _ in ranked[:k]]

    def fine_rank(self, query_emb: np.ndarray,
                  candidates: list[Any], k: int = 10) -> list[Any]:
        scores = self.fine_ranker(query_emb, candidates)
        ranked = sorted(zip(candidates, scores), key=lambda x: -x[1])
        return [item for item, _ in ranked[:k]]

    def search(self, query_emb: np.ndarray, top_k: int = 10) -> list[Any]:
        recall_results, _ = self.recall(query_emb, k=max(100, top_k * 10))
        reranked = self.rerank(query_emb, recall_results, k=max(30, top_k * 3))
        final = self.fine_rank(query_emb, reranked, k=top_k)
        return final
```

多路召回是保证搜索覆盖率的关键技术。除了 CLIP 向量检索外，还可以同时使用标签检索（精确匹配商品标签）、属性检索（筛选价格区间、品牌等结构化属性）和文本全文检索（使用 Elasticsearch 对商品的文本描述进行关键词匹配）。多路结果通过加权融合或级联过滤合并为最终的候选集合。

### 5.3 大规模向量索引

当多模态数据规模达到亿级以上时，暴力搜索（Flat Index）已经不可行。FAISS 提供了多种大规模索引方案，其中 HNSW（Hierarchical Navigable Small World）和 IVF-PQ（Inverted File with Product Quantization）是最常用的两种。

HNSW 通过构建多层的可导航小世界图实现对数级别的搜索复杂度。它的召回率极高（通常 95% 以上），但内存消耗较大。IVF-PQ 通过倒排文件和乘积量化将向量压缩到原始大小的 1/8 甚至 1/16，可以显著降低内存需求，但搜索精度有一定损失。在实际系统中，HNSW 适用于千万级以下、对精度要求高的场景；IVF-PQ 适用于十亿级以上、内存受限的场景。

```python
# vector_index_hnsw.py
import faiss
import numpy as np

class HNSWIndex:
    """HNSW index for billion-scale similarity search.
    
    Key parameters:
      - M: connections per node (higher = better recall, more memory)
      - efConstruction: search depth during construction
      - efSearch: search depth during query
    """
    def __init__(self, dim: int, M: int = 32, ef_construction: int = 200):
        self.dim = dim
        self.index = faiss.IndexHNSWFlat(dim, M)
        self.index.hnsw.efConstruction = ef_construction
        self.index.hnsw.efSearch = 64

    def add(self, embeddings: np.ndarray, metadata: list[dict]):
        faiss.normalize_L2(embeddings)
        self.index.add(embeddings)
        self.metadata = metadata

    def search(self, query: np.ndarray, k: int = 10) -> tuple[np.ndarray, np.ndarray]:
        faiss.normalize_L2(query)
        distances, indices = self.index.search(query, k)
        return distances, indices


class IVFPQIndex:
    """IVF-PQ (Inverted File with Product Quantization) index.
    
    Compresses vectors to 1/8 of original size using product
    quantization. Sub-1ms recall on 1B-scale datasets.
    """
    def __init__(self, dim: int, nlist: int = 4096, m_sub: int = 64):
        quantizer = faiss.IndexFlatIP(dim)
        self.index = faiss.IndexIVFPQ(quantizer, dim, nlist, m_sub, 8)
        self.index.nprobe = 32

    def train_and_add(self, embeddings: np.ndarray):
        faiss.normalize_L2(embeddings)
        self.index.train(embeddings)
        self.index.add(embeddings)

    def search_with_debug(self, query: np.ndarray, k: int = 10) -> dict:

        start = time.time()
```

在构建多模态搜索索引时，一个实用的技巧是将图像 Embedding 和文本 Embedding 存储在同一个索引中。这样，无论是"以文搜图"还是"以图搜图"，都可以使用同一个向量索引，简化系统架构。另一个重要的工程考量是增量更新——在电商等场景中，商品会持续新增和更新，索引需要支持高效的低延迟更新，而不是每次重建全量索引。

## 6. 多模态 Agent

多模态 Agent 是当前 AI 应用最具想象力的方向之一。它将多模态理解能力与工具调用能力结合，让 AI 不仅能够"看"和"读"，还能"执行操作"。本节覆盖视觉 Agent、GUI Agent 和多模态 RAG 三种典型范式。

### 6.1 视觉 Agent

视觉 Agent 的核心能力是理解图像内容并根据理解采取行动。它的工作流程通常是"感知-规划-执行"的循环：先通过 VLM 理解图像内容，然后根据指令规划下一步操作，执行工具调用，分析结果，直到完成目标。

视觉 Agent 的关键组件是工具注册表（Tool Registry）和规划循环（Planning Loop）。工具注册表包含了 Agent 可以调用的所有函数及其描述；规划循环则负责在每一步决定是调用工具还是给出最终答案。在实现中，我们通常让 VLM 输出结构化的 JSON 来决定下一步动作。

```python
# visual_agent.py
import json
import torch
from PIL import Image
from typing import Any

class VisualAgent:
    """Vision-language agent that can understand images AND call tools.
    
    Combines:
      1. VLM (LLaVA / Qwen2-VL) for image understanding
      2. Function-calling capability for tool execution
      3. Planning loop for multi-step visual tasks
    """
    def __init__(self, vlm_model, tool_registry: dict[str, callable]):
        self.vlm = vlm_model
        self.tools = tool_registry

    def plan_and_execute(self, image_path: str, instruction: str) -> dict[str, Any]:
        """Perceive -> Plan -> Execute loop for complex visual tasks."""
        image = Image.open(image_path).convert("RGB")
        observations = []
        step, max_steps = 0, 10

        while step < max_steps:
            context = "\n".join(observations[-5:])
            prompt = f"""You are a visual agent. Given the image and instruction, decide the next action.
Instruction: {instruction}
Recent observations: {context}
Available tools: {list(self.tools.keys())}
Respond in JSON format:
{{"thought": "...", "tool": "tool_name or None", "args": {{...}}, "response": "final answer or None"}}"""
            result = self.vlm.generate(image, prompt)
            parsed = json.loads(self._extract_json(result))
            if parsed.get("tool") and parsed["tool"] in self.tools:
                tool_fn = self.tools[parsed["tool"]]
                try:
                    tool_output = tool_fn(**parsed.get("args", {}))
                    observations.append(f"Tool {parsed['tool']} returned: {tool_output}")
                except Exception as e:
                    observations.append(f"Tool {parsed['tool']} error: {e}")
            elif parsed.get("response"):
                return {"answer": parsed["response"], "steps": step + 1}
            step += 1
        return {"answer": "Failed to complete after max steps", "steps": step}

    @staticmethod
    def _extract_json(text: str) -> str:
        start = text.find('{')
        end = text.rfind('}') + 1
        return text[start:end] if start >= 0 and end > start else "{}"
```

视觉 Agent 面临的工程挑战之一是错误恢复。当工具调用失败时，Agent 需要能够理解错误信息并重新规划，而不是陷入死循环。常用的策略包括：限制最大尝试次数（max_retries）、提供回退方案（fallback strategy）、以及定期进行"健康检查"（确认 Agent 是否仍在朝着目标前进）。

### 6.2 GUI Agent

GUI Agent 是多模态 Agent 的另一个重要分支，它的目标是在图形用户界面上自主操作。GUI Agent 需要三个核心能力：屏幕理解（识别当前界面状态）、元素定位（找到目标交互元素的位置）和动作执行（点击、输入、滚动等）。

与传统 RPA（机器人流程自动化）相比，GUI Agent 的最大优势是它能理解动态变化的界面内容。RPA 依赖固定的元素选择器（如 XPath），界面稍作调整就会失效；而 GUI Agent 通过视觉理解定位元素，对界面变化有更强的鲁棒性。

```python
# gui_agent.py
import json
from typing import Any

class GUIAgent:
    """GUI Agent: understands screen content + operates UI elements.
    
    Core capabilities:
      1. Screen understanding: describe UI from screenshot
      2. Element grounding: locate UI elements by description
      3. Action execution: click, type, scroll, navigate
    """
    def __init__(self, vlm_model, action_executor: callable):
        self.vlm = vlm_model
        self.execute = action_executor
        self.history: list[dict] = []

    def describe_screen(self, screenshot_path: str) -> dict[str, Any]:
        image = Image.open(screenshot_path).convert("RGB")
        prompt = """List all interactive UI elements visible in this screenshot.
        For each element, provide: {type, text, bounding_box, is_enabled}
        Output as JSON list."""
        result = self.vlm.generate(image, prompt)
        return json.loads(self._extract_json(result))

    def ground_element(self, screenshot_path: str,
                       description: str) -> dict[str, float]:
        """Locate a UI element by description and return its coordinates."""
        image = Image.open(screenshot_path).convert("RGB")
        prompt = f"""Find the element described as: "{description}"
        Return its center coordinates as {{"x": ..., "y": ..., "confidence": ...}}"""
        result = self.vlm.generate(image, prompt)
        return json.loads(self._extract_json(result))

    def run_task(self, task: str, screenshot_path: str,
                 max_steps: int = 20) -> dict[str, Any]:
        """End-to-end GUI task execution with ReAct loop."""
        current_screenshot = screenshot_path
        for step in range(max_steps):
            elements = self.describe_screen(current_screenshot)
            history_summary = "\n".join(
                [f"Action {i}: {h['action']} -> {h['result']}"
                 for i, h in enumerate(self.history[-3:])])
            prompt = f"""Task: {task}
Visible elements: {json.dumps(elements, indent=2)[:500]}
Recent actions: {history_summary}
Decide next action. Output JSON:
{{"thought": "...", "action": "click|type|scroll|done",
  "target_text": "...", "value": "...", "reasoning": "..."}}"""
            image = Image.open(current_screenshot).convert("RGB")
            decision = self.vlm.generate(image, prompt)
            parsed = self._parse_decision(decision)
            if parsed["action"] == "done":
                return {"success": True, "steps": step + 1}
            result = self.act(parsed["action"],
                              target_text=parsed.get("target_text"),
                              value=parsed.get("value"))
            current_screenshot = self._capture_screen()
        return {"success": False, "steps": max_steps}

    def _parse_decision(self, text: str) -> dict:
        try:
            return json.loads(self._extract_json(text))
        except json.JSONDecodeError:
            return {"action": "done", "reasoning": "parse error"}

    def _capture_screen(self) -> str:
        import tempfile
        path = f"{tempfile.gettempdir()}/gui_step.png"
        return path

    @staticmethod
    def _extract_json(text: str) -> str:
        start = text.find('[')
        if start == -1:
            start = text.find('{')
        end = text.rfind(']') + 1
        if end <= 0:
            end = text.rfind('}') + 1
        return text[start:end] if start >= 0 else "{}"
```

GUI Agent 在实际部署中面临的一个重要挑战是动作空间的定义和安全性。动作空间需要足够丰富以覆盖各种操作场景——点击、双击、右键、拖拽、键盘快捷键、滚动方向等——但过于宽泛的动作空间又增加了 Agent 决策难度和误操作风险。安全方面，需要设置操作白名单（允许访问的 URL 或应用）、操作确认（高危操作前需要人工确认）和操作回滚（支持撤销上一步操作）。

### 6.3 多模态 RAG

多模态 RAG（Retrieval-Augmented Generation）将传统的文本检索增强生成扩展到图文混合的检索和生成。当用户的问题涉及图像内容时（例如"这个产品的用户评价界面长什么样"），系统不仅需要检索相关文本，还需要检索对应的图像并让 VLM 同时理解两者。

多模态 RAG 的实现难点在于：如何将文本检索和图像检索的结果有效融合，并以 VLM 可以理解的方式呈现。常用的策略是在检索阶段使用 CLIP Embedding 进行跨模态检索（用户问题→最相关的图像），然后在生成阶段将检索到的图像和文本一起作为 VLM 的上下文。

```python
# multimodal_rag.py
import torch
import numpy as np
from PIL import Image
from typing import Any

class MultimodalRAG:
    """Retrieval-Augmented Generation with both image and text documents.
    
    Pipeline:
      Query -> (Text Search + Image Search) -> Fusion -> VLM Generation
    """
    def __init__(self, clip_model, vlm_model, text_index, image_index):
        self.clip = clip_model
        self.vlm = vlm_model
        self.text_index = text_index
        self.image_index = image_index

    def retrieve(self, query: str, top_k_text: int = 5,
                 top_k_image: int = 3) -> dict[str, list]:
        """Retrieve relevant text passages and images for a query."""
        query_emb = self.clip.encode_text(query)
        text_scores, text_indices = self.text_index.search(query_emb, top_k_text)
        text_results = [self.text_index.get_doc(i) for i in text_indices[0]]
        img_scores, img_indices = self.image_index.search(query_emb, top_k_image)
        image_results = [self.image_index.get_image(i) for i in img_indices[0]]
        return {
            "texts": text_results, "images": image_results,
            "text_scores": text_scores[0].tolist(),
            "image_scores": img_scores[0].tolist(),
        }

    def fuse_context(self, retrieved: dict[str, list],
                     max_images: int = 2) -> tuple[str, list]:
        """Fuse text and image contexts into a unified prompt."""
        context_parts = []
        image_tensors = []
        for i, text in enumerate(retrieved["texts"]):
            context_parts.append(f"[Reference {i+1}] {text}")
        for i, img in enumerate(retrieved["images"][:max_images]):
            context_parts.append(f"[Image {i+1}] See attached image.")
            img_tensor = self._load_image(img)
            image_tensors.append(img_tensor)
        context = "\n\n".join(context_parts)
        return context, image_tensors

    def generate(self, query: str, context: str,
                 images: list[torch.Tensor]) -> str:
        prompt = f"""Answer the question based on the provided context and images.
Question: {query}
Context: {context}
Answer concisely and cite sources where relevant."""
        return self.vlm.generate(images, prompt)

    def query(self, question: str) -> dict[str, Any]:
        """End-to-end multimodal RAG query."""
        retrieved = self.retrieve(question)
        context, images = self.fuse_context(retrieved)
        answer = self.generate(question, context, images)
        return {"answer": answer, "context": context,
                "num_texts": len(retrieved["texts"]),
                "num_images": len(images)}

    @staticmethod
    def _load_image(path: str) -> torch.Tensor:
        from torchvision import transforms
        img = Image.open(path).convert("RGB")
        transform = transforms.Compose([
            transforms.Resize((224, 224)),
            transforms.ToTensor(),
            transforms.Normalize(mean=[0.485, 0.456, 0.406],
                                 std=[0.229, 0.224, 0.225]),
        ])
        return transform(img).unsqueeze(0)
```

多模态 RAG 的关键设计决策是确定图像检索的粒度。对于一篇包含多张图片的文档，可以按文档级别存储图像（一张图对应整篇文章）、按段落级别存储（一张图对应一个段落）或按图像本身独立存储（一张图就是一个检索单元）。不同的粒度选择影响检索精度和上下文使用效率。在实际系统中，段落级别通常取得最好的平衡——既保证图像与上下文的语义相关性，又不至于引入过多噪声。

## 7. 生产化挑战

多模态 AI 模型的生产化部署面临一系列独特的挑战，包括计算成本、延迟控制、评估体系等。这些工程层面的考量往往决定了项目能否从实验阶段走向实际落地。

### 7.1 视频处理的成本与延迟

视频处理是多模态应用中最昂贵的计算任务之一。一个 60 秒、30fps 的视频包含 1800 帧，即使经过采样压缩到 8 帧，每帧经过 ViT 编码也需要约 30ms（ViT-L）的处理时间。加上 LLM 解码的时间，一次视频 QA 的总延迟通常在 5-15 秒级别。

成本优化的主要策略包括自适应帧采样（通过运动检测跳过低运动量的冗余帧）、模型量化（将模型从 FP16 压缩到 INT8，推理速度提升 2-3 倍）和 Token 压缩（通过 Perceiver Resampler 将每帧的 256 个 Token 压缩到 16-64 个）。

```python
# video_cost_optimization.py
import time
import cv2
import numpy as np
from dataclasses import dataclass

@dataclass
class VideoProcessCost:
    fps: int
    resolution: tuple
    latency_per_frame_ms: float
    total_latency_s: float
    memory_mb: float
    estimated_cost_usd: float

def estimate_video_cost(video_path: str, num_frames: int = 8,
                        model_type: str = "video_llama") -> VideoProcessCost:
    """Estimate cost and latency of processing a video through a Video LLM."""
    cap = cv2.VideoCapture(video_path)
    fps = cap.get(cv2.CAP_PROP_FPS)
    width = int(cap.get(cv2.CAP_PROP_FRAME_WIDTH))
    height = int(cap.get(cv2.CAP_PROP_FRAME_HEIGHT))
    cap.release()

    frame_decode_ms = 5.0
    vit_inference_ms = 30.0
    temporal_agg_ms = 50.0
    llm_decode_tokens = 128
    llm_per_token_ms = 15.0
    llm_decode_ms = llm_decode_tokens * llm_per_token_ms

    total_latency = (num_frames * (frame_decode_ms + vit_inference_ms)
                     + temporal_agg_ms + llm_decode_ms) / 1000
    vit_memory = 2.5 * 1024
    llm_memory = 14.0 * 1024
    feature_memory = num_frames * (width // 32) * (height // 32) * 1024 * 4 / 1024**2
    gpu_cost_per_hour = 3.50
    estimated_cost = (total_latency / 3600) * gpu_cost_per_hour

    return VideoProcessCost(fps=fps, resolution=(width, height),
                            latency_per_frame_ms=frame_decode_ms + vit_inference_ms,
                            total_latency_s=total_latency,
                            memory_mb=vit_memory + llm_memory + feature_memory,
                            estimated_cost_usd=estimated_cost)


def adaptive_frame_sampling(video_path: str, max_frames: int = 8,
                            motion_threshold: float = 0.1) -> list[int]:
    """Adaptive frame sampling: skip low-motion segments.
    
    Uses frame-difference magnitude to select informative frames
    while skipping near-duplicate frames, reducing redundant ViT passes.
    """
    cap = cv2.VideoCapture(video_path)
    frame_diffs = []
    prev_frame = None
    while True:
        ret, frame = cap.read()
        if not ret:
            break
        gray = cv2.cvtColor(frame, cv2.COLOR_BGR2GRAY)
        if prev_frame is not None:
            diff = cv2.absdiff(gray, prev_frame).mean()
            frame_diffs.append(diff)
        prev_frame = gray
    cap.release()
    if not frame_diffs:
        return list(range(min(max_frames, len(frame_diffs))))
    diffs = np.array(frame_diffs)
    diffs = (diffs - diffs.min()) / (diffs.max() - diffs.min() + 1e-8)
    peaks = np.where(diffs > motion_threshold)[0]
    if len(peaks) < max_frames:
        peaks = np.linspace(0, len(diffs)-1, max_frames, dtype=int)
    return peaks[:max_frames].tolist()
```

延迟优化方面，自回归 LLM 解码通常是主要瓶颈。KV Cache 技术可以显著减少重复计算——在连续的解码步骤中复用之前计算过的 Key 和 Value 矩阵。另外，Speculative Decoding（推测解码）通过一个小模型预测多个候选 Token，再用大模型一次性验证，可以在不降低生成质量的情况下将解码速度提升 2-3 倍。

### 7.2 图像 Token 数量控制

图像 Token 数量控制是多模态 LLM 推理优化的核心问题。一张 224×224 的图像经过 ViT 编码会产生 256 个 Patch Token（16×16 的网格）。如果输入的是高分辨率图像（如 1344×1344），Token 数量将达到 9216 个，远超大多数 LLM 的上下文窗口上限。

Perceiver Resampler 是目前最有效的 Token 压缩方案之一。它通过学习一组可压缩的潜在查询向量（latent queries），通过交叉注意力从原始视觉 Token 中提取关键信息，输出固定数量的压缩 Token。例如，256 个输入 Token 可以压缩为 16 个输出 Token，压缩率达到 16 倍，而关键信息的损失非常有限。

```python
# token_compression.py
import torch
import torch.nn as nn

class PerceiverResampler(nn.Module):
    """Perceiver Resampler: compress variable-length visual tokens to fixed length.
    
    Given P visual tokens from ViT (e.g., 256 patches),
    compresses them to Q fixed tokens (e.g., 16) using cross-attention.
    
    This is critical for:
      1. Reducing LLM context length (256 -> 16 = 16x reduction)
      2. Enabling variable resolution support
      3. Controlling inference cost
    """
    def __init__(self, d_model: int = 1024, num_latents: int = 16, num_layers: int = 2):
        super().__init__()
        self.latent_queries = nn.Parameter(torch.randn(1, num_latents, d_model))
        self.num_latents = num_latents
        self.cross_attn = nn.MultiheadAttention(d_model, 8, batch_first=True)
        layer = nn.TransformerEncoderLayer(d_model=d_model, nhead=8,
                                            dim_feedforward=d_model*4,
                                            batch_first=True)
        self.self_attn_layers = nn.TransformerEncoder(layer, num_layers)

    def forward(self, visual_tokens: torch.Tensor,
                mask: torch.Tensor = None) -> torch.Tensor:
        """visual_tokens: [B, P, d_model]; mask: [B, P]"""
        B, P, D = visual_tokens.shape
        latents = self.latent_queries.expand(B, -1, -1)
        for _ in range(2):
            latents, _ = self.cross_attn(latents, visual_tokens, visual_tokens,
                                         key_padding_mask=~mask if mask is not None else None)
            latents = self.self_attn_layers(latents)
        return latents


def compute_token_budget(image_size: tuple, patch_size: int = 14,
                         max_tokens: int = 4096) -> bool:
    """Check if an image fits within the LLM's token budget."""
    H, W = image_size
    num_patches = (H // patch_size) * (W // patch_size)
    return num_patches <= max_tokens


def dynamic_resolution_tokens(image_size: tuple, max_tokens: int = 4096,
                              base_patch_size: int = 14) -> tuple[int, int]:
    """Compute optimal resolution that fits token budget."""
    candidates = [
        (224, 224), (336, 336), (448, 448), (672, 672),
        (224, 672), (672, 224), (448, 672), (672, 448),
    ]
    best = (224, 224)
    for H, W in candidates:
        tokens = (H // base_patch_size) * (W // base_patch_size)
        if tokens <= max_tokens:
            best = (H, W)
    return best
```

动态分辨率是另一个实用的 Token 控制策略。对于不同尺寸的输入图像，不是统一缩放到固定大小，而是选择在 Token 预算范围内最接近原始宽高比的分辨率。Qwen2-VL 采用的策略是维护一组预定义候选分辨率（如 224×224、336×336、448×448、672×672 等），从中选择能最大化利用 Token 预算且保持原始宽高比的那一个。

### 7.3 多模态评估

多模态系统的评估比纯文本系统复杂得多。准确评估一个多模态模型需要考虑多个维度：生成图像的质量（FID）、图文一致性（CLIP Score）、任务特定准确率（VQA Accuracy）、以及人工评价。

FID（Fréchet Inception Distance）是目前最常用的图像生成质量评价指标。它计算真实图像和生成图像在 InceptionV3 特征空间中的分布距离，数值越低代表生成质量越高。FID 在 10 以下通常被认为是高质量生成，20-30 为可接受水平。

CLIP Score 衡量图像和文本之间的语义一致性——给定文本描述后生成的图像，CLIP Score 越高说明图像与描述越匹配。但 CLIP Score 也有局限性，它可能偏好"稳妥"的生成（包含所有常见元素但不具创造性），因此通常与 FID 和人工评价联合使用。

```python
# multimodal_evaluation.py
import torch
import numpy as np
from typing import Any

class MultimodalEvaluator:
    """Comprehensive evaluation suite for multimodal systems.
    
    Covers:
      1. CLIP Score: image-text alignment quality
      2. FID: image generation fidelity
      3. Human evaluation orchestration
      4. Task-specific metrics (VQA accuracy, captioning CIDEr)
    """
    def __init__(self, clip_model, clip_processor):
        self.clip = clip_model
        self.processor = clip_processor

    def clip_score(self, images: list, texts: list[str]) -> dict:
        """Compute CLIP Score: mean cosine similarity between image-text pairs."""
        scores = []
        for img, txt in zip(images, texts):
            inputs = self.processor(text=txt, images=img, return_tensors="pt",
                                    padding=True, truncation=True)
            with torch.no_grad():
                outputs = self.clip(**inputs)
            scores.append(outputs.logits_per_image.item())
        return {"mean": float(np.mean(scores)), "std": float(np.std(scores))}

    def fid_score(self, real_features: np.ndarray,
                  generated_features: np.ndarray) -> float:
        """Compute Fréchet Inception Distance.
        
        FID = ||mu_r - mu_g||^2 + Tr(Sigma_r + Sigma_g - 2*(Sigma_r*Sigma_g)^(1/2))
        """
        mu_r, sigma_r = real_features.mean(0), np.cov(real_features, rowvar=False)
        mu_g, sigma_g = generated_features.mean(0), np.cov(generated_features, rowvar=False)
        diff = mu_r - mu_g
        covmean, _ = self._sqrtm(sigma_r @ sigma_g)
        fid = diff @ diff + np.trace(sigma_r + sigma_g - 2 * covmean)
        return float(fid)

    @staticmethod
    def _sqrtm(matrix: np.ndarray) -> tuple[np.ndarray, bool]:
        U, S, Vt = np.linalg.svd(matrix, full_matrices=False)
        sqrt_matrix = U @ np.diag(np.sqrt(S)) @ Vt
        return sqrt_matrix, np.all(np.isfinite(sqrt_matrix))

    def vqa_accuracy(self, predictions: list[str],
                     ground_truth: list[list[str]]) -> dict:
        exact = sum(pred in gt_list for pred, gt_list in zip(predictions, ground_truth))
        soft = sum(any(gt.lower() in pred.lower() for gt in gt_list)
                   for pred, gt_list in zip(predictions, ground_truth))
        n = len(predictions)
        return {"exact_match": exact / n, "soft_match": soft / n}

    def caption_cider(self, generated: list[str],
                      references: list[list[str]]) -> float:
        """CIDEr-D score for image captioning evaluation."""
        from pycocoevalcap.cider.cider import Cider
        scorer = Cider()
        gts = {i: refs for i, refs in enumerate(references)}
        res = {i: [gen] for i, gen in enumerate(generated)}
        score, _ = scorer.compute_score(gts, res)
        return float(score)
```

在评估体系设计中，自动指标和人工评价需要形成互补。自动指标适合在开发迭代中快速发现问题（如 FID 突然升高），但无法捕捉语义层面的细微差异（如生成的图像虽然质量好但与描述不符）。人工评价虽然成本高、速度慢，但能够提供深层质量判断。一个成熟的评估体系通常采用"多级筛选"策略：用自动指标快速过滤低质量结果，用人工评价对通过筛选的结果进行精细化评估。

## 总结与技术展望

多模态 AI 应用开发正经历从"独立编码器加融合模块"到原生统一架构的范式转变。本文从七个维度系统性地梳理了多模态应用开发的核心技术栈，覆盖了从模型原理到工程实现再到生产化部署的全链路。

当前多模态 AI 领域的几个关键趋势值得关注：

**架构统一化**。Qwen2-VL、GPT-4o 等模型正在模糊视觉编码器和语言模型的边界，走向端到端的多模态 Transformer。未来的多模态模型不再需要手动的模态对齐拼接，而是从架构底层原生支持多种模态的联合建模。

**Token 效率革命**。Perceiver Resampler、动态分辨率、视觉 Token 压缩等技术正在大幅降低多模态推理的上下文成本。256 个图像 Token 压缩到 16 个而不损失关键信息的能力，使得多模态 LLM 的推理效率和纯文本模型之间的差距正在快速缩小。

**Agent 化演进**。从单纯的"理解"到"理解加行动"，多模态 Agent 正在成为 AI 应用的主要交互范式。视觉 Agent、GUI Agent 和多模态 RAG 三种范式的融合，预示着未来的 AI 系统将同时具备感知、规划和执行能力。

**评估体系成熟**。从单一的 CLIP Score 到结合 FID、任务准确率和人工评价的多维度评估体系，多模态系统的质量保障正在走向成熟化和标准化。

**成本梯度下降**。视频处理通过动态帧采样、Token 压缩、模型蒸馏等技术路线，正在逐步跨越实用化的成本阈值。对于大多数应用场景，单次视频推理的成本已经降低到可接受的商业水平。

多模态 AI 技术的工程实践需要同时把握模型架构原理、数据处理流水线和生产化部署三方面的能力。本文提供的代码框架和设计模式可作为实际项目的技术参考，但更重要的是理解每一层技术选择背后的权衡——精度与速度的权衡、通用性与专用性的权衡、复杂性与可维护性的权衡。在实际项目中，做出正确的工程取舍往往比掌握单点技术更为关键。
